🧭 브레드크럼 — 현재 위치·긴 경로 접기·aria-current 설계 내비게이션·탭

브레드크럼(breadcrumb)은 "지금 이 화면이 사이트 구조 어디쯤인지"를 한 줄로 보여주고 상위로 되돌아갈 링크를 주는 내비다. 정산·설정처럼 깊이가 있는 관리 화면에서 길잃음을 막는다. 요즘 설계의 핵심은 세 가지: 마지막 항목은 링크가 아니라 aria-current="page", 경로가 길면 가운데를 …로 접기, 좁은 화면에선 현재 항목만 말줄임.

① 기본 — 마지막은 현재 페이지(링크 아님)

  1. 대시보드
  2. 결제
  3. 거래 내역

② 긴 경로 접기 — 가운데를 … 로 숨기고, 눌러 펼침

    현재 페이지: 거래 내역 — 상위 링크를 눌러 이동해 보세요.

    구분자(›)는 CSS ::before로 그린다 — 실제 텍스트가 아니라 스크린리더가 "슬래시"를 읽지 않는다. 마지막 항목은 <a>가 아니라 aria-current="page"를 단 <span>이라, 스스로에게 가는 죽은 링크를 없앤다.

    전체 구조는 <nav aria-label="현재 위치"> > <ol> > <li>. 순서가 의미 있으니 순서 리스트(ol)를 쓴다. 접기 버튼(…)은 장식이 아니라 진짜 <button>이라 키보드로도 펼칠 수 있고, aria-expanded로 상태를 알린다. 모바일에선 전체 경로 대신 "← 상위 한 단계"만 남기는 것도 흔한 대안이다.

    🃏 스와이프 액션 리스트 — 밀어서 보관·삭제, 버튼 폴백·되돌리기 카드·리스트

    거래·알림 리스트에서 항목을 왼쪽으로 밀면 보관·삭제 버튼이 나오는 패턴. 핀테크 거래 목록의 사실상 표준이다. 하지만 스와이프는 숨은 동작이라, 마우스·키보드 사용자를 위한 ⋯ 버튼 폴백과 실수 삭제를 되살리는 되돌리기(undo)가 함께 있어야 진짜 설계다.

      항목을 삭제했습니다.

      데스크톱에선 항목을 마우스로 잡고 왼쪽으로 드래그, 모바일에선 손가락으로 스와이프. 열기 싫으면 오른쪽 ⋯ 버튼으로도 같은 액션을 연다. 삭제는 토스트가 뜬 5초 안에 되돌리기 가능.

      접근성이 관건이다: 스와이프만으로 삭제를 걸면 스크린리더·키보드 사용자는 영영 못 쓴다. 그래서 각 항목에 항상 보이는 ⋯ 버튼을 두고, 열렸을 때 액션 버튼이 실제로 포커스를 받게 한다(닫혔을 땐 inert로 탭 순서에서 제외). 드래그 임계값(약 절반)을 넘기면 열림으로 스냅, 아니면 닫힘으로 되돌아간다 — touch-action:pan-y로 세로 스크롤은 살린다. 파괴적 동작(삭제)엔 항상 되돌릴 길을 남긴다.

      🌀 CSS 캐러셀 — ::scroll-button·::scroll-marker로 JS 없이 트렌드·개념

      캐러셀(carousel)은 카드를 옆으로 넘겨 보는 슬라이드 UI다. 그동안 화살표·점(dot) 페이지네이션을 만들려면 JS가 필수였는데, CSS Overflow Level 5의 ::scroll-button()(이전/다음 버튼)과 ::scroll-marker(점 표시자)가 이를 CSS만으로 만들 수 있게 했다. 스크롤 스냅 위에 얹으면 접근성·키보드까지 브라우저가 챙긴다.

      1. 무이자 할부

        2~6개월 무이자, 카드사별 자동 적용.

        결제

      2. 즉시 정산

        영업일 기준 다음 날, 원하면 당일 정산.

        정산

      3. 수수료 0.8%

        월 거래액 구간에 따라 자동 할인.

        수수료

      4. 간편 링크결제

        URL 하나로 카드·계좌·간편결제 모두.

        결제

      5. 매출 대시보드

        승인율·환불·정산을 한 화면에서.

        분석
      지원 여부 확인 중…

      지원 브라우저에선 위 화살표·점이 순수 CSS로 그려져 동작한다(HTML엔 버튼이 없다). 미지원 브라우저에선 아래에 JS로 만든 화살표·점 폴백이 대신 나타나, 어디서든 넘길 수 있다. 트랙을 Tab으로 포커스한 뒤 화살표 키로도 스크롤된다.

      왜 지금 뜨나: Chromium 135(2025)부터 ::scroll-button()·::scroll-marker·scroll-marker-group가 들어와, 캐러셀의 대표적 JS 뭉치(현재 인덱스 추적·점 하이라이트·경계에서 버튼 비활성)를 브라우저가 대신한다. 생성된 요소는 포커스 가능·키보드 접근·경계에서 자동 비활성이고 스크린리더엔 탭 목록처럼 읽힌다. 다만 Firefox는 부분 지원, Safari는 아직이라(2026-08 기준, 추정) 프로덕션에선 scroll-snap + 가벼운 JS 폴백을 함께 둔다 — 오늘 데모가 그 형태다.
