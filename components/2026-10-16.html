결제가 언제 몰리고 언제 거절이 많은지 한눈에. 이상치 하나가 색 전체를 납작하게 만드는 함정과, 색이 아니라 숫자·키보드로도 읽히게 하는 법.

셀을 클릭하거나 화살표 키로 이동해 보세요.

금요일 18~24시의 폭증(이상치)이 있을 때 "선형 구간"은 나머지를 전부 연한 색으로 뭉갭니다. "분위수 구간"은 칸 수가 균등하게 나뉘어 평소 패턴(점심·저녁)이 보입니다. 단, 분위수는 "얼마나 큰지"를 과장/왜곡할 수 있어 범례에 구간 숫자를 반드시 표기합니다.

🔔 내보내기 작업 상태 — 대기·진행·완료·실패를 눈에 보이게, 중복 클릭은 합치기 피드백·상태

정산 엑셀처럼 서버가 수 초~수 분 만드는 파일은 "버튼 → 스피너"로 끝나지 않습니다. 이탈해도 이어지고, 실패는 되돌릴 수 있게.

A. 인라인 버튼 — 버튼이 상태판이 된다

대기 중

진행 중에도 버튼은 aria-disabled(포커스는 유지)이고, 누르면 "이미 만드는 중"이라고 알려 줍니다.

B. 작업 목록 — 새로고침해도 돌아와서 받는 방식

진행률은 폴링(주기적 확인) 간격을 1→1.5→2→3초로 늘립니다(백오프). 같은 조건을 또 누르면 새 작업 대신 기존 작업으로 안내합니다.

// 폴링 + 백오프 (요지)
const delays = [1000, 1500, 2000, 3000];
async function poll(jobId, i = 0){
  const job = await fetch(`/api/exports/${jobId}`).then(r => r.json());
  render(job);
  if (['done','failed','canceled'].includes(job.status)) return;
  setTimeout(() => poll(jobId, i + 1), delays[Math.min(i, delays.length-1)]);
}
설계 포인트: 상태는 서버가 가진다(jobId) → 새로고침·다른 탭에서도 복원. 요청은 멱등키로 중복 방지. 진행률 숫자가 불확실하면 막대를 "불확정(indeterminate)"으로. 스크린리더에는 매 퍼센트가 아니라 "완료/실패" 전환만 알립니다.

🌀 Speculation Rules — 링크를 누르기 전에 브라우저가 미리 받아 두기 트렌드·개념

JSON 규칙 하나로 prefetch(문서만 미리 받기)·prerender(숨은 탭에서 미리 렌더)를 선언합니다. 이 데모는 규칙 생성기 + 동작 시뮬레이션입니다(실제 사전 로드는 일으키지 않음).

<script type="speculationrules">
{ "prefetch": [{
    "where": { "and": [
      { "href_matches": "/*" },
      { "not": { "selector_matches": ".no-spec" } } ] },
    "eagerness": "moderate" }] }
</script>


결제 도메인 주의: GET만으로 상태가 바뀌는 URL(로그아웃, 결제 확정)은 절대 사전 로드 대상에 두지 않습니다. prerender된 페이지의 스크립트는 사용자가 보기 전에 실행되므로 분석 이벤트·결제 SDK 초기화는 prerenderingchange 이후로 미룹니다. 지원: Chrome/Edge 109+(prerender), Firefox·Safari는 제한적(변동 가능 — 출시 전 MDN 재확인).
