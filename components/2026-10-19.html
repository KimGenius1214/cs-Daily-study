    B. 진행 중 잠금 + 멱등키

    대기 중
    서버가 받은 요청 0실제 승인 0중복 차단 0

      체크 후 결제하면 서버는 승인했지만 응답이 사라집니다. 버튼은 "결과 확인 중"이 되고, 재시도는 같은 키를 쓰므로 서버가 새 승인 없이 기존 결과를 돌려줍니다.

      // 주문 단위로 키를 한 번만 만들고, 재시도에 재사용
const keyRef = useRef(crypto.randomUUID());   // 새 주문일 때만 갱신
async function pay() {
  if (pending.current) return;                // 1차: 클라이언트 잠금
  pending.current = true;
  try {
    return await fetch('/api/pay', {
      method: 'POST',
      headers: { 'Idempotency-Key': keyRef.current },  // 2차: 서버 중복 제거
      body: JSON.stringify(order),
    });
  } finally { pending.current = false; }
}
      접근성: 잠글 때 disabled 대신 aria-disabled를 써서 포커스를 유지하고, 클릭은 핸들러에서 무시. 상태 문구는 role="status"로 안내. 클라이언트 잠금은 새로고침·다른 탭·네트워크 재시도를 못 막으므로 서버 멱등키가 본체입니다.

      ⌨️ 검색 입력 경합 처리 — 늦게 도착한 옛 응답이 새 결과를 덮어쓰는 문제 입력·폼

      거래 검색창에 타이핑하면 요청이 여러 개 날아갑니다. 응답 순서는 요청 순서와 같지 않습니다 — 방어를 껐다 켜며 비교하세요.

      입력을 시작하세요.
        보낸 요청 0취소 0옛 응답이 화면을 덮은 횟수 0

          가짜 서버는 글자가 짧을수록 느리게(최대 900ms) 응답합니다. 방어를 끄고 "kakao"를 빠르게 치면 "k" 응답이 가장 늦게 도착해 결과를 덮습니다.

          let timer, ctrl;
input.addEventListener('input', e => {
  if (e.isComposing) return;            // 한글 조합 중에는 보내지 않기
  clearTimeout(timer);                  // debounce: 멈춘 뒤에만 요청
  timer = setTimeout(async () => {
    ctrl?.abort();                      // 이전 요청 취소
    ctrl = new AbortController();
    try {
      const r = await fetch(`/api/search?q=${encodeURIComponent(q)}`, { signal: ctrl.signal });
      render(await r.json());
    } catch (err) { if (err.name !== 'AbortError') showError(); }
  }, 250);
});
          설계 포인트: debounce(입력이 멈출 때까지 기다렸다 한 번만 실행)는 요청 수를 줄이고, AbortController(진행 중 요청 취소 신호)는 순서 역전을 막습니다. 서버에 이미 도달한 요청은 취소돼도 처리되므로 조회(GET)에만 안전합니다. 결과 영역에는 aria-live="polite" 요약("3건")을 둡니다.

          🌀 contrast-color() — 배경색에 맞춰 글자색을 CSS가 고르게 하기 트렌드·개념

          가맹점이 직접 고른 브랜드 색 위에 올릴 글자를 흰색/검정 중 CSS가 선택합니다. 슬라이더로 배경을 바꿔 보세요.

          위 칸의 글자색은 @supports가 되면 contrast-color(), 아니면 JS가 계산한 폴백입니다. 아래 수치는 JS로 계산한 WCAG 대비율입니다.

          .badge {
  --bgc: var(--merchant-color);
  background: var(--bgc);
  color: #fff;                               /* 폴백 */
}
@supports (color: contrast-color(red)) {
  .badge { color: contrast-color(var(--bgc)); }
}
          주의: 결과는 흰색 또는 검정 둘 중 하나일 뿐, WCAG AA(일반 텍스트 4.5:1) 통과를 보장하지 않습니다. 중간 명도 배경에서는 둘 다 낮을 수 있어 슬라이더 중간값에서 대비율을 직접 확인하세요. 브라우저 지원은 최근 Safari/Chrome 계열에서 보고되나 정확한 버전은 미검증(추정)이므로 폴백이 필수입니다.
