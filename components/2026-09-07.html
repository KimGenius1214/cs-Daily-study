🔘 분할 버튼과 액션 메뉴 버튼·액션

가장 많이 쓰는 액션 하나는 바로 누르게 두고, 나머지 변형은 옆 화살표에 접어두는 버튼. "저장 / 저장하고 계속" 같이 형제 액션이 3개 이상일 때 버튼을 나란히 늘어놓는 대신 쓴다.

변형 1 — 기본 분할 버튼 (주 액션 + 더보기)

키보드: Tab 두 번이면 화살표 버튼
아직 고른 액션이 없습니다.

주 액션이 바로 눌리는 자리에 있어야 분할 버튼이다. 화살표를 눌러야 주 액션이 나오면 그건 그냥 드롭다운이고, 사용자는 매번 두 번 누른다.

변형 2 — 주 액션이 로딩 중일 때

눌러보세요 — 처리 중엔 화살표까지 같이 잠깁니다

주 액션이 진행 중이면 화살표도 함께 비활성이어야 한다. 메뉴 안의 "예약 송금"을 처리 중에 눌러 두 번 나가는 사고가 실제로 난다.

변형 3 — 아이콘 전용 액션 줄 (툴바형)

툴바 안에서 ← → 로 이동해 보세요.

아이콘만 있는 버튼은 보이는 글자가 없으므로 aria-label이 곧 버튼 이름이다. 툴바는 버튼 개수만큼 Tab을 먹지 않도록 로빙 탭인덱스를 쓴다 — 로빙 탭인덱스: 그룹 안에서 딱 한 개만 tabindex="0"이고 나머지는 -1, 화살표 키로 그 하나를 옮기는 방식.

언제 뭘 쓰나

상황고를 것이유
액션 2개, 둘 다 자주 씀버튼 2개 나란히접는 순간 한쪽이 손해
주 액션 1개 + 변형 2~5개분할 버튼주 액션 1클릭 유지, 나머지는 접힘
동등한 액션 5개 이상메뉴 버튼(⋯)주 액션을 못 고르면 분할할 이유가 없음
행마다 반복되는 액션아이콘 툴바 + ⋯세로 공간 절약, 자주 쓰는 2~3개만 노출

코드 — 분할 버튼의 뼈대

<div class="split">
  <button type="button">정산 실행</button>
  <button type="button" aria-haspopup="true" aria-expanded="false"
          aria-controls="menu1" aria-label="정산 실행 옵션 더 보기">▾</button>
</div>
<ul id="menu1" role="menu" hidden>
  <li><button role="menuitem" tabindex="-1">예약 정산</button></li>
</ul>
// 열 때 첫 항목으로 포커스, 닫을 때 화살표 버튼으로 복귀
function open(){
  menu.hidden = false;
  toggle.setAttribute('aria-expanded','true');
  menu.querySelector('[role=menuitem]').focus();
}
function close({restore = true} = {}){
  menu.hidden = true;
  toggle.setAttribute('aria-expanded','false');
  if (restore) toggle.focus();     // Esc·바깥클릭 시 포커스가 body로 날아가지 않게
}
menu.addEventListener('keydown', e => {
  const items = [...menu.querySelectorAll('[role=menuitem]')];
  const i = items.indexOf(document.activeElement);
  if (e.key === 'ArrowDown'){ e.preventDefault(); items[(i+1) % items.length].focus(); }
  if (e.key === 'ArrowUp')  { e.preventDefault(); items[(i-1+items.length) % items.length].focus(); }
  if (e.key === 'Home')     { e.preventDefault(); items[0].focus(); }
  if (e.key === 'End')      { e.preventDefault(); items.at(-1).focus(); }
  if (e.key === 'Escape')   { close(); }
});

접근성·상태 설계

  • 이름: 화살표 버튼은 보이는 글자가 없다. aria-label에 "무엇의 옵션인지"까지 넣는다 — 그냥 "더 보기"면 화면 낭독기에서 여러 개가 전부 "더 보기"가 된다.
  • 연결: aria-haspopup="true" + aria-expanded + aria-controls 세 개가 한 세트다. 열림/닫힘을 aria-expanded로 매번 갱신하지 않으면 시각장애 사용자는 열린 줄 모른다.
  • 포커스: 열면 첫 항목, Esc·바깥 클릭으로 닫으면 화살표 버튼으로 되돌린다. 항목을 실행해 닫을 때도 마찬가지.
  • 키보드: ↑↓ 순환 이동, HomeEnd 처음·끝, Esc 닫기. 메뉴 항목은 tabindex="-1"이라 Tab으로는 안 들어간다.
  • disabled: 주 액션이 처리 중이면 화살표도 같이 잠근다. 단, 잠긴 버튼은 포커스를 못 받으므로 진행 상황은 role="status" 영역으로 따로 알린다.
  • 터치 타깃: 아이콘 버튼은 40×40 이상 확보. 화살표 부분이 24px이면 모바일에서 주 액션을 오폭한다.
paysable 적용 포인트 — 정산 상세의 "정산 실행"처럼 주 액션은 명확한데 변형이 계속 늘어나는 자리에 맞는다. 특히 "모의 정산(dry-run)"을 메뉴 첫 칸에 두면, 실행 버튼 옆에 위험한 버튼을 나란히 놓지 않아도 된다. 거래 목록의 행 액션은 자주 쓰는 2개만 아이콘으로 내놓고 나머지는 ⋯ 안으로.

⌨️ 금액 입력 필드 입력·폼

숫자를 받는 칸인데 <input type="number">를 쓰면 안 되는 대표적인 자리. 천 단위 쉼표를 넣으면서도 커서가 튀지 않게 하는 게 이 컴포넌트의 전부다.

변형 1 — 원화, 타이핑하는 동안 서식 유지

₩ 원

1회 한도 5,000,000원 · 숫자만 입력

서버로 보낼 값 null 커서 0

직접 확인해 볼 것

  • 1234567 입력 → 쉼표가 붙어도 커서가 끝에 남는가
  • 가운데를 클릭해 숫자 하나 지우기 → 커서가 맨 뒤로 튀지 않는가
  • "₩1,234,567원" 통째로 붙여넣기 → 숫자만 걸러지는가
  • 한도 초과 입력 → 막지 않고 에러로 알려주는가

커서 유지는 "커서 앞에 숫자가 몇 개였나"를 세어두고, 서식을 새로 그린 뒤 같은 개수의 숫자 뒤로 커서를 되돌리는 방식으로 한다. 글자 수가 아니라 숫자 개수가 기준이다.

변형 2 — 소수점 2자리 통화(USD)와 blur 정규화

$

소수점 둘째 자리까지 · 칸을 벗어나면 자동 정리

서버로 보낼 값(센트) null

왜 blur에서 정리하나

  • 12.처럼 입력 도중에는 정상인 중간 상태가 있다. 타이핑 중에 강제로 12.00으로 고치면 소수점을 못 찍는다.
  • 그래서 타이핑 중엔 최소한만(쉼표·허용 문자), 칸을 벗어날 때 완성형으로 맞춘다.
  • 돈은 부동소수점으로 다루지 않는다. 화면은 문자열, 서버로는 최소 단위 정수(센트·원)로 보낸다.

왜 type="number"를 피하나

항목type="number"type="text" + inputmode
천 단위 쉼표불가 값이 무효 처리됨가능
모바일 키패드숫자패드inputmode로 동일
스크롤 휠 오조작값이 바뀜없음
앞자리 0·긴 자릿수브라우저마다 다름직접 제어

inputmode: 값의 종류가 아니라 어떤 키보드를 띄울지만 알려주는 힌트. numeric은 정수 키패드, decimal은 소수점 있는 키패드(추정 — 기기·키보드 앱마다 표시가 다를 수 있음).

코드 — 커서를 지키는 포맷

const nf = new Intl.NumberFormat('ko-KR');

function formatKeepingCaret(input){
  const before = input.value.slice(0, input.selectionStart);
  const digitsBeforeCaret = (before.match(/\d/g) || []).length;   // 커서 앞 '숫자 개수'

  const digits = input.value.replace(/\D/g, '');
  input.value = digits ? nf.format(Number(digits)) : '';

  // 같은 개수의 숫자를 지난 지점으로 커서 복원
  let seen = 0, pos = 0;
  for (; pos < input.value.length && seen < digitsBeforeCaret; pos++){
    if (/\d/.test(input.value[pos])) seen++;
  }
  input.setSelectionRange(pos, pos);
  return digits;                     // ← 서버로 보낼 원본
}

input.addEventListener('input', () => {
  const raw = formatKeepingCaret(input);
  form.amount = raw ? Number(raw) : null;
});

접근성·상태 설계

  • 붙여넣기는 input 이벤트로 함께 잡힌다. keydown에서 키를 막는 방식은 붙여넣기·자동완성·한글 조합을 전부 놓친다.
  • 한도 초과는 입력을 막지 말고 에러로 알린다. 못 치게 막으면 사용자는 "왜 안 눌리지"만 겪는다. 에러 문구는 aria-describedby로 연결된 칸에 넣고, 즉시 알려야 하면 role="alert".
  • 포커스 링은 칸 전체(.moneybox)에 준다. input에만 주면 ₩ 기호와 "원"이 링 밖으로 빠져 어색하다 — :has(input:focus-visible)로 부모에 건다.
  • 화폐 기호는 aria-hidden. 낭독기는 라벨("송금 금액")과 값만 읽으면 되고, 기호를 읽으면 "원화 기호 일이삼사"처럼 지저분해진다.
  • 정렬은 오른쪽, 숫자는 font-variant-numeric: tabular-nums(모든 숫자 폭을 같게)로 자릿수가 흔들리지 않게.
paysable 적용 포인트 — 송금·부분취소·한도 설정처럼 금액을 받는 칸을 <MoneyInput currency /> 하나로 통일할 자리. 핵심은 표시값과 전송값을 분리하는 것: 화면엔 1,234,567, 상태엔 1234567(정수). 두 값을 하나로 쓰기 시작하면 어딘가에서 Number("1,234,567") === NaN이 터진다.

🌀 CSS 네이티브 캐러셀 — ::scroll-button()과 ::scroll-marker() 트렌드·개념

지원 브라우저에서는 위 화살표·점이 CSS가 만든 것이고, 미지원 브라우저에서는 아래 JS 폴백이 뜬다. 둘 다 ← → 키와 스크롤이 그대로 동작한다.

📈 왜 지금 뜨나 / 어디에 쓰나

  • 캐러셀은 "가로 스크롤 + 스냅 + 버튼 + 인디케이터 + 현재 위치 동기화"가 필요해서, 별것 아닌 UI인데도 라이브러리를 부르게 되는 대표 사례였다.
  • CSS Overflow Level 5가 ::scroll-button()(이전/다음 버튼)과 ::scroll-marker()(점 인디케이터)를 표준으로 넣었다. 스크롤 컨테이너가 스스로 버튼을 만들고, 끝에 닿으면 알아서 :disabled가 된다.
  • 현재 위치 하이라이트도 :target-current로 CSS가 처리한다. "지금 몇 번째 슬라이드인지"를 JS로 계산해 클래스를 붙이던 코드가 통째로 사라진다.
  • 버튼·마커는 브라우저가 만들되 접근성 배선(포커스·이름·순서)까지 브라우저가 붙인다는 게 진짜 이득이다. 직접 만든 캐러셀이 접근성에서 깨지는 지점이 대부분 여기였다.
⚠️ 지원 상황(2026-09 기준, 검색으로 확인) — Chromium 계열(Chrome 135+)에서 동작하고, Baseline(주요 브라우저 공통 지원)에는 아직 들어가지 않았다. 폴백 없이 프로덕션에 넣을 단계는 아니다. Safari·Firefox의 정확한 현재 상태는 확인하지 않았으므로 단정하지 않는다(추정).

코드 — 캐러셀 전체

.car{
  display:grid; grid-auto-flow:column; grid-auto-columns:min(260px,72%);
  gap:14px; overflow-x:auto; scroll-snap-type:x mandatory;
  anchor-name:--car;                 /* 버튼을 이 컨테이너에 붙이기 위한 이름 */
}
.car > .slide{ scroll-snap-align:center; }

/* 지원할 때만 켠다 — 미지원 브라우저에서 파싱 에러를 피한다 */
@supports selector(::scroll-button(right)){
  .car{ scroll-marker-group: after; }          /* 점 묶음을 컨테이너 뒤에 생성 */

  .car::scroll-button(*){                       /* 두 버튼 공통 스타일 */
    position:fixed; position-anchor:--car;
    width:36px; height:36px; border-radius:50%;
  }
  .car::scroll-button(*):disabled{ opacity:.35; }   /* 끝에 닿으면 자동 */
  .car::scroll-button(left) { content:"←"; position-area:top span-left; }
  .car::scroll-button(right){ content:"→"; position-area:top right; }

  .car::scroll-marker-group{ display:flex; gap:8px; justify-content:center; }
  .car > .slide::scroll-marker{ content:""; width:9px; height:9px; border-radius:50%;
                                background:var(--border); }
  .car > .slide::scroll-marker:target-current{ background:var(--brand); }  /* 현재 위치 */
}

content가 비어 있으면 의사 요소 자체가 생성되지 않는다. 점 인디케이터처럼 글자가 없어도 content:""는 반드시 써야 한다.

♿ 접근성·상태 설계

  • 진행 원리: ::scroll-button() 클릭은 스크롤 영역의 약 85%만큼 이동시킨다(검색으로 확인). 슬라이드 하나씩 정확히 넘기려면 scroll-snap-type과 슬라이드 폭을 맞춰야 한다.
  • 폴백이 본체다: @supports selector(...)로 감싸고, 그 밖에서는 JS 버튼을 유지한다. 미지원 브라우저에서 화살표가 통째로 사라지는 게 가장 흔한 사고다.
  • 스크롤 컨테이너 자체에 tabindex="0"과 이름(aria-label)을 준다. 브라우저는 스크롤 가능한 영역을 키보드 초점 대상으로 만들지만, 이름이 없으면 낭독기가 "그룹"이라고만 읽는다.
  • 자동 재생은 넣지 않는다. 굳이 넣는다면 정지 버튼을 같이 두고 prefers-reduced-motion(움직임 줄이기 설정)을 존중한다.
  • 캐러셀 자체를 의심할 것: 중요한 정보를 가로로 숨기면 뒤쪽 슬라이드는 거의 안 보인다. 항목이 5개 이하면 그냥 다 펼치는 편이 낫다.
paysable 적용 포인트 — 대시보드의 "이번 주 정산 요약" 같은 보조 카드 묶음에 먼저 써볼 만하다. 핵심 지표는 절대 캐러셀에 넣지 않는다. 지금 단계에선 기존 JS 캐러셀을 유지한 채 @supports 블록으로 네이티브 버전을 얹어두면, 브라우저가 따라오는 만큼 자동으로 가벼워진다.
