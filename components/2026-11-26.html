🧭 상단 뒤로가기 버튼 — 앱 안에서 왔으면 뒤로, 링크로 바로 열렸으면 부모 화면으로, 결제 단계는 되돌아가지 않게내비게이션결제 흐름

헤더의 ← 버튼을 history.back() 한 줄로 만들면, 카카오톡 링크·푸시·새 탭으로 바로 들어온 사용자는 그 버튼을 누르는 순간 앱을 떠납니다. 결제 완료 화면에선 결제 단계로 되돌아가 "다시 결제"를 부르기도 하죠. 같은 시나리오를 왼쪽(순진한 back)과 오른쪽(판단하는 back)에서 눌러 보세요.

✅ 갈 곳을 판단하는 뒤로가기

아래 띠는 이 탭의 방문 기록입니다(점선 = 다른 사이트, 굵은 테두리 = 지금 화면). 오른쪽은 직전 기록이 우리 앱이고 되돌아가도 안전할 때만 뒤로 가고, 아니면 부모 화면으로 replace(기록을 덮어써서 한 칸을 새로 쌓지 않음)합니다. 그리고 버튼에 어디로 가는지를 씁니다.

버튼을 누르면 새 화면의 제목으로 포커스가 이동합니다(스크린리더가 "어디에 왔는지"를 바로 읽도록). 루트 화면(홈)에선 뒤로 버튼 자체를 숨깁니다.

// app/_components/BackButton.tsx  (Next.js App Router)
'use client';
import { useEffect, useState } from 'react';
import { useRouter } from 'next/navigation';

type Props = { fallbackHref: string; fallbackLabel: string };

function canGoBackInApp(): boolean {
  // Navigation API: 같은 출처(우리 앱)의 직전 기록이 있을 때만 true
  const nav = (window as unknown as { navigation?: { canGoBack: boolean } }).navigation;
  if (nav) return nav.canGoBack;
  // 미지원 브라우저 폴백: 클라이언트 라우팅이 한 번이라도 있었는지 표시해 둔 값
  return sessionStorage.getItem('app:navigated') === '1';
}

export function BackButton({ fallbackHref, fallbackLabel }: Props) {
  const router = useRouter();
  const [inApp, setInApp] = useState(false);
  useEffect(() => setInApp(canGoBackInApp()), []); // 서버 렌더와 어긋나지 않게 마운트 후 결정
  return (
    <button
      type="button"
      onClick={() => (canGoBackInApp() ? router.back() : router.replace(fallbackHref))}
      aria-label={inApp ? '뒤로 가기' : `${fallbackLabel}(으)로 이동`}
    >
      ← {inApp ? '뒤로' : fallbackLabel}
    </button>
  );
}

// 결제 완료로 갈 때는 결제 단계를 기록에서 지운다
router.replace(`/orders/${orderId}/complete`);
핵심: ① 뒤로 = "직전 기록"이지 "부모 화면"이 아니다 — 둘이 다를 땐 다른 걸 알려줘야 한다. ② 직전 기록이 우리 앱인지 알 수 있는 표준 방법이 navigation.canGoBack(아래 🌀 항목). document.referrer는 브라우저·정책에 따라 비는 경우가 많아 근거로 약하다(추정). ③ 되돌아가면 안 되는 화면(결제 진행·인증 완료)은 처음부터 replace로 지나가서 기록에 남기지 않는다. 하이드레이션 전 서버 렌더에서 window를 읽지 않도록 라벨은 클라이언트에서 정한다.

🃏 카드 더보기(⋯) 메뉴 — 자주 쓰는 하나는 밖에, 나머지는 메뉴에, 지우기는 맨 아래 따로, 못 하는 건 숨기지 말고 이유와 함께카드UI접근성

정산 계좌·저장 카드·가맹점처럼 "한 줄 = 하나의 대상"인 카드에 동작이 4~5개 붙으면 버튼을 다 늘어놓을 수 없습니다. 이럴 때 쓰는 ⋯(케밥) 메뉴는 동작 메뉴라서, 링크 목록인 내비게이션 드롭다운과 달리 role="menu"가 맞는 자리입니다. 키보드로 열고(Enter·↓·↑), 화살표로 움직이고, Esc로 닫아 보세요.

등록된 정산 계좌

    각 ⋯ 버튼의 이름은 "더보기"가 아니라 "신한 ···1234 계좌 더보기"입니다. 같은 버튼이 여러 개라 이름이 같으면 스크린리더 사용자는 어느 줄인지 모릅니다.

    메뉴 안: ↑↓ 이동(끝에서 처음으로 돌아감) · Home/End · 글자를 치면 그 글자로 시작하는 항목으로 · Esc는 닫고 ⋯ 버튼으로 포커스 복귀 · Tab은 닫고 다음으로. 화면 아래쪽 카드는 메뉴가 위로 열립니다. 기본 계좌의 "삭제"는 숨기지 않고 비활성 + 이유 문구로 둡니다(aria-disabled라서 포커스는 받음).

menu.addEventListener('keydown', (e) => {
  const items = [...menu.querySelectorAll('[role=menuitem]')];
  const i = items.indexOf(document.activeElement);
  if (e.key === 'ArrowDown') items[(i + 1) % items.length].focus();
  else if (e.key === 'ArrowUp') items[(i - 1 + items.length) % items.length].focus();
  else if (e.key === 'Home') items[0].focus();
  else if (e.key === 'End') items.at(-1).focus();
  else if (e.key === 'Escape') { close(); trigger.focus(); }
  else if (e.key === 'Tab') close();          // 포커스는 자연스럽게 다음으로
  else return;
  e.preventDefault();
});
    지운 뒤 포커스가 사라진 카드와 함께 증발하지 않게 다음 카드의 ⋯ 버튼(없으면 이전 카드)으로 옮깁니다. 되돌릴 수 있는 삭제라면 확인창 대신 실행 취소가 더 빠릅니다. 단, 서버에서 즉시 되돌릴 수 없는 작업(계좌 해지·환불)은 확인 단계가 맞습니다(11-10 "위험도별 확인 3단계" 참고). 참고: WAI-ARIA APG — Menu Button 패턴

    🌀 Navigation API — history.pushState와 popstate 대신, 모든 이동을 한 곳에서 가로채고 "뒤로 갈 수 있나"를 묻기트렌드Baseline 2026

    window.navigation은 링크 클릭·폼 제출·뒤로/앞으로·코드 이동을 하나의 navigate 이벤트로 모아 주고, 이 탭에서 우리 앱이 쌓은 기록(entries())과 canGoBack을 알려 주는 표준 API입니다. 2026년에 주요 브라우저 모두 지원하는 Baseline이 됐습니다. 아래 미니 앱의 링크는 페이지를 새로 불러오지 않고 intercept()로 처리됩니다.

    거래 링크를 빠르게 두 번 눌러 보세요. 앞선 이동의 로딩은 event.signal(AbortSignal)로 취소되고 마지막 것만 그려집니다 — "늦게 온 옛 응답이 덮어쓰기" 문제(10-19)를 라우터 차원에서 막는 방법입니다.

    // 모든 같은 문서 이동을 한 곳에서
navigation.addEventListener('navigate', (e) => {
  const url = new URL(e.destination.url);
  if (!e.canIntercept || e.downloadRequest || !url.hash.startsWith('#/r/')) return;

  e.intercept({
    focusReset: 'after-transition',   // 끝나면 포커스를 문서 처음으로 (직접 하려면 'manual')
    scroll: 'manual',
    async handler() {
      const data = await fetch(apiFor(url), { signal: e.signal }).then(r => r.json());
      render(data);                   // 새 이동이 시작되면 e.signal이 abort → 여기 안 옴
    },
  });
});

navigation.canGoBack;                       // 이 탭의 직전 기록이 우리 앱인가
