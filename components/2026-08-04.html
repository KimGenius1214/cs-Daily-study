🪟 바텀시트 — 드래그로 닫기·백드롭·포커스 관리 오버레이·모달·토스트

모바일 결제 흐름의 기본기. 화면 아래에서 올라와 맥락을 덜 가리고, 손가락이 닿는 하단에 액션을 둔다. 손잡이(grabber)를 아래로 끌면 닫힌다.

아직 선택 안 함

native <dialog> + showModal() → 포커스 트랩·Esc 닫기·백드롭이 공짜. 여기에 손잡이 드래그(pointer 이벤트)만 얹었다. 아래로 30% 넘게 끌면 닫히고, 덜 끌면 제자리로 스냅.

결제수단 선택
왜 모달 대신 바텀시트? 가운데 모달은 화면을 통째로 막아 "이것부터"를 강제한다. 바텀시트는 위쪽 맥락(주문 요약)을 남겨 되돌아가기 쉽고, 엄지 도달 범위(thumb zone)에 버튼이 온다. 대신 접근성은 그대로 챙겨야 한다 — 여기선 dialog가 그 부담을 대신 진다.

🔔 낙관적 UI — 즉시 반영하고, 실패하면 되돌리기 피드백·상태

낙관적 UI(optimistic update): 서버 응답을 기다리지 않고 일단 화면부터 바꾼다. 대개 성공하니 체감 속도가 빨라진다. 핵심은 실패했을 때 깔끔히 롤백하고 이유를 알리는 것.

· 별을 눌러 즐겨찾기 토글
  • 김세일₩ 120,000
  • 이하나₩ 48,500
  • 박도현₩ 9,900

누르는 순간 별이 바뀌고(즉시 반영), 흐릿해지며 저장 중. 성공하면 그대로 확정. "강제 실패"를 켜면 900ms 뒤 서버가 거절 → 원래 상태로 롤백 + 에러 안내. 값을 잠깐 흐리게(saving) 두어 아직 미확정임을 표시.

돈이 오가는 액션엔 함부로 쓰지 말 것. 좋아요·즐겨찾기·읽음처럼 실패해도 손해가 작고 되돌리기 쉬운 것에 적합하다. "결제 승인" 같은 건 낙관적으로 보이면 위험 — 진짜 확정은 서버 응답 뒤 본문 상태로 못박는다.

🌀 View Transitions API — 상태 전환을 라이브러리 없이 부드럽게 트렌드·개념

DOM을 바꾸기 직전/직후를 브라우저가 스냅샷 떠서 사이를 애니메이션해 준다(same-document). 목록→상세처럼 요소가 "이어져 움직이는" 모핑을 framer-motion 없이. 2025-10 기준 주요 브라우저 Baseline.

💳

카드 매출

₩ 3,204,900

전월 대비 +8.4% · 승인 1,204건 · 취소 7건

지원 여부 확인 중…

카드를 누르면 그 카드가 상세 패널로 확장되며 이어진다. 같은 view-transition-name을 공유한 요소끼리 브라우저가 위치·크기를 보간. 미지원 브라우저에선 애니메이션 없이 즉시 교체(폴백). prefers-reduced-motion이면 모션 제거.

주의: startViewTransition의 콜백 안에서 DOM을 바꿔야 스냅샷이 맞물린다. 모든 전환에 쓰면 오히려 산만하니, "맥락이 이어진다"는 신호가 필요한 목록↔상세·탭 전환 정도에 절제해 쓴다. 크로스-도큐먼트(페이지 이동) 버전은 Chrome·Safari만 지원(Firefox 미지원, 2026 추정) — 없어도 그냥 즉시 이동하니 안전.
