🔘 스플릿 버튼 버튼·액션

큰 버튼은 "가장 흔한 동작", 옆 화살표는 "다른 방법". 결제처럼 되돌리기 어려운 동작에선 기본 동작을 무엇으로 두느냐가 핵심입니다.

A. 기본 동작 고정 (결제에 권장)

  • 지금 결제 즉시
  • 예약 결제 날짜 선택
  • 견적서로 저장

메인 라벨은 절대 바뀌지 않습니다. 메뉴에서 "예약 결제"를 골라도 즉시 결제가 나가지 않고 해당 흐름이 열릴 뿐입니다.

B. 마지막 선택 기억 (결제엔 비권장)

  • CSV
  • Excel
  • PDF

되돌릴 수 있는 동작(내보내기)엔 편리하지만, 라벨이 바뀌는 순간 스크린리더에도 알려야 합니다(아래 로그 영역).

키보드: 화살표 버튼에서 Enter/Space/↓로 열기 → ↑↓ 이동 → Enter 선택 → Esc 닫고 화살표 버튼으로 포커스 복귀.
<button aria-haspopup="menu" aria-expanded="false" aria-label="다른 결제 방법">▾</button>
<ul role="menu" hidden><li role="menuitem" tabindex="-1">…</li></ul>

⌨️ 쿠폰 코드 입력 입력·폼

입력은 관대하게 받고(공백·소문자·전각 문자 보정), 결과는 분명하게 말합니다. 시도해 보세요: welcome10, FIRST5000, EXPIRED1, USED1, 아무 값.

입력 → 확인 중 → 적용됨 / 사유별 오류

상품 금액49,000원
할인0원
결제 금액49,000원

적용 중 다른 코드를 연달아 넣으면 마지막 요청 결과만 반영합니다(옛 응답이 덮어쓰기 방지).

에러 문구는 "유효하지 않음" 하나로 뭉치지 않고 만료·이미 사용·없는 코드로 나눕니다. 이 데모의 코드와 응답은 모두 가짜 데이터입니다.
const norm = s => s.normalize('NFKC').replace(/[\s​-‍]/g,'').toUpperCase();

🌀 Invoker Commands 트렌드·개념

버튼에 command·commandfor 속성만 달면 JS 없이 dialog·popover를 열고 닫습니다. 직접 만든 명령은 --로 시작하는 이름과 command 이벤트로 처리합니다.

속성만으로 동작

환불은 영업일 기준 3~5일 걸릴 수 있어요. (예시 문구)

TX-20261109-0042

커스텀 명령 결과가 여기에 표시됩니다.

정말 취소할까요?

닫기 버튼도 속성만으로 동작합니다.

 
<button command="show-modal" commandfor="dlg">열기</button>
<button command="--copy" commandfor="tx">복사</button>
el.addEventListener('command', e => { if (e.command === '--copy') … })

self-contained · 외부 의존성 없음
