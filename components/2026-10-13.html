🪟 간편결제 외부 창 — 차단·닫힘·복귀 오버레이

간편결제·본인인증이 새 창(window.open)으로 뜨는 경우, "안 떴다 / 그냥 닫았다 / 끝났다"를 구분해서 보여줘야 사용자가 갇히지 않는다. (아래 창은 실제 팝업이 아니라 동작을 흉내 낸 가상 창)

① 나쁜 예 — await 뒤에 열기 · 닫힘을 모름   ② 좋은 예 — 클릭 즉시 열기 + 폴백 + 닫힘 확인

✗ 나쁜 예

대기 중

서버 호출(await) 뒤에 창을 열면 사용자 클릭에서 시간이 지나 차단되기 쉽고, 차단돼도 아무 안내가 없다.

✓ 좋은 예

대기 중

클릭 핸들러 안에서 동기적으로 먼저 창을 연 뒤 주소를 채운다 → 막히면 같은 탭 이동으로 폴백, 창이 닫히면 서버 상태부터 확인.

가상 결제 창 (pay.example.com)
12,000원 결제하시겠어요?
// 1) 클릭 핸들러 안에서 "즉시" 연다 (await 이전)
const w = window.open('', 'pay', 'width=420,height=640');
if (!w) { return redirectInSameTab(); }        // 차단됨 → 폴백
const { url, orderId } = await createSession();  // 이후 주소를 채운다
w.location.href = url;

// 2) 결과는 postMessage로 받고 origin을 반드시 검증
window.addEventListener('message', (e) => {
  if (e.origin !== 'https://pay.example.com') return;
  if (e.data?.type === 'PAID') confirmOnServer(orderId);
});
// 3) closed 폴링은 "신호"일 뿐 — 닫힘 후엔 서버로 최종 상태 확인
const t = setInterval(() => { if (w.closed) { clearInterval(t); checkStatus(orderId); } }, 500);
핵심: w.closed는 "결제 취소"가 아니라 "창이 사라짐"이다. 승인 직후 창이 닫히기도 하므로, 닫힘 → 즉시 실패 처리 대신 서버 상태 조회로 확정한다. 브라우저별 차단 정책·COOP 설정에 따라 w.closed/opener 동작이 달라질 수 있어 실기기 검증 필요 — 추정.

🔔 위젯 부분 실패 — 격리·stale·개별 재시도 피드백·상태

대시보드 위젯 3개 중 1개만 실패했는데 화면 전체가 에러가 되면 정상 데이터까지 못 본다. 실패는 위젯 단위로 격리하고, 마지막 성공값은 "오래된 데이터"로 표시한다.

✗ 전부 아니면 전무

Promise.all — 하나라도 거부되면 전체 에러.

✓ 위젯별 격리

Promise.allSettled — 실패 위젯만 에러, 이전 값은 stale 표시, 재시도는 개별.

const results = await Promise.allSettled([getSales(), getSettle(), getRefund()]);
results.forEach((r, i) => {
  if (r.status === 'fulfilled') set(i, { data: r.value, at: Date.now(), stale: false });
  else set(i, { ...prev[i], error: true, stale: !!prev[i]?.data }); // 마지막 성공값 유지
});
// 위젯 컨테이너: role="status" + aria-busy, 에러 문구엔 "다시 시도" 버튼
핵심: stale 값은 반드시 "N분 전 기준"과 함께 보여준다. 금액 위젯에서 시각 표시 없는 옛 숫자는 오류보다 위험하다. 자동 재시도는 지수 백오프(점점 늘리는 간격)로, 사용자가 누르는 재시도와 구분한다.

🌀 scrollbar-gutter — 모달 열 때 화면 흔들림 제거 트렌드·개념

모달을 열며 배경 스크롤을 잠그면(overflow:hidden) 스크롤바가 사라져 본문이 스크롤바 너비만큼 옆으로 밀린다. scrollbar-gutter: stable은 스크롤바 자리를 항상 예약해 이 흔들림을 없앤다.

✗ 기본

콘텐츠 너비 —

✓ scrollbar-gutter: stable

콘텐츠 너비 —

데스크톱(항상 보이는 스크롤바) 기준. 모바일·macOS 오버레이 스크롤바에서는 원래 흔들림이 없어 차이가 안 보일 수 있다.

덤: overscroll-behavior — 모달 안 스크롤이 뒤 배경으로 번지는 것(스크롤 체이닝) 막기

바깥 스크롤 영역 ↓ 안쪽 목록 끝까지 휠을 내려 보세요

기본 — 끝에서 바깥이 따라 움직임

overscroll-behavior: contain

/* 스크롤바 자리를 항상 예약 → 잠금 전후 너비 동일 */
html { scrollbar-gutter: stable; }
/* 모달 열림 동안 배경 잠금 (JS 클래스 토글 없이) */
html:has(dialog[open]) { overflow: hidden; }
dialog .scroll { overscroll-behavior: contain; }
핵심: scrollbar-gutter는 최신 주요 브라우저에서 지원되는 것으로 알려져 있다(web.dev가 Baseline Newly available로 소개). 정확한 버전은 배포 전 MDN/caniuse 확인 — 추정. 레이아웃 폭이 중요한 결제 화면(금액 정렬)에서 모달 열고 닫을 때 숫자가 좌우로 튀지 않게 한다.
