🔔 스켈레톤 스크린 피드백·상태

스피너 대신, 들어올 콘텐츠의 모양 그대로 회색 자리표시를 먼저 그린다. 화면이 튀지 않고(레이아웃 시프트↓) 체감 대기가 짧아진다.

💡 OS에서 “동작 줄이기”를 켜면(prefers-reduced-motion) shimmer·pulse가 자동으로 멈추고 정적 회색으로 표시됩니다.

캡션: 아바타·2줄 텍스트·금액이 들어올 실제 레이아웃과 같은 격자로 스켈레톤을 짜야 로딩→완료 시 요소가 제자리에 붙는다.

언제 쓰나 / 언제 쓰지 말까

  • 쓴다: 목록·카드·대시보드처럼 구조가 예측 가능한 첫 로딩. 0.3~2초대 대기.
  • 스피너가 낫다: 구조를 모르는 짧은 액션(버튼 제출), 아주 빠른(<300ms) 응답, 페이지 일부의 소규모 갱신.
  • 과유불급: 스켈레톤이 1초 미만이면 오히려 깜빡임처럼 보인다 → 최소 표시시간(예 400ms)을 두거나 지연 표시.
용어: 레이아웃 시프트 = 콘텐츠가 늦게 로드되며 화면이 밀려 덜컥이는 현상(CLS). 스켈레톤이 자리를 미리 잡아 이를 줄인다. prefers-reduced-motion = 사용자가 OS에서 “동작 줄이기”를 켰는지 알려주는 CSS 미디어 쿼리.

🪟 위험 액션 확인 다이얼로그 오버레이·모달

삭제·해지처럼 되돌리기 어려운 액션은 마찰을 의도적으로 준다. 확인 문구를 타이핑해야 위험 버튼이 열리고, 기본 포커스는 안전한 “취소”에 둔다.

캡션: 파괴적 확인의 3원칙 — ① 무엇이 사라지는지 명시(자동결제 3건), ② 위험 버튼은 빨강 + 기본 비활성, ③ 실행 후 실행취소를 함께 제공.

디자인 포인트

  • 기본 포커스를 취소에 두어 Enter 오타로 삭제되지 않게.
  • “삭제”를 입력해야 위험 버튼 활성화 → 실수 방지(type-to-confirm).
  • 가능하면 확인창보다 실행취소가 더 낫다. 되돌릴 수 있는 액션은 굳이 막지 말고 취소 기회를 준다.
용어: type-to-confirm = 대상 이름이나 지정 단어를 직접 타이핑해야 실행되게 하는 확인 방식(GitHub 저장소 삭제 등). <dialog> = 브라우저 기본 모달 요소로 포커스 트랩·Esc 닫기·백드롭을 표준 제공.

🌀 진입·퇴장 애니메이션 (@starting-style) 트렌드·개념

모달·팝오버·토스트처럼 화면에 새로 나타났다 사라지는 요소를, 이제 JS 애니메이션 라이브러리 없이 순수 CSS로 부드럽게 들여보내고 내보낼 수 있다.

두 버튼을 번갈아 눌러 열고 닫아 보세요. @starting-style을 준 쪽만 나타날 때·사라질 때 모두 스르륵 전환됩니다.

왜 지금 뜨나 / 무엇을 배워가나

  • 예전엔 display:none → block은 애니메이션이 안 걸려서, JS로 클래스를 두 번(다음 프레임에) 토글하는 트릭이 필요했다.
  • 이제 @starting-style(나타나는 순간의 시작값) + transition-behavior: allow-discrete(display·overlay 같은 “켜짐/꺼짐” 속성도 전환 허용)로 CSS만으로 진입·퇴장을 처리한다.
  • 모달·팝오버·토스트를 한 규칙으로 다룰 수 있어 코드가 준다.
브라우저 지원(확인함, 2026-08): Chrome 121+ · Firefox 129+ · Safari 17.5+ 에서 진입 애니메이션 동작. Baseline에 진입한 기능이라 최신 브라우저 대부분 커버(추정 85~90%).
주의(확인함): Safari는 overlay allow-discrete 미지원이라 닫힐 때 애니메이션이 즉시 사라짐으로 폴백될 수 있음. 진입 효과는 “있으면 좋은” 향상(progressive enhancement)으로 다뤄 없어도 기능은 그대로 되게.
용어: top layer = 모달·팝오버가 다른 요소 위에 겹겹 순서 걱정 없이 뜨는 브라우저 최상위 레이어. overlay 속성은 요소가 이 레이어에 머무는지를 나타내며, 닫힐 때 사라지는 타이밍을 애니메이션과 맞추려면 allow-discrete가 필요하다.
self-contained 라이브 예시 · ?embed=<섹션id> 로 데모만 컴팩트 렌더 · ?theme=dark 지원
