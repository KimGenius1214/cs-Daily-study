💳 카드 정보 입력 — 자동 띄어쓰기·브랜드 감지·Luhn 검사를 "입력 도중엔 조용히" 하기 결제·체크아웃 UX

카드번호를 4자리씩 끊어 보여주고(Amex는 4-6-5), 앞자리로 브랜드를 알아채고, Luhn 검사(카드번호 끝자리가 맞는지 확인하는 간단한 체크섬 알고리즘)로 오타를 잡습니다. 에러는 입력을 마치고 칸을 벗어날 때(blur)만 보여주고, 한 번 에러가 뜬 칸은 고치는 즉시 에러가 사라집니다.

A. 번호 · 유효기간 · CVC

숫자가 아닌 문자는 입력 즉시 걸러지고, 중간을 고쳐도 커서가 튀지 않습니다. 비워 둔 채 칸을 벗어나면 안내가 뜹니다.

B. 붙여넣기·자동완성 시험대

서버/로그에 남길 값: (없음)

버튼으로 자동완성/붙여넣기를 흉내 냅니다. 로그·분석 도구에는 전체 번호 대신 마지막 4자리만 남기세요 — 아래 마스킹 값처럼요.

// 숫자만 남기고 → 포맷 → 커서를 "앞쪽 숫자 개수" 기준으로 복원
function reformat(input, format, max){
  const pos = input.selectionStart;
  const before = input.value.slice(0, pos).replace(/\D/g, '').length;
  const out = format(input.value.replace(/\D/g, '').slice(0, max));
  input.value = out;
  let n = 0, i = 0;
  for (; i < out.length && n < before; i++) if (/\d/.test(out[i])) n++;
  input.setSelectionRange(i, i);
}
const luhn = d => [...d].reverse().reduce((s, c, i) =>
  s + (i % 2 ? ((c * 2) > 9 ? c * 2 - 9 : c * 2) : +c), 0) % 10 === 0;
입력 속성이 절반입니다: inputmode="numeric"(숫자 키패드), autocomplete="cc-number|cc-exp|cc-csc"(브라우저·패스워드 매니저 자동완성). type="number"는 쓰지 마세요 — 앞자리 0·스피너·휠 오입력 문제가 있습니다. 실제 서비스에선 카드번호가 우리 서버를 거치지 않게 PG사의 호스팅 필드/SDK를 쓰는 것이 일반적입니다(정책은 PG사 문서 확인).

⌨️ 금액 입력 — 콤마·한도·한글 읽기로 "0 하나 더" 실수 막기 입력·폼

충전·송금·결제 금액은 0 하나 차이가 사고입니다. 입력하는 동안 천 단위 콤마를 붙이고, 한도를 넘으면 조용히 한도로 맞추고 이유를 알려주며, "백이십삼만 사천오백 원"처럼 한글로 다시 읽어 줍니다.

A. 기본 — 콤마 + 한도(500만 원)

1회 최대 5,000,000원

0으로 시작하는 입력("007")은 7로 정리되고, 붙여넣은 "₩1,200원"도 숫자만 남깁니다.

B. 칩 + 한글 읽기 + 잔액 대비

const fmt = n => n ? n.toLocaleString('ko-KR') : '';
input.addEventListener('input', () => {

  input.value = fmt(n);            // + 위 reformat처럼 커서 복원

// 버튼은 disabled 대신 aria-disabled + 이유를 라벨에 (포커스를 잃지 않게)
금액은 화면에선 문자열로 다루되 서버로는 정수(원 단위)로 보냅니다. 부동소수점(0.1+0.2 문제)이 낄 틈을 없애려면 "정수 + 통화 단위" 계약이 안전합니다. 한글 읽기는 확인용 보조 텍스트이므로 스크린리더가 매 글자마다 읽지 않도록 aria-live="polite"로만 둡니다.

🌀 @starting-style + allow-discrete — display:none에서 나타나는 요소를 CSS만으로 부드럽게 트렌드·개념

예전엔 display:none → block이 되는 순간 transition(속성 변화를 시간에 걸쳐 보간하는 CSS 기능)이 먹지 않아 JS로 클래스를 두 번 나눠 붙이곤 했습니다. @starting-style은 "처음 렌더될 때의 시작값"을 정해 주고, transition-behavior: allow-discrete는 display 같은 이산 속성도 전환에 참여시켜 사라질 때까지 기다려 줍니다.

A. 드롭다운 메뉴 (클래스 토글)

열 때 위에서 살짝 내려오고, 닫을 때도 사라지는 동안 애니메이션이 재생됩니다. Esc로 닫기.

B. 토스트 (popover) · C. 리스트 추가/삭제

  • 정산 완료 알림
  • 환불 승인 알림

토스트는 popover의 top-layer 진입·퇴장을 overlay 전환으로 보이게 하고, 리스트 항목은 추가 시 위에서 내려오고 삭제 시 옆으로 빠집니다.

.menu{ display:none; opacity:0; transform:translateY(-8px);
  transition: opacity .2s, transform .2s, display .2s allow-discrete; }
.menu.open{ display:block; opacity:1; transform:none; }
@starting-style{ .menu.open{ opacity:0; transform:translateY(-8px); } }
/* 팝오버(top layer)는 overlay도 allow-discrete로 */
.toast{ transition: opacity .3s, overlay .3s allow-discrete, display .3s allow-discrete; }
미지원 브라우저에서는 전환 없이 그냥 즉시 나타나고 사라집니다(기능 손실 없음 = 점진적 향상). 브라우저 지원은 web.dev "Now in Baseline: animating entry effects" 글을 기준으로 확인하되, 배포 전 대상 브라우저 버전은 직접 재확인하세요(이 갤러리의 지원 문구는 런타임 감지값입니다). 모션을 줄이려는 사용자를 위해 prefers-reduced-motion에서는 transition을 꺼 둡니다.
