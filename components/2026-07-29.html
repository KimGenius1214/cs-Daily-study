💳 결제 수단 선택 ⌨️ 콤보박스 자동완성 🌀 field-sizing

💳 결제 수단 선택 — 라디오 카드 그룹·저장카드/새카드 전환 결제·체크아웃 UX

결제 수단 선택기(payment method selector)는 체크아웃에서 "무엇으로 낼지"를 고르는 첫 관문입니다. 요즘은 밋밋한 <select>·기본 라디오 대신, 탭 하나로 고르는 큰 카드(radio card)로 만들어 실수를 줄이고, 고른 수단에 맞는 입력만 그 자리에서 펼치는(progressive disclosure, 필요한 것만 단계적으로 노출) 방식이 표준입니다. 아래에서 방향키·Space로 골라 보세요.

💳 신용·체크카드국내외 카드 · 최대 12개월 무이자
⚡ 간편결제토스페이 · 카카오페이 · 네이버페이 추천
🏦 계좌이체실시간 계좌이체 · 수수료 없음
결제 금액 ₩42,000

현재 선택: 신용·체크카드

🧩 변형들 (요즘 패턴)

  • 라디오 카드(radio card) — 작은 원형 라디오 대신 카드 전체가 탭 영역. 손가락·마우스 타깃이 커져 오탭이 줄고, 아이콘·설명·배지를 함께 담습니다.
  • 선택 시 상세 펼침 — 카드 결제를 고르면 카드번호 칸이, 간편결제를 고르면 저장된 페이 목록이 그 자리에서 나타납니다. 안 쓰는 입력을 미리 다 보여주지 않습니다.
  • 저장 수단 + "새로 추가" — 재구매 고객은 저장된 카드를 칩(chip)으로 바로 고르고, 필요할 때만 새 카드 폼을 엽니다(입력 마찰 최소화).
  • 추천·혜택 배지 — "추천", "무이자 12개월"처럼 결정에 영향을 주는 정보를 카드 위에 붙여 선택을 유도합니다.

💻 코드 (핵심 — 라디오 그룹 방향키 + 상세 전환)

const cards = [...group.querySelectorAll('[role=radio]')];
function select(card){
  cards.forEach(c => {
    const on = c === card;
    c.setAttribute('aria-checked', on);
    c.tabIndex = on ? 0 : -1;        // roving tabindex: 선택된 것만 Tab 대상
  });
  renderDetail(card.dataset.pm);     // 고른 수단의 입력만 펼침
}
group.addEventListener('keydown', e => {
  const i = cards.indexOf(document.activeElement);
  if(e.key === 'ArrowDown' || e.key === 'ArrowRight'){
    e.preventDefault(); const n = cards[(i+1) % cards.length]; n.focus(); select(n);
  }
  if(e.key === 'ArrowUp' || e.key === 'ArrowLeft'){
    e.preventDefault(); const n = cards[(i-1+cards.length) % cards.length]; n.focus(); select(n);
  }
  if(e.key === ' ' || e.key === 'Enter'){ e.preventDefault(); select(document.activeElement); }
});

♿ 접근성·상태 설계

  • 컨테이너는 role="radiogroup", 각 카드는 role="radio" + aria-checked — 네이티브 라디오가 아니어도 스크린리더가 "3개 중 1개 선택"으로 읽습니다.
  • 로빙 탭인덱스(roving tabindex) — 그룹 전체가 Tab 한 번으로 들어오고, 안에서는 방향키로 이동합니다(라디오의 표준 키보드 동작). 선택된 카드만 tabindex="0".
  • 선택 표시는 색만이 아니라 원형 라디오 채움·테두리로도 줘서 색각 이상에서도 구분됩니다.
  • 상세를 펼칠 때 새로 뜬 입력으로 포커스를 옮기면 키보드 사용자가 자연스럽게 이어서 입력합니다.

🧠 paysable 적용 포인트

체크아웃 첫 화면의 전환율을 좌우하는 핵심 컴포넌트입니다. 간편결제를 맨 위·"추천" 배지로 두면 결제 완료율이 올라가는 경우가 많고(추정 — A/B로 검증 권장), 재구매 고객에겐 저장 카드 원탭을 기본 노출해 입력 단계를 0으로 줄입니다. 수단별 상세를 지연 렌더(선택 시에만)하면 초기 화면이 가벼워지고, 카드번호 같은 민감 입력을 필요할 때만 DOM에 올려 노출 시간을 줄이는 부수효과도 있습니다.

🔗 참고: WAI-ARIA "Radio Group" 패턴(로빙 탭인덱스). 상세 펼침은 progressive disclosure. Stripe·Toss 체크아웃이 라디오 카드 + 지연 상세의 대표 사례. 이 데모는 self-contained.

⌨️ 콤보박스 자동완성 — 타이핑 필터·키보드 탐색·ARIA 설계 입력·폼

콤보박스(combobox)는 텍스트 입력과 목록을 합친 컴포넌트입니다. 타이핑하면 후보가 실시간 필터되고, 방향키로 고릅니다. 국가·은행·통화처럼 항목이 수십~수백 개인 선택에서 기본 <select>보다 훨씬 빠릅니다. 아래 칸에 "kor", "미국", "en"처럼 쳐 보세요 — 이름·코드 어느 쪽으로도 걸립니다.

    선택된 값: (없음)

    🧩 변형들 (요즘 패턴)

    • 이름·코드 동시 검색 — "대한민국"도, "KR"도, "krw"도 같은 항목을 찾게 하면 사용자가 아는 대로 칠 수 있습니다.
    • 매칭 하이라이트 — 친 글자를 결과에서 굵게 표시해 왜 걸렸는지 즉시 보여 줍니다.
    • 빈 결과 상태 — 후보가 0개면 "결과 없음" 안내로 마무리감을 줍니다(빈 목록만 덩그러니 두지 않기).
    • 열림 방식 선택 — 포커스 시 전체 목록을 열지, 타이핑 후에만 열지는 항목 수·맥락에 따라. 여기선 포커스 시 전체를 엽니다.

    💻 코드 (핵심 — 필터 + aria-activedescendant)

    input.addEventListener('input', () => {
  const q = input.value.trim().toLowerCase();
  const hits = data.filter(d =>
    d.name.toLowerCase().includes(q) || d.code.toLowerCase().includes(q));
  renderList(hits); open();                 // 실시간 필터
});
input.addEventListener('keydown', e => {
  if(e.key === 'ArrowDown'){ e.preventDefault(); move(+1); }
  if(e.key === 'ArrowUp'){   e.preventDefault(); move(-1); }
  if(e.key === 'Enter'){ e.preventDefault(); choose(activeEl); }
  if(e.key === 'Escape'){ close(); }
});
function move(dir){
  active = (active + dir + opts.length) % opts.length;
  opts.forEach((o,i) => o.classList.toggle('active', i === active));
  // 실제 포커스는 input에 두고, 활성 옵션만 id로 가리킨다
  input.setAttribute('aria-activedescendant', opts[active].id);
}

    ♿ 접근성·상태 설계

    • 입력은 role="combobox" + aria-expanded + aria-controls, 목록은 role="listbox", 항목은 role="option" — WAI-ARIA "Combobox with listbox" 패턴 그대로입니다.
    • aria-activedescendant — 실제 DOM 포커스는 입력창에 그대로 두고, "지금 하이라이트된 옵션"만 이 속성으로 가리킵니다. 그래서 타이핑과 목록 탐색이 끊기지 않습니다.
    • 키보드: ↓↑ 이동, Enter 선택, Esc 닫기, 바깥 클릭으로도 닫힘.
    • 매칭 하이라이트는 굵기로 주고, 활성 옵션은 배경색 + 밑줄을 함께 써서 색에만 의존하지 않습니다.

    🧠 paysable 적용 포인트

    결제·정산 화면엔 국가·통화·은행·카드사·수취인 검색 등 "긴 목록 선택"이 자주 나옵니다. 콤보박스로 만들면 스크롤 대신 서너 글자 타이핑으로 끝나 입력 시간이 확 줄죠. 항목이 수백 개를 넘거나 서버에서 와야 하면 디바운스(debounce, 입력이 멎을 때까지 잠깐 기다렸다 요청)로 원격 검색을 붙입니다. 직접 만들기 부담되면 접근성이 검증된 헤드리스 콤보박스(예: Downshift, Radix, React Aria)를 쓰는 편이 안전합니다.

    🔗 참고: WAI-ARIA APG "Combobox (with listbox popup)". 원격 데이터면 debounce + 로딩/빈 상태 처리 필수. 이 데모는 self-contained(로컬 데이터).

    🌀 field-sizing: content — CSS 한 줄로 입력창이 내용만큼 자라기 트렌드·개념

    field-sizing: content는 <textarea>·<input>·<select>가 내용 길이에 맞춰 스스로 커지고 줄어들게 하는 CSS 속성입니다. 예전엔 "타이핑할 때 자동으로 커지는 textarea"를 만들려면 scrollHeight를 재서 높이를 바꾸는 JS가 필요했는데, 이제 CSS 한 줄로 됩니다. 2026년 6월 파이어폭스 152까지 지원이 붙어 Baseline "새로 사용 가능(Newly available)"이 됐습니다(그 전엔 크롬 123·사파리 26.2부터). 아래 왼쪽 칸에 여러 줄 쳐 보세요.

    ❌ 고정 높이 (예전 방식)

    높이가 고정 → 내용이 넘치면 작은 칸 안에서 스크롤(내용 파악이 어려움).

    ✅ field-sizing: content

    CSS field-sizing:content 한 줄 → 내용만큼 자동으로 성장(최대 높이까지). JS 0줄.

    📈 왜 지금 뜨나 / 어디에 쓰나

    • JS 제거 — "auto-grow textarea"는 거의 모든 서비스가 쓰는 패턴인데, 이제 라이브러리·scrollHeight 계산 없이 CSS 한 줄로 끝납니다(유지보수·성능 이득).
    • Baseline 진입(2026-06) — 파이어폭스 152 지원으로 3대 엔진(Chrome·Safari·Firefox) 최신판을 모두 커버해 "이제 실무에 써도 되는" 단계에 들어섰습니다.
    • 어디에 — 채팅·댓글·메모 입력창, 주소·요청사항처럼 길이를 모르는 필드, 태그·금액처럼 내용만큼만 폭을 주고 싶은 인라인 입력.
    • 제어 포인트 — 무한정 커지지 않게 max-height(세로)·max-width(가로)를, 처음 크기는 min-height·rows로 잡습니다.

    💻 코드 (복붙용)

    /* 예전: JS로 높이 재계산 (이제 불필요) */
// el.style.height = 'auto';
// el.style.height = el.scrollHeight + 'px';

/* 지금: CSS 한 줄 */
textarea{
  field-sizing: content;   /* 내용만큼 자라고 줄어듦 */
  min-height: 44px;        /* 시작 높이 */
  max-height: 220px;       /* 이 이상은 내부 스크롤 */
}

/* 인라인으로 가로로 자라는 input (태그·금액 등) */
input.tag{
  field-sizing: content;
  min-width: 60px;
  max-width: 100%;
}

    ♿ 접근성·상태 설계

    • 레이아웃이 커질 때 주변이 밀리므로, 최대 높이/폭을 정해 갑작스러운 점프와 레이아웃 이동(CLS)을 억제합니다.
    • 지원하지 않는 구형 브라우저에서는 그냥 기본 크기로 동작하는 점진적 향상(progressive enhancement, 되는 곳에선 더 좋게, 안 되는 곳에서도 멀쩡하게)이라 안전합니다.
    • 자동 성장이라도 resize 손잡이를 남길지(수동 조절 허용) 여부는 UX 판단 — 이 데모는 resize:none으로 자동에 맡겼습니다.

    🧠 paysable 적용 포인트

    결제 요청·정산 메모·CS 문의처럼 "얼마나 길지 모르는" 입력에 바로 적용할 수 있습니다. 기존에 auto-grow용 JS나 라이브러리를 붙여 뒀다면 CSS 한 줄로 대체하고 걷어내 번들을 줄일 수 있고요(추정 — 실제 제거 전 대상 브라우저 지원표 확인 권장). 다만 사내 지원 브라우저 하한이 낮다면, 걷어내기 전에 폴백(기존 JS 유지 또는 rows 기본값)을 함께 두세요.
