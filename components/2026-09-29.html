🪟 세션 만료 경고 — 조용한 배너에서 모달로, 연장은 한 번에, 입력은 살려두기 오버레이·모달·토스트

결제·금융 서비스는 보안상 유휴 세션을 끊는다. 문제는 "말없이 끊는 것". WCAG 2.2.1은 만료 전에 경고하고 최소 20초 안에 간단한 동작으로 연장할 수 있게 하라고 요구한다. 여기선 데모를 위해 세션을 90초로 줄였다(배속 조절 가능).

라이브 — 2단계 경고(배너 → 모달) + 만료 후 재로그인
⏱️ 남은 세션 1:30
⚠️ 곧 자동 로그아웃돼요. 약 1분 남았어요.
활동하지 않으면 60초 남았을 때 배너, 30초 남았을 때 모달이 뜹니다.

배너 단계는 흐름을 막지 않는다(role=status). 모달 단계에서만 포커스를 가져간다 — 경고를 두 번 나누는 이유.

로그인을 유지할까요?

핵심 코드 — 카운트다운은 "남은 초 빼기"가 아니라 "마감 시각과의 차이"

let deadline = Date.now() + SESSION_MS;          // 기준은 절대 시각
function tick() {
  const left = Math.max(0, deadline - Date.now());  // 백그라운드 탭 타이머 지연에도 정확
  if (left <= 0) return expire();
  if (left <= 30_000 && !dlg.open) dlg.showModal(); // 2단계
  else if (left <= 60_000) banner.hidden = false;   // 1단계
  requestAnimationFrame / setTimeout(tick, 250);
}
// 여러 탭 동기화: 한 탭에서 연장하면 모두 연장
const bc = new BroadcastChannel('session');
bc.onmessage = e => { if (e.data.type === 'extend') deadline = e.data.deadline; };
  • 절대 시각 기준: 브라우저는 백그라운드 탭의 타이머를 늦춘다. count-- 방식은 탭을 오래 비우면 실제보다 많이 남은 것처럼 보인다.
  • 숫자 매초 낭독 금지: 큰 카운트다운은 aria-hidden, 스크린리더엔 별도 status로 30·20·10초만.
  • autofocus는 "연장" 쪽: 파괴적 액션(로그아웃)이 아니라 안전한 쪽에 기본 포커스. Esc로 닫으면 연장으로 취급.

🔔 복사 버튼 피드백 — "복사됨"을 보여주고, 들려주고, 실패하면 손으로라도 피드백·상태

가상계좌 입금 안내, 거래 ID, 초대 링크 — 결제 화면엔 "복사" 버튼이 많다. 누른 뒤 아무 변화가 없으면 사용자는 두세 번 더 누르고, 그래도 불안해서 직접 긁어 간다. 좋은 복사 버튼은 상태 3개(대기·완료·실패)를 가진다.

핵심 코드

const timers = new WeakMap();
async function copy(btn, text, label) {
  try {
    await navigator.clipboard.writeText(text);   // HTTPS + 사용자 제스처 필요
    setState(btn, 'done');  say(`${label}가 복사되었습니다`);
  } catch {
    setState(btn, 'fail');  showManualFallback(text); // 선택해 두고 Ctrl+C 안내
  }
  clearTimeout(timers.get(btn));                   // 연타 시 타이머 리셋
  timers.set(btn, setTimeout(() => setState(btn, 'idle'), 2000));
}
  • 표시값 ≠ 복사값: 화면은 110-123-456789, 복사는 110123456789. 은행 앱마다 하이픈 붙여넣기 처리가 다르므로 숫자만이 안전(추정 — 대부분 앱은 하이픈을 제거하지만 보장되지 않음).
  • 라벨은 바꾸되 폭은 고정: "복사" → "복사됨" 전환 시 min-width로 버튼 폭 흔들림 방지.
  • 아이콘 버튼은 aria-label에 무엇을 복사하는지까지("거래 ID 복사"). 툴팁은 시각용이라 aria-hidden, 알림은 별도 status.

🌀 CSS if() — 속성값 안에서 분기하는 인라인 조건문 트렌드·개념

if()는 값 자리에서 조건을 고르는 CSS 함수다. style(--status: paid)(커스텀 속성 값 비교), media(), supports() 세 종류 조건을 쓸 수 있다. 상태별 클래스를 여러 개 만드는 대신, 변수 하나를 바꾸면 여러 속성이 같이 바뀐다. Chrome·Edge 137+ 지원, Safari·Firefox 미지원 → 점진적 향상 전용.

refunded는 어떤 분기에도 없어서 else(회색)로 떨어진다. 카드 안쪽 여백도 if(media(width < 520px): 8px; else: 16px) — 창을 좁혀 보세요.

함정: if() 안에 var()를 넣으면 폴백이 안 먹을 수 있다
bad: 폴백 뒤에 var() 섞인 if() good: @supports로 감싼 if()

핵심 코드

.chip {
  /* 1) 폴백을 먼저 — 미지원 브라우저는 아래 if() 선언을 통째로 버린다 */
  color: #475569;
  /* 2) 지원 브라우저는 뒤의 선언이 이긴다 */
  color: if(
    style(--status: paid):    #15803d;
    style(--status: failed):  #b91c1c;
    style(--status: pending): #b45309;
    else: #475569
  );
}
/* var()가 섞이면 @supports로 감싸기 */
@supports (color: if(else: red)) {
  .chip { background: if(style(--status: paid): var(--ok-soft); else: var(--surface-2)); }
}
  • style() 쿼리와의 차이: 기존 @container style(--x: y)는 부모 컨테이너의 값을 보고, if(style())는 자기 자신의 계산된 변수를 본다. 래퍼가 필요 없다.
  • var() 함정: 선언에 var()가 들어 있으면 브라우저는 파싱 단계에서 무효 판정을 미룬다. 미지원 브라우저는 if()를 계산 시점에야 무효로 보고 앞 폴백이 아니라 unset으로 떨어진다(사양상 동작, 위 데모에서 확인).
  • 언제 쓰나: 상태·테마·밀도 같은 "변수 하나 → 여러 속성" 매핑. 조건이 복잡하면 여전히 클래스/데이터 속성이 읽기 쉽다.
