📊 서버 페이지네이션 정산 테이블 — 오프셋은 중복을 만들고 커서는 만들지 않는다 데이터·테이블·차트

정산·거래 목록은 수만 건이라 서버 페이지네이션(한 번에 한 페이지만 서버에서 받아오는 방식)이 기본이다. 오프셋 방식(page=2&size=8)은 번호 이동이 쉽지만 보는 도중 새 거래가 들어오면 행이 밀려 중복·누락이 생긴다. 커서 방식(after=마지막 행의 정렬값+id)은 밀리지 않는 대신 "N페이지로 바로 이동"이 없다. 아래에서 직접 비교한다.

A. 필터·정렬·페이지 이동 — 오프셋/커서 전환, 응답 지연 시뮬

정산 내역 (KST 기준 · 열 제목 버튼으로 정렬)
불러오는 중…
따라 해 보기: ① 오프셋에서 1페이지 → [＋ 새 거래] → 다음 페이지 = 주황색 중복 표시 행 발생 ② 커서로 바꿔 같은 순서 반복 = 중복 없음.

정렬을 바꾸거나 필터를 걸면 항상 1페이지로 리셋. 로딩 중엔 이전 행을 지우지 않고 흐리게 + 상단 진행 바(aria-busy)만 보여 화면이 번쩍이지 않는다. 느림(1.2초)에서 빠르게 연속 클릭해도 늦게 온 옛 응답은 버린다(요청 번호 비교).

오프셋 vs 커서

구분오프셋 (page/size)커서 (after)
장점페이지 번호·총 페이지·임의 이동데이터가 바뀌어도 안정, 깊은 페이지도 빠름(인덱스)
단점삽입·삭제 시 중복/누락, 깊을수록 느림(추정: DB가 앞 행을 훑음)임의 페이지 점프 불가, 정렬 키+id 타이브레이커 필수
어울리는 곳관리자 정적 목록, 건수 적음실시간으로 쌓이는 거래 내역·무한 스크롤
 
// 커서: (정렬값, id) 튜플을 불투명 문자열로 — id 타이브레이커가 없으면 같은 값에서 행이 샌다
GET /settlements?sort=-time&limit=8&after=eyJ2IjoxNzU...   // base64(JSON)
// 응답: { items:[...], nextCursor: "eyJ2..." | null }

th[aria-sort="descending"] // 정렬 상태는 th에, 버튼은 th 안에
금액·시간은 서버가 내려준 값을 tabular-nums로 오른쪽 정렬해야 자릿수가 맞는다. 모바일(640px 이하)에선 같은 데이터를 카드형 행으로 재배치하며, display를 바꾸면 표 의미가 사라질 수 있어 role을 명시했다.

🔔 빈 상태 설계 — 처음·검색·필터·오류는 서로 다른 화면이다 피드백·상태

"데이터 없음" 한 문구로 뭉개면 사용자가 다음 행동을 모른다. 빈 상태(목록에 보여줄 항목이 0개인 화면)는 원인별로 메시지와 주 버튼이 달라야 한다. 특히 오류를 빈 상태로 위장하면 결제 도메인에선 "거래가 없다"로 오해해 위험하다.

A. 직접 0건 만들어 보기 — 아래 버튼 또는 검색·칩으로

상태 필터

네 가지 빈 상태

상황메시지주 액션하지 말 것
처음 사용무엇이 여기 쌓이는지 + 첫 행동첫 결제 링크 만들기"데이터가 없습니다"만 쓰기
검색 결과 없음입력어를 그대로 보여주기검색어 지우기필터까지 몰래 초기화
필터 0건걸린 조건을 칩으로 노출칩 개별 해제 / 전체 해제조건 숨기고 빈 화면만
불러오기 실패실패했고 데이터는 안전하다는 말다시 시도(+문의)빈 상태 UI 재사용
 
function emptyKind({ total, q, filters, error, loading }) {
  if (loading) return "skeleton";   // 첫 로딩은 빈 상태가 아니라 스켈레톤
  if (error) return "error";        // 오류가 항상 우선
  if (total === 0 && !q && !filters.length) return "first";
  return q ? "search" : "filter";
}
처음 로딩 중에 "결과 없음"이 깜빡 보이면 안 된다 — 로딩 → 데이터/빈 상태 순으로만 전환. 목록 개수는 role="status"로 알려 스크린리더도 0건을 알 수 있게 한다.

🌀 View Transitions — 목록→상세·정렬 재배치를 JS 애니메이션 없이 트렌드·개념

View Transitions API는 DOM이 바뀌기 전·후 화면을 브라우저가 스냅샷으로 찍고 view-transition-name이 같은 요소끼리 위치·크기를 보간해 주는 기능이다. document.startViewTransition(() => 화면 갱신) 한 줄이 핵심. 같은 문서 안 전환(same-document)은 Baseline "Newly available"로 보도된 바 있다(web.dev 글 제목 기준, 세부 버전은 직접 확인 권장).

A. 목록 → 상세: 클릭한 카드의 아이콘·이름이 이어서 커진다

B. 정렬 재배치: 행마다 고유 이름을 주면 자리를 찾아 이동

    정렬을 눌러 보세요.

    function go(update) {
  if (!document.startViewTransition || matchMedia("(prefers-reduced-motion: reduce)").matches) return update();
  card.style.viewTransitionName = "m-hero";           // 전환 '전' 요소에 이름
  const t = document.startViewTransition(() => {
    update();                                          // 전환 '후' 요소에도 같은 이름
    detail.style.viewTransitionName = "m-hero";
  });
  t.finished.finally(() => { card.style.viewTransitionName = ""; });  // 이름은 쓰고 지운다
}
    함정 ① 같은 이름이 한 화면에 둘이면 전환이 통째로 건너뛰어진다(추정: 이름 중복 시 전환 취소) → 전환 중에만 한 요소에 부여. ② 전환 중 화면은 스냅샷이라 클릭이 안 된다 → 300ms 이하로. ③ 접근성: prefers-reduced-motion이면 호출 자체를 생략. ④ 포커스는 DOM 갱신 콜백 안에서 직접 옮길 것.
