💳 쿠폰·프로모션 코드 입력 — 적용·무효·적용됨·제거 상태 설계 결제·체크아웃 UX

체크아웃에서 가장 자주 깨지는 작은 폼. 코드를 넣고 적용을 누르면 (1) 검증 중 로딩, (2) 성공 시 할인 반영 + 제거 가능한 칩, (3) 실패 시 이유가 붙은 에러. 금액이 그 자리에서 바뀌는 게 핵심이다.

상품 금액₩ 48,000
할인-₩ 0
배송비₩ 3,000
결제 예정 금액₩ 51,000
테스트 코드: WELCOME10(10% 할인) · SAVE5000(5,000원) · FREESHIP(배송비 무료) · 그 외는 무효 처리
작은 디테일이 신뢰를 만든다: 코드는 대문자 자동 정규화(입력은 소문자여도 됨), 빈 값이면 버튼 비활성, 검증 중엔 버튼 잠금+스피너로 중복 제출 방지, 결과는 aria-live로 스크린리더에 읽힌다. 이미 적용된 코드는 입력창을 되살리지 말고 칩 + 제거(×)로 보여줘 "지금 뭐가 걸려 있는지"를 분명히 한다.

⌨️ 콤보박스(자동완성) — ARIA listbox·키보드 내비게이션 입력·폼

타이핑하면 후보가 좁혀지는 입력. 결제 폼의 은행·카드사·국가 선택에서 흔하다. 요즘 표준은 포커스는 입력창에 두고 aria-activedescendant로 "활성 항목"만 가리키는 방식 — 화살표로 훑고 Enter로 고른다.

▾
    아직 선택 안 함

    화살표 ↓↑로 이동, Enter 선택, Esc 닫기, Home/End로 처음·끝. 입력한 글자는 후보에서 강조되고, 없는 은행이면 "일치 항목 없음"을 알린다.

    흔한 실수: 진짜 포커스(DOM focus)를 목록으로 옮기면 타이핑이 끊기고 스크린리더가 혼란스러워진다. 그래서 role="listbox"+role="option"을 두되 포커스는 combobox 입력에 남기고, 활성 항목만 aria-activedescendant로 지목한다(W3C ARIA APG 권장). aria-expanded로 열림 상태, aria-controls로 목록을 연결.

    🌀 Native Popover API — JS 없이 메뉴·툴팁·정보 팝오버 트렌드·개념

    HTML만으로 팝오버를 띄우는 표준. 요소에 popover 속성, 버튼에 popovertarget만 주면 끝. 브라우저가 top-layer(항상 맨 위 레이어)·바깥 클릭으로 닫기(light dismiss)·Esc·포커스 관리를 대신 해준다. 2025-04 Baseline(Chrome·Firefox·Safari·Edge)로 널리 사용 가능.
