계좌이체·가상계좌처럼 현금성 결제일 때만 나타나고, 소득공제(개인)·지출증빙(사업자)에 따라 식별번호 입력이 바뀝니다. 결제 버튼 바로 위에 "무엇으로 신청되는지"를 한 줄 요약합니다.

신청하지 않아도 가맹점이 국세청 자진발급 번호로 발급하는 경우가 있고, 이후 홈택스에서 본인 번호로 등록할 수 있어요(업종별로 다름).

요약 줄은 aria-live="polite"로 바뀔 때만 읽힙니다. 번호 오류는 입력 중이 아니라 blur·결제 시에 보여줍니다.

// 사업자등록번호 검증번호 (가중치 1,3,7,1,3,7,1,3,5)
function isValidBRN(v){
  const d = v.replace(/\D/g,'').split('').map(Number);
  if (d.length !== 10) return false;
  const w = [1,3,7,1,3,7,1,3,5];
  let s = w.reduce((a, wi, i) => a + d[i]*wi, 0);
  s += Math.floor(d[8]*5/10);
  return (10 - s % 10) % 10 === d[9];
}

검증번호 통과 ≠ 실제 존재하는 사업자. 휴·폐업 여부는 서버에서 국세청 조회 API 등으로 따로 확인해야 합니다(클라이언트 검사는 오타 방지용).

⌨️ 이메일 입력 — 고치지 말고 제안하고, 붙여넣기 쓰레기는 조용히 치우기 입력·폼

영수증·정산 메일이 엉뚱한 곳으로 가는 원인 1순위는 도메인 오타(gmial.com, naver.con). 자동으로 바꾸지 않고 "혹시 ~인가요?"를 제안하고, 전각 ＠·앞뒤 공백 같은 붙여넣기 잡음은 정리한 뒤 알려줍니다.

라이브 — 아래 예시를 눌러 넣거나 직접 입력 후 바깥을 클릭(blur)

  • @ 앞뒤에 글자가 있음
  • 도메인에 점(.)이 있음 — type=email은 a@b도 통과시킴
  • 자주 쓰는 도메인 오타 아님

제안은 편집 거리(Damerau-Levenshtein) 2 이하일 때만. "아니요, 그대로"를 누르면 같은 값에 다시 묻지 않습니다. 회사 도메인은 오타 사전에 없으니 막지 않습니다.

const DOMAINS = ['gmail.com','naver.com','daum.net','hanmail.net','kakao.com','nate.com','icloud.com','outlook.com','hotmail.com'];
function suggest(email){
  const [local, domain] = email.split('@');
  if (!domain || DOMAINS.includes(domain)) return null;
  let best = null, bestD = 3;
  for (const d of DOMAINS){ const dist = osa(domain, d); if (dist < bestD){ best = d; bestD = dist; } }
  return best ? `${local}@${best}` : null;   // 고치지 말고 "혹시 이거?"로 제안만
}
const normalize = s => s.normalize('NFKC').replace(/\s+/g,'');  // ＠→@, 전각 영문→반각, 공백 제거

NFKC 정규화: 호환 문자를 표준형으로 접는 유니코드 변환. 전각 ＠·Ａ 같은 문자를 반각으로 바꿔 줘서 한글 IME 상태에서 붙여넣은 이메일을 살려냅니다.

🌀 Intl.Segmenter — "20자 제한"이 이모지·한글에서 틀리는 이유 트렌드·개념

사람이 보는 "한 글자"(grapheme, 자소 묶음)와 JS의 length(UTF-16 코드 유닛)는 다릅니다. 👨‍👩‍👧는 length 8, 🇰🇷는 4, 맥에서 온 NFD 한글 "한"은 3. Intl.Segmenter로 사람 기준 글자 수를 세고, 자를 때도 글자 경계에서 자릅니다.

라이브 — 가맹점 메모(최대 10자) 입력. 예시를 눌러 보세요

글자 수는 사람이 보는 기준으로 셉니다

.length (UTF-16)0
[...s] (코드포인트)0
UTF-8 바이트0

slice는 이모지 중간을 잘라 깨진 문자(�)나 엉뚱한 사람 이모지를 남깁니다. 미리보기·말줄임에서 자주 터지는 버그.

const seg = new Intl.Segmenter('ko', { granularity: 'grapheme' });
const graphemes = s => Array.from(seg.segment(s), x => x.segment);
const countChars = s => graphemes(s).length;
const truncate = (s, n) => { const g = graphemes(s); return g.length > n ? g.slice(0, n).join('') + '…' : s; };
// 서버와 맞추기 전에 먼저 NFC로 정규화 (맥 NFD 한글 대비)
const clean = s => s.normalize('NFC');

지원: Intl.Segmenter는 2024년 4월 Firefox 125 출시로 Baseline(주요 브라우저 공통 지원)이 됐습니다. 오래된 환경 대비 폴백은 Array.from(s)(코드포인트 기준, 이모지 조합은 틀림).

HTML maxlength는 사양상 UTF-16 코드 유닛 기준이라 화면 글자 수와 어긋날 수 있습니다(브라우저별 차이 있음 — 추정). 서버 DB 한도가 바이트/코드포인트 기준이면 "보이는 카운터"와 "서버 검증 규칙"을 따로 두세요.
