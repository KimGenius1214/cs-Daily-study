📊 구성비 막대 — 도넛 대신 100% 누적 막대, 작은 조각은 '기타'로, 반올림 합계는 최대 잔여법으로 100%데이터 시각화정산 대시보드

"결제 수단별 비중"을 도넛으로 그리면 1~3%짜리 조각은 각도로 구분이 안 되고, 퍼센트를 각자 Math.round하면 합계가 98%나 101%가 됩니다. 한 줄짜리 100% 막대 + 같은 순서의 범례 표, 작은 조각 묶기, 합이 정확히 100이 되게 나누는 최대 잔여법(각 값을 내림한 뒤 남은 1%p들을 소수점 아래가 큰 순서대로 나눠 주는 방법)을 비교합니다.

기준·소수 자릿수·묶기 기준을 바꿔 보고, 범례 줄에 마우스/포커스를 올려 보기

😬 각자 Math.round

    합계

    ✅ 최대 잔여법 + 기타 묶기

      합계

      막대는 한눈에 보는 그림이고(role="img" + 요약 라벨), 정확한 값은 같은 순서의 범례 목록이 맡습니다. 색 말고도 순서·라벨·값이 붙어 있어 색약이어도 읽힙니다.

      '기타' 줄을 누르면 안에 묶인 항목이 펼쳐집니다. 묶어도 숨기지는 않습니다 — 정산 담당자는 "휴대폰결제가 몇 %인지"를 결국 찾으니까요.

      // 최대 잔여법(Hamilton): 합이 정확히 100(또는 100.0)이 되게 나누기
function percentLR(values, digits = 0) {
  const unit = 10 ** digits, total = values.reduce((a, b) => a + b, 0);
  if (!total) return values.map(() => 0);
  const raw = values.map(v => (v / total) * 100 * unit);   // 0자리면 % 그대로, 1자리면 ×10
  const floored = raw.map(Math.floor);
  let left = 100 * unit - floored.reduce((a, b) => a + b, 0); // 남은 칸 수
  raw.map((r, i) => [r - floored[i], i])
     .sort((a, b) => b[0] - a[0])                              // 소수점 아래 큰 순
     .forEach(([, i]) => { if (left-- > 0) floored[i] += 1; });
  return floored.map(n => n / unit);
}
// 묶기는 '반올림 전 비율'로 판단하고, 묶은 뒤의 목록에 percentLR을 적용한다
      참고: 최대 잔여법은 의석 배분에서 온 Hamilton 방식입니다. 화면 표시용이며, 금액 자체(원 단위 정산)를 나누는 데 쓰는 건 별개 문제입니다.

      🔔 필터 바꿀 때 로딩 — 이전 결과는 지우지 말고 흐리게, 늦게 온 옛 응답은 버리고, 끝나면 건수로 알리기로딩 상태경쟁 상태

      거래 목록에서 상태 칩을 빠르게 바꾸면 요청이 여러 개 동시에 날아갑니다. 응답은 보낸 순서대로 오지 않습니다. 늦게 도착한 옛 요청이 화면을 덮으면 "취소" 칩이 눌려 있는데 승인 건이 보이는 경쟁 상태(race condition)가 생기죠. 또 매번 표를 비우고 스피너를 돌리면 화면이 깜빡이고 스크롤 위치도 날아갑니다.

      방식을 고르고 → 칩을 빠르게 연달아 눌러 보기 (예: 승인 → 취소 → 실패). '엇갈림 강제'를 켜면 옛 요청이 일부러 늦게 옵니다

      권장 방식: 기존 행은 그대로 두고 aria-busy="true" + 흐림 + 상단 얇은 진행 막대(150ms 지나도 안 끝날 때만). 새 요청을 보내면 이전 요청은 AbortController로 취소하고, 혹시 도착해도 요청 번호가 최신이 아니면 버립니다. 끝나면 "취소 12건"을 낭독기에 한 번만 알립니다.

      검색창은 디바운스(입력이 멈춘 뒤 일정 시간—여기선 300ms—이 지나야 한 번 실행)로 글자마다 요청이 나가지 않게 합니다.

      // React 훅 형태(요지) — 최신 요청만 화면에 반영
function useLatestQuery(params) {
  const [state, set] = useState({ rows: [], loading: true, error: null });
  const seq = useRef(0);
  useEffect(() => {
    const id = ++seq.current;
    const ac = new AbortController();
    set(s => ({ ...s, loading: true }));            // rows는 그대로 둔다 (stale-while-loading)
    fetchTx(params, { signal: ac.signal })
      .then(rows => { if (id === seq.current) set({ rows, loading: false, error: null }); })
      .catch(e => { if (e.name !== 'AbortError' && id === seq.current)
                      set(s => ({ ...s, loading: false, error: e })); });
    return () => ac.abort();                         // 파라미터가 바뀌면 이전 요청 취소
  }, [JSON.stringify(params)]);
  return state;
}
// TanStack Query라면 queryKey에 필터를 넣고 placeholderData: keepPreviousData로 같은 효과
      참고: MDN AbortController, MDN aria-busy. abort는 브라우저 쪽 수신을 끊을 뿐 서버 처리를 되돌리지 않습니다 — 조회(GET)에만 쓰고, 결제 같은 쓰기 요청엔 쓰지 마세요.

      🌀 content-visibility: auto — 화면 밖 긴 목록의 렌더를 건너뛰고, contain-intrinsic-size로 스크롤바 튐 막기CSS 성능Baseline 2024

      content-visibility: auto는 "이 덩어리가 화면 근처에 오기 전까지는 안쪽 레이아웃·그리기를 건너뛰어도 된다"는 CSS 선언입니다. 가상 스크롤(보이는 행만 DOM에 두는 라이브러리) 없이도 수천 행 목록의 첫 렌더가 가벼워집니다. 단, 건너뛴 덩어리는 크기를 모르니 contain-intrinsic-size(렌더 전 임시로 가정할 크기)를 같이 줘야 스크롤바가 튀지 않습니다.

      모드를 바꿔 '다시 그리기'를 누르고 → 레이아웃 시간과 전체 높이를 비교, 박스를 스크롤해 보기 (정산일 365개 × 12행 ≈ 4,400행)

      –DOM 생성 + 첫 레이아웃(ms)
      –스크롤 전체 높이(px)
      –스크롤 중 높이 변화(px)
      –이 브라우저 지원

      'auto만'은 화면 밖 덩어리 높이를 0으로 보기 때문에 전체 높이가 비정상적으로 작고, 스크롤하면서 실제 크기가 드러나 스크롤바가 줄어듭니다. contain-intrinsic-size: auto 330px의 auto는 "한 번 그려진 뒤엔 실제 크기를 기억해 쓰라"는 뜻입니다.

      숫자는 기기·브라우저마다 크게 다릅니다. 차이가 작게 나오면 행 수가 적은 탓이니 상대 비교만 보세요. Ctrl+F로 아래쪽 날짜(예: 12-20)를 찾아도 건너뛴 영역이 정상적으로 검색됩니다.

      /* 정산일 그룹(카드 한 장, 표 한 덩어리) 단위로 건다 — 행 하나하나에 걸면 이득이 적다 */
.settle-day {
  content-visibility: auto;
  contain-intrinsic-size: auto 330px;   /* 렌더 전 가정 높이. auto = 한 번 본 뒤엔 실제 크기 기억 */
}
/* 주의: 페인트 격리(contain: paint)가 함께 걸려 상자 밖으로 삐져나온 건 잘린다.
   행 안의 ⋯ 메뉴·툴팁은 popover / top-layer로 띄우거나, 그 그룹엔 걸지 않는다 */
