📊 넓은 데이터 테이블 — 고정 열·고정 헤더·페이지네이션 데이터·테이블·차트

열이 많은 정산·거래 테이블은 가로로 스크롤된다. 이때 첫 열(거래ID·상점명)과 헤더를 고정(sticky)해 두면 어느 행·어느 열인지 놓치지 않는다. 여기에 페이지네이션으로 한 번에 보는 행 수를 제한한다.

가로/세로 스크롤 + 고정 열·헤더

거래 ID 상점명 결제수단 결제금액 수수료 정산액 승인시각 상태

첫 열과 헤더가 스크롤 중에도 고정된다. 금액 열은 우측 정렬 + tabular-nums(숫자 폭 고정)로 자릿수가 정렬된다. 페이지 버튼으로 8행씩 끊어 본다.

왜 이렇게? 고정 열엔 반드시 불투명 배경색을 줘야 아래로 흐르는 다른 열이 비쳐 보이지 않는다. 좌상단 모서리 셀은 헤더·첫 열이 겹치므로 z-index를 가장 높게 준다. 한 화면에 수백 행을 그리면 느려지니 서버 페이지네이션(또는 가상 스크롤)로 DOM 행 수를 제한한다.

🔔 낙관적 업데이트(Optimistic UI) — 즉시 반영하고 실패 시 되돌리기 피드백·상태(로딩·빈상태·에러)

낙관적 업데이트는 서버 응답을 기다리지 않고 UI를 먼저 바꿔 "됐다"고 보여준 뒤, 뒤에서 요청을 보내고 실패하면 원래대로 롤백(rollback)하는 방식이다. 토글·좋아요·자동저장처럼 대개 성공하는 동작에서 체감 속도를 크게 높인다.

알림 설정 토글 — 낙관적 vs 비관적(서버 대기)

    토글을 눌러보세요. 실패 강제 시 잠깐 켜졌다가 원위치로 롤백되고 재시도 버튼이 뜬다.
    왜 이렇게? 낙관적 UI의 핵심은 실패 처리다. 롤백 없이 "먼저 켜두기"만 하면 서버가 거절해도 화면은 켜진 채 남아 데이터가 어긋난다. 결제·금액처럼 되돌리기 힘든 동작엔 낙관적 UI를 쓰지 말고, 서버 확정 후 반영(비관적)하거나 명시적 확인을 둔다. 상태 변화는 aria-live로 스크린리더에도 알린다.

    🌀 CSS field-sizing: content — JS 없이 입력창이 내용에 맞춰 커진다 트렌드·개념

    textarea·input·select가 입력한 내용 크기에 맞춰 자동으로 늘고 줄게 하는 CSS 한 줄이다. 예전엔 JS로 scrollHeight를 재서 높이를 계산했지만, 이제 field-sizing:content 하나면 된다.

    왼쪽=자동 크기 켬 / 오른쪽=끔(기본). 타이핑해 비교
