💳 할부 개월 선택 — 월 납입액만이 아니라 수수료와 총액까지 결제·체크아웃 UX

개월 수를 고르는 순간 월 납입액·수수료·총 결제액이 같이 움직여야 한다. 무이자 조건과 할부 불가 사유도 숨기지 않고 말해 준다. (요율·조건은 모두 데모용 가상 값)

결제 금액과 카드를 바꿔 보세요

✅ 투명형 — 수수료·총액·무이자 사유 병기

할부 개월

❌ 월 납입액만 강조 — 총액·수수료가 사라진다

할부 개월

같은 선택(왼쪽과 연동)인데 사용자는 "월 3만원"만 본다. 명세서에서 금액이 달라 보이면 CS 문의가 된다.

라디오 그룹이라 방향키로 이동, Space로 선택. 선택이 바뀔 때마다 요약 한 문장만 role="status"로 읽어 준다(옵션 전체를 읽지 않음).

// 원리금균등 월 납입액(데모): pay = P·r / (1 − (1+r)^−n),  r = 연이율/12
const total = Math.round(pay * n);       // 총액은 서버 계산값을 신뢰하되 화면은 같은 규칙으로
const first = Math.floor(pay);           // 1~(n-1)회차
const last  = total - first * (n - 1);   // 마지막 회차에서 원 단위 오차 흡수
// 무이자: fee = 0, 단 카드·최소금액 조건을 만족할 때만
할부 최소 금액(5만원)·무이자 개월 수·수수료율은 카드사·가맹점 정책마다 다릅니다. 이 데모 값은 설명용 가정이며 실제 요율이 아닙니다.
핵심: "월 얼마"는 결론이 아니라 계산 결과일 뿐. 총 결제액과 수수료를 같은 줄에 두고, 할부가 막힌 이유는 비활성 라디오 옆 한 줄로 말한다.

⌨️ 멀티스텝 폼 — 단계 이동·뒤로가기·입력 보존 입력·폼

단계는 숨기기만 하고 값은 지키며, 다음은 현재 단계만 검증한다. 브라우저 뒤로가기도 "이전 단계"로 동작해야 사용자가 입력을 잃지 않는다.

가맹점 정산 계좌 등록 (3단계)

    1. 사업자 정보

    하이픈은 넣든 말든 괜찮아요.

    2. 정산 계좌

    입금 계좌는 가입자 본인 명의여야 해요.

    3. 확인하고 제출

    제출 완료

    정산 계좌가 등록되었어요. 심사는 영업일 기준 1~2일 걸립니다.

    단계 이동 후 입력값은 그대로 남아 있습니다. 2단계에서 브라우저 뒤로가기를 눌러도 1단계로 돌아가고, 완료한 단계는 상단 스텝퍼에서 직접 클릭해 돌아갈 수 있습니다.

    panels.forEach(p => p.hidden = p.id !== 'p' + step)   // 지우지 말고 숨기기(값 보존)
history.pushState({ step }, '')                         // 단계 = 히스토리 항목
addEventListener('popstate', e => go(e.state?.step ?? 1, { push: false }))
// 단계 이동 후 포커스는 그 단계 제목(h3 tabindex=-1)으로
if (!validate(step)) { firstInvalid.focus(); return }   // 다음: 현재 단계만 검증
    핵심: 단계마다 URL을 바꾸지 않아도 history 항목은 쌓을 수 있다. 다만 새로고침 복원이 필요하면 값을 어디에 둘지(서버 임시저장/스토리지)를 먼저 정해야 한다.

    🌀 금액 축약 표기 — Intl compact와 "9.8천"의 함정 트렌드·개념

    Intl.NumberFormat의 notation: 'compact'는 큰 수를 "1.2억" 식으로 줄여 준다. 대시보드 KPI에 편하지만, 반올림과 단위 때문에 돈 숫자에는 그대로 쓰면 위험하다.

    금액을 골라 비교해 보세요

    오늘 정산 예정액 (KPI 타일 예)-

    const compact = new Intl.NumberFormat('ko-KR', { notation: 'compact', maximumFractionDigits: 1 })
compact.format(1_250_000_000)   // "12.5억"  (기본 옵션이면 "13억"으로 반올림됨)
compact.format(9_800)           // "9.8천"   ← 한국어 서비스 관례와 어긋남
// 보정: 1만 미만은 전체 표기, 표시는 줄여도 정확값은 data/title/aria-label에 남기기
<data value="1250000000" title="₩1,250,000,000">12.5억</data>
    compact 단위 문자열(천·만·억)과 반올림 규칙은 브라우저가 쓰는 CLDR(로케일 데이터) 버전에 따라 다를 수 있습니다 — 추정. 위 결과는 이 브라우저에서 실제로 계산한 값이며, 배포 전 주요 브라우저에서 같은 출력인지 확인하세요.
    핵심: 축약은 "읽기 쉬움" 장치일 뿐 정확값이 아니다. 표·정산 내역·영수증에는 전체 금액, KPI·차트 축에만 축약을 쓰고 정확값은 항상 병기한다.
