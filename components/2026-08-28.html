📊 테이블 열 제어 — 다중 정렬·열 숨김·너비 조절·밀도 데이터·테이블·차트

정산표처럼 열이 많은 표는 "모두 보여주기"가 답이 아닙니다. 보는 사람이 필요한 열만 골라, 원하는 순서로 정렬하고, 한 화면에 몇 줄 담을지 스스로 정하게 하는 게 요즘 데이터 그리드의 기본입니다. 아래 표에서 헤더를 클릭하고, Shift+클릭으로 2차 정렬을 얹고, 열 경계를 드래그해 보세요.

표시할 열
정산 거래 목록. 열 머리글 버튼으로 정렬할 수 있습니다.

헤더 클릭 = 단일 정렬(오름 → 내림 → 해제) · Shift+클릭 = 정렬 조건 추가(①②③ 뱃지) · 열 경계 드래그 = 너비 조절 · ⚙️ 열 설정에서 열 숨김. 마지막 남은 열은 끌 수 없게 막아 "빈 표"를 원천 차단합니다.

왜 이렇게 하나 — 정산·거래 화면은 사람마다 보는 열이 다릅니다(CS는 상태·가맹점, 재무는 금액·수수료). 열 설정과 정렬을 사용자별로 저장해 두면 매번 다시 만지지 않아도 됩니다. 실제 서비스에선 이 상태를 URL 쿼리스트링이나 서버의 사용자 설정에 넣습니다(이 데모는 메모리에만 둡니다).

핵심 코드 — 다중 정렬 + aria-sort

<!-- 스크린리더가 "정렬 가능/현재 정렬"을 읽으려면 th에 aria-sort 가 필요 -->
<th aria-sort="ascending"><button type="button">금액 ▲ <span>①</span></button></th>

// 정렬 조건을 "배열"로 들고 있으면 다중 정렬이 자연스럽다
let sorts = [{ key: "amount", dir: -1 }, { key: "merchant", dir: 1 }];

rows.sort((a, b) => {
  for (const s of sorts) {
    const d = compare(a[s.key], b[s.key]) * s.dir;
    if (d !== 0) return d;          // 앞 조건에서 승부가 나면 종료
  }
  return 0;                          // 전부 같으면 원래 순서 유지(안정 정렬)
});

// 클릭 핸들러: shift 여부로 "교체 / 추가"를 가른다
th.addEventListener("click", (e) => {
  const cur = sorts.find(s => s.key === key);
  if (!e.shiftKey) sorts = cur ? (cur.dir === 1 ? [{key, dir:-1}] : []) : [{key, dir:1}];
  else if (!cur)   sorts.push({ key, dir: 1 });
  else if (cur.dir === 1) cur.dir = -1;
  else sorts = sorts.filter(s => s.key !== key);
  render();
});

열 너비 드래그 (포인터 이벤트)

// table-layout:fixed + <colgroup> 이어야 너비가 흔들리지 않는다
handle.addEventListener("pointerdown", (e) => {
  handle.setPointerCapture(e.pointerId);   // 손가락/마우스가 밖으로 나가도 계속 추적
  const startX = e.clientX, startW = col.offsetWidth;
  const move = (ev) => { col.style.width = Math.max(70, startW + ev.clientX - startX) + "px"; };
  handle.addEventListener("pointermove", move);
  handle.addEventListener("pointerup", () => handle.removeEventListener("pointermove", move), { once: true });
});
용어 한 줄
· aria-sort — 표 머리글의 현재 정렬 상태를 보조기기에 알리는 속성. ascending(오름) / descending(내림) / none.
· 안정 정렬(stable sort) — 값이 같은 항목의 원래 순서가 뒤바뀌지 않는 정렬. JS Array.sort는 최신 명세상 안정 정렬입니다.
· setPointerCapture — 드래그 중 포인터가 요소 밖으로 나가도 이벤트를 계속 받게 고정하는 API.
· 밀도(density) — 행 높이 프리셋. 한 화면에 담기는 행 수를 사용자가 고르게 합니다.

🔔 빈 상태 5형 — "아무것도 없음"을 다섯 가지로 나눠 설계하기 피드백·상태

화면에 데이터가 0건일 때 전부 "데이터가 없습니다"로 때우면, 사용자는 내가 뭘 해야 하는지 알 수 없습니다. 원인이 다르면 문구도 행동 버튼도 달라야 합니다. 아래 버튼으로 상태를 바꿔 보세요.

정산 내역 검색어 없음
현재 상태: 로딩

각 상태의 차이는 제목 한 줄 + 다음 행동 버튼에 있습니다. 빈 상태는 "설명"이 아니라 탈출구입니다.

상태원인제목 톤가장 중요한 다음 행동
⏳ 로딩아직 응답 전문구 없음(스켈레톤)없음 — 200ms 미만이면 아무것도 띄우지 않기
🌱 첫 사용정말로 데이터가 0건환영·안내첫 항목 만들기 / 가이드 보기
🔍 검색 결과 없음검색어와 일치 0건중립·사실 전달검색어 지우기 / 오타 제안
🧪 필터 결과 없음필터 조합이 너무 좁음중립 + 원인 지목적용된 필터 보여주고 개별 해제
🔒 권한 없음역할·권한 부족차분한 설명관리자에게 요청 / 다른 계정
⚠️ 불러오기 실패네트워크·서버 오류사과 없이 명확히다시 시도 + 오류코드 노출

핵심 코드 — 상태를 문자열 하나로 모으기

// ❌ 흔한 실수: 조건이 흩어져 "로딩인데 빈 상태"가 깜빡 보인다
if (!data.length) return <Empty />;
if (loading) return <Skeleton />;

// ✅ 하나의 상태값으로 계산해서 한 곳에서 분기
type ListState =
  | "loading" | "error" | "denied"
  | "empty-first" | "empty-search" | "empty-filter" | "ready";

function getListState(q): ListState {
  if (q.isLoading) return "loading";
  if (q.error?.status === 403) return "denied";
  if (q.error) return "error";
  if (q.data.length > 0) return "ready";
  if (q.params.keyword) return "empty-search";
  if (hasActiveFilter(q.params)) return "empty-filter";
  return "empty-first";              // 필터도 검색어도 없는데 0건 = 진짜 첫 사용
}
실무 포인트
  • "첫 사용"과 "결과 없음"을 절대 섞지 말 것. 필터 때문에 0건인데 "첫 거래를 만들어 보세요"가 뜨면 사용자는 데이터가 사라진 줄 압니다.
  • 빈 상태 영역에 role="status" + aria-live="polite"를 두면, 화면을 못 보는 사용자도 "결과 없음"으로 바뀐 걸 듣습니다. (aria-live="polite" = 지금 읽는 걸 끊지 않고 나중에 알려 달라는 뜻)
  • 에러 상태엔 오류 코드/추적 ID를 작게라도 노출하면 CS 문의 처리 시간이 줄어듭니다.
  • 로딩이 아주 짧으면(대략 200ms 이하) 스켈레톤을 띄우지 않는 편이 덜 어수선합니다 — 깜빡임(flash)을 피하는 흔한 관행이며, 정확한 임계값은 서비스마다 다릅니다(추정).

🌀 컨테이너 쿼리 — 화면이 아니라 "담긴 칸"에 반응하는 컴포넌트 트렌드·개념

미디어 쿼리(@media)는 브라우저 창 크기를 봅니다. 그래서 같은 카드라도 사이드바에 넣으면 좁은데 데스크톱이라 넓은 레이아웃이 나오는 사고가 납니다. 컨테이너 쿼리(@container)는 그 컴포넌트를 감싼 부모 칸의 크기를 봅니다. 아래 슬라이더로 칸 너비만 바꿔 보세요 — 창 크기는 그대로인데 카드가 알아서 바뀝니다.

컨테이너 300px — 세로 스택 레이아웃

340px에서 썸네일이 왼쪽으로, 480px에서 금액이 오른쪽 열로 빠지고 상세 정보가 나타납니다. 브라우저 창은 한 번도 건드리지 않았습니다.

지원 여부 확인 중…

코드 — 크기 쿼리

/* 1) 감싼 칸을 "컨테이너"로 선언 (이름은 선택) */
.card { container-type: inline-size; container-name: paycard; }
/* 축약형: container: paycard / inline-size; */

/* 2) 그 칸의 너비로 분기 — 창 크기와 무관 */
@container paycard (min-width: 340px) {
  .card__inner { grid-template-columns: 110px 1fr; }
}
@container paycard (min-width: 480px) {
  .card__inner { grid-template-columns: 130px 1fr auto; }
  .card__extra { display: block; }
}

/* 컨테이너 기준 단위도 쓸 수 있다: cqw(너비 1%), cqi(인라인축 1%) */
.card__title { font-size: clamp(0.95rem, 4cqi, 1.3rem); }

코드 — 스타일 쿼리(style query)

/* 상태를 클래스가 아니라 "CSS 변수"로 두고, 그 값으로 분기한다 */
.card { --tone: paid; }                 /* JS는 이 한 줄만 바꾸면 끝 */

@container paycard style(--tone: failed) {
  .card__badge { background: var(--danger-soft); color: var(--danger); }
  .card__amount { color: var(--danger); }
}

/* JS 쪽 */
card.style.setProperty("--tone", "failed");   // .is-failed 같은 클래스 관리 불필요
용어 한 줄 + 지원 현황
  • container-type: inline-size — 이 요소의 인라인축(가로쓰기에선 너비)을 자식들이 쿼리할 수 있게 만듭니다. size는 높이까지 열지만 높이가 자식에 의존하면 순환이 생겨 잘 안 씁니다.
  • cqi / cqw — 컨테이너 인라인축·너비의 1%에 해당하는 길이 단위. vw의 컨테이너판입니다.
  • 크기 컨테이너 쿼리는 주요 브라우저에 오래 전 안착했습니다.
  • 스타일 쿼리 style()는 검색 결과 기준 Firefox 151(2026년 5월)이 지원하며 Baseline "newly available"에 올랐고, Chrome/Edge 111+, Safari 18+가 지원합니다. 다만 커스텀 속성(--변수)만 질의 가능하고 color·font-weight 같은 일반 속성 쿼리는 아직 어느 브라우저도 지원하지 않습니다. 사내 지원 브라우저 폭에 따라 클래스 폴백을 함께 두세요.
  • 주의: container-type을 준 요소는 크기 격리(containment)가 걸려 자식 내용으로 너비가 늘지 않습니다. 그리드/플렉스 안에서 예상 밖으로 줄어들 수 있으니 감싸는 요소 하나를 더 두는 편이 안전합니다.
