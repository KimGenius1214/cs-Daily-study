📊 금액 테이블의 숫자 조판 데이터·테이블·차트

정산 화면에서 눈이 제일 피곤한 순간은 금액 열을 위아래로 훑을 때다. 대부분의 폰트는 숫자마다 폭이 달라서(1은 좁고 0은 넓다) 자릿수가 같아도 열이 들쭉날쭉해 보인다. 해결은 화려한 차트가 아니라 숫자 조판 — 등폭 숫자, 오른쪽 정렬, 부호 표기, 그리고 셀 안에 들어가는 아주 작은 시각화다.

거래 8건 합계 0원 2026-09-01 ~ 09-04
가맹점별 정산 내역 — 금액은 오른쪽 정렬된 등폭 숫자입니다
가맹점 상태 최근 7일 정산 금액
합계 0

헤더는 position:sticky로 고정, 합계 행은 아래에 고정. 스크롤을 내려도 "지금 보는 숫자가 무슨 열인지"와 "총액이 얼마인지"를 잃지 않는다.

등폭 숫자를 켜고 끄면 이만큼 달라진다

tabular-nums (등폭) — 자릿수가 세로로 맞는다
1,111,111
9,000,000
1,410,983
48,271
7,777,777
proportional-nums (기본) — 1이 좁아 열이 흔들린다
1,111,111
9,000,000
1,410,983
48,271
7,777,777

차이가 잘 안 보이면 두 칸의 오른쪽 끝(정렬선)이 아니라 쉼표 위치를 세로로 따라가 보라. 오른쪽 칸은 쉼표가 지그재그로 흔들린다.

단위와 부호를 어떻게 붙이나

  • 단위는 헤더에 한 번만. 모든 행에 "원"을 붙이면 숫자를 훑는 눈이 계속 걸린다(위 스위치로 켜보면 체감된다).
  • 부호는 색+기호를 같이. 빨강만으로 마이너스를 표시하면 색각 이상 사용자에게 전달되지 않는다. −/+를 함께 쓴다.
  • 0은 0으로, 없음은 “—”로. "값이 0원"과 "아직 데이터 없음"은 다른 상태다.
  • 반올림은 한 곳에서. 화면에서 반올림한 값들을 더하면 합계가 안 맞는다. 합계는 항상 원본 값으로 계산해 표시만 반올림한다.

💻 핵심 코드

/* 1) 숫자 열: 등폭 + 오른쪽 정렬 */
td.amt { text-align: right; font-variant-numeric: tabular-nums; }

/* 2) 헤더·합계 고정 */
thead th { position: sticky; top: 0;    background: var(--surface-2); z-index: 2; }
tfoot td { position: sticky; bottom: 0; background: var(--surface-2); }

/* 3) 셀 안 미니 막대 — 같은 열 안에서의 상대 크기 */
.microbar   { height: 4px; border-radius: 2px; background: var(--brand-soft); }
.microbar i { display:block; height:100%; background: var(--brand); }

♿ 접근성·상태 설계

  • <caption>으로 표의 목적을 한 줄 적는다(시각적으로 숨겨도 스크린리더는 읽는다).
  • 헤더 셀은 <th scope="col">. 스크린리더가 셀을 읽을 때 "가맹점 A, 정산 금액, 1,410,983"처럼 열 이름을 함께 말해준다.
  • 정렬 가능한 열은 aria-sort="ascending|descending|none"으로 현재 정렬 방향을 알린다.
  • 미니 막대는 장식이므로 aria-hidden="true". 값은 이미 옆 숫자로 읽힌다.
  • 상태 배지는 색만 쓰지 말고 글자를 같이 넣는다(정산완료 / 대기 / 실패).
tabular-nums가 안 먹는 경우 — 이 기능은 폰트 안에 등폭 숫자 자형이 들어있어야 작동한다. HTTP Archive의 2024년 Web Almanac 집계로는 웹폰트 중 등폭/비례 숫자 변형을 갖춘 비율이 16% 정도라고 한다. 즉 브랜드 폰트를 쓰면 선언해도 조용히 무시될 수 있다 — 숫자 열에만 시스템 폰트를 지정하는 게 현실적인 대안이다(추정: 폰트마다 결과가 다름).

🔔 실패했을 때 되살리는 UI 피드백·상태

로딩과 빈 상태는 많이들 챙기는데, 에러 이후는 대개 "오류가 발생했습니다"에서 멈춘다. 결제 도메인에서 이건 치명적이다 — 사용자는 돈이 빠져나갔는지 아닌지를 모른 채 새로고침을 누른다. 좋은 에러 화면은 세 가지를 답해준다: 뭐가 실패했나 / 내 돈은 어떻게 됐나 / 지금 뭘 누르면 되나.

온라인 — 연결 정상

① 자동 재시도 — 기다리는 시간을 보여준다

⚠️

정산 내역을 불러오지 못했습니다

서버 응답이 없습니다. 결제는 진행되지 않았습니다.

지수 백오프(exponential backoff): 재시도 간격을 1초 → 2초 → 4초처럼 배로 늘리는 방식. 전부가 동시에 재시도해 서버를 다시 죽이는 걸 막는다. 거기에 지터(jitter) — 간격에 랜덤 오차를 조금 섞어 재시도 시점이 겹치지 않게 흩뜨리는 것 — 를 더한다. 중요한 건 남은 시간을 사용자에게 보여주는 것. 조용히 기다리면 멈춘 걸로 보인다.

② 부분 실패 — 성공한 건 되돌리지 않는다

일괄 송금 5건 대기 중

    5건 중 2건이 실패해도 전체를 초기화하지 않는다. 성공·실패를 행 단위로 남기고, 재시도 버튼은 실패한 것만 다시 보낸다. 이때 각 건에 붙어 있는 Idempotency-Key 가 핵심이다 — 같은 키로 다시 요청하면 서버가 "이미 처리한 건"으로 인식해 중복 송금이 일어나지 않는다. 재시도 버튼을 안심하고 누를 수 있는 이유가 이것이다.

    에러 문구 3원칙 — ① 사용자 언어로("HTTP 502" ❌ / "서버가 응답하지 않습니다" ⭕), ② 돈의 상태를 명시("결제는 진행되지 않았습니다" / "승인은 완료됐고 영수증만 실패했습니다"), ③ 다음 행동을 버튼으로. 문의가 필요하면 추적 번호를 화면에 노출하고 복사 버튼을 준다.

    💻 핵심 코드

    // 지수 백오프 + 지터. 4xx(클라이언트 잘못)는 재시도해도 소용없으니 즉시 포기한다.
async function fetchWithRetry(url, opts = {}, max = 4) {
  for (let attempt = 0; attempt <= max; attempt++) {
    try {
      const res = await fetch(url, opts);
      if (res.ok) return res;
      if (res.status >= 400 && res.status < 500 && res.status !== 408 && res.status !== 429) {
        throw new Error("재시도 불가: " + res.status);   // 입력이 틀린 것 → 다시 보내도 같음
      }
    } catch (e) {
      if (attempt === max) throw e;
    }
    const base = 1000 * 2 ** attempt;          // 1s, 2s, 4s, 8s
    const jitter = Math.random() * base * 0.3; // 최대 30% 랜덤 오차
    await new Promise(r => setTimeout(r, base + jitter));
  }
}
    // 결제·송금은 반드시 멱등키를 함께 보낸다.
// 키는 "요청을 만들 때" 한 번 생성해 재시도에서도 그대로 재사용하는 게 핵심.
const key = crypto.randomUUID();
await fetchWithRetry("/api/transfers", {
  method: "POST",
  headers: { "Content-Type": "application/json", "Idempotency-Key": key },
  body: JSON.stringify({ to, amountKrw }),
});

    ♿ 접근성·상태 설계

    • 에러 영역은 role="alert"(즉시 읽힘), 카운트다운처럼 반복 갱신되는 건 role="status" aria-live="polite"(하던 말을 끊지 않음).
    • 카운트다운 숫자를 1초마다 aria-live로 읽어주면 소음이 된다. 상태가 바뀔 때만 문장을 갱신한다("3초 후 다시 시도합니다" → "다시 시도 중").
    • 재시도 버튼은 요청 중 disabled + aria-busy="true". 중복 클릭으로 요청이 두 번 나가지 않게 한다.
    • 스피너는 prefers-reduced-motion(사용자가 OS에서 "동작 줄이기"를 켠 상태)에서 회전을 느리게 하거나 정적 표시로 바꾼다.
    • 에러 발생 시 포커스를 에러 박스로 옮기면 키보드 사용자가 재시도 버튼까지 바로 도달한다.

    🌀 CSS Anchor Positioning 트렌드·개념

    툴팁·드롭다운·팝오버를 만들 때 늘 하던 짓 — 버튼의 좌표를 getBoundingClientRect()로 재고, 스크롤·리사이즈마다 다시 재고, 화면 밖으로 나가면 반대편으로 뒤집는 계산을 하고… 이걸 대신해주는 게 Floating UI 같은 라이브러리였다. 이제 CSS가 직접 한다. 요소에 이름을 붙이고(anchor-name), 다른 요소가 그 이름에 붙는다(position-anchor).

    ① 스크롤해도 따라붙고, 잘리지 않는다

    9월 1주 정산
    1,410,983원
    수수료 32,110원 차감 후 · 09-08 입금 예정

    박스 안을 위아래로 스크롤해 보라. 버튼이 위쪽 끝에 가까워지면 팝오버가 아래로, 아래쪽 끝에 가까워지면 위로 뒤집힌다 — @position-try가 자동으로 대안 위치를 시도한 결과다. JS 한 줄 없이. (팝오버는 popover 속성 덕에 최상위 레이어에 뜨므로 부모의 overflow에 잘리지 않는다.)

    ② 툴팁 세 개, CSS만으로

    결제 승인 금액에서 PG·카드사 몫으로 빠지는 금액입니다.
    영업일 기준 D+2에 등록된 계좌로 입금됩니다.
    분쟁·환불 가능성 때문에 일시적으로 잡아두는 금액입니다.

    마우스를 올리거나 Tab으로 포커스를 옮겨 보라. 세 툴팁 모두 각자의 앵커 위에 뜬다 — 위치 계산 코드는 CSS 두 줄(anchor-name, position-area)이 전부다.

    anchor-name 기준이 될 요소에 이름 붙이기 position-anchor 그 이름에 붙겠다고 선언 position-area 앵커 기준 어느 칸에 놓을지 @position-try 안 들어가면 시도할 대안 위치

    📈 왜 지금 뜨나

    • Baseline에 올라왔다. 검색 결과 기준 Chrome/Edge 125+, Firefox 132+, Safari 18.2+에서 핵심 기능이 동작한다. 다만 @position-try(자동 뒤집기)는 Safari 18.4+가 필요하다고 알려져 있다 — 즉 구형 Safari에선 위치는 맞지만 뒤집기는 안 되는 절반 상태가 된다.
    • 번들이 줄어든다. 툴팁 위치 계산만을 위해 들고 있던 포지셔닝 라이브러리를 덜어낼 수 있다.
    • Popover API와 짝이다. popover 속성이 "최상위에 띄우기 + ESC로 닫기 + 바깥 클릭으로 닫기"를 맡고, 앵커 포지셔닝이 "어디에 띄울지"를 맡는다. 둘을 합치면 드롭다운 하나에 JS가 거의 필요 없다.
    • 스크롤 컨테이너 문제의 정석 해법. 테이블 안 드롭다운이 overflow:hidden에 잘리는 고질병을 포털(portal) 없이 푼다.

    💻 핵심 코드

    /* 1) 기준 요소에 이름표를 붙인다 (--로 시작하는 커스텀 이름) */
.trigger { anchor-name: --menu-trigger; }

/* 2) 붙을 요소가 그 이름을 가리킨다 */
.dropdown {
  position: absolute;
  position-anchor: --menu-trigger;
  position-area: block-end span-inline-end;  /* 앵커 아래, 오른쪽으로 늘어남 */
  margin-block-start: 8px;
}

/* 3) 화면 밖으로 나가면 시도할 대안 위치들 */
@position-try --flip-up   { position-area: block-start span-inline-end; }
@position-try --flip-left { position-area: inline-start span-block-end; }
.dropdown { position-try-fallbacks: --flip-up, --flip-left; }

/* 4) 폭을 앵커에 맞추기 — anchor-size()로 앵커의 치수를 직접 참조 */
.dropdown { min-width: anchor-size(width); }
    <!-- Popover API와 합치면 여닫기 JS도 사라진다 -->
<button class="trigger" popovertarget="menu">메뉴</button>
<div class="dropdown" id="menu" popover>…</div>
<!-- ESC 닫기·바깥 클릭 닫기·최상위 레이어 표시가 브라우저 기본 동작으로 딸려온다 -->
    /* 안전한 도입법: 지원하는 곳만 새 방식, 아니면 기존 방식 유지 */
@supports (anchor-name: --x) {
  .dropdown { position-anchor: --menu-trigger; position-area: block-end; }
}
/* 지원 안 하면 위 블록이 통째로 무시되고 기존 JS 포지셔닝이 그대로 산다 */

    🧠 paysable 적용 포인트

    • 거래 테이블 행 메뉴 — 스크롤 컨테이너 안에서 "…" 메뉴가 잘리는 문제를 포털 없이 해결.
    • 금액 옆 물음표 툴팁 — 수수료·보류금 설명 툴팁을 라이브러리 없이. 위 데모 ②가 그대로 그 형태다.
    • 단, 결제 확인 같은 필수 흐름엔 아직 이르다(추정) — 구형 Safari에서 뒤집기가 빠지므로 화면 가장자리에서 잘릴 수 있다. 취소해도 되는 보조 UI부터 적용하는 게 안전하다.
