🔘 툴바와 토글 버튼 — Tab 한 번, 화살표로 이동, 눌림은 aria-pressed 버튼·액션

버튼이 6개 붙은 툴바를 Tab으로 6번 지나가게 하면 키보드 사용자는 표까지 가는 데 지친다. roving tabindex(묶음 안에서 한 버튼만 tabindex="0", 나머지는 -1로 두고 화살표로 "0"을 옮기는 기법)로 툴바 전체를 Tab 정지점 하나로 만들고, 켜짐/꺼짐이 있는 버튼은 aria-pressed로 상태를 말하게 한다.

변형 A — 거래내역 툴바 (roving tabindex + 토글 + 비활성 이유)

툴바에 Tab으로 들어온 뒤 ←→ HomeEnd 로 이동, Space/Enter로 누르기
선택된 거래가 없어 환불할 수 없습니다. 목록에서 거래를 먼저 고르세요.
    키 입력 로그가 여기 표시됩니다.

    비활성 버튼도 툴바 안에선 포커스는 받게 둔다(aria-disabled) — 화살표로 지나가다 "왜 안 되지?"의 답(aria-describedby)을 들을 수 있어야 하니까.

    변형 B — "토글"을 무엇으로 만들까: 눌림 버튼 · 스위치 · 흔한 실수

    눌러 보고, 아래 "스크린리더가 듣는 말(모식도)"이 어떻게 바뀌는지 비교

    ✅ 눌림 버튼 (aria-pressed)

    ✅ 스위치 (role="switch")

    ❌ 라벨도 바꾸고 pressed도 바꿈

    언제쓸 것규칙
    필터·보기 옵션처럼 "눌러둔 상태"<button aria-pressed>라벨은 고정, 상태는 aria-pressed만 바꾼다
    설정처럼 즉시 켜짐/꺼짐 반영role="switch" aria-checked누르는 즉시 저장. "저장" 버튼이 따로 있으면 체크박스가 맞다
    라벨이 행동을 바꿔 말함(일시정지↔재개)그냥 <button>aria-pressed를 빼야 이중 부정("일시정지 해제, 눌림")이 안 생긴다

    💻 코드 — roving tabindex 최소 구현

    <div role="toolbar" aria-label="거래내역 도구">
  <button aria-pressed="true">환불 포함</button>
  <button aria-pressed="false" tabindex="-1">테스트 결제</button>
  <button aria-disabled="true" aria-describedby="why" tabindex="-1">선택 건 환불</button>
</div>

const items = [...toolbar.querySelectorAll('button')];
toolbar.addEventListener('keydown', (e) => {
  const i = items.indexOf(document.activeElement);
  const next = { ArrowRight: i + 1, ArrowLeft: i - 1, Home: 0, End: items.length - 1 }[e.key];
  if (next === undefined) return;
  e.preventDefault();
  const n = (next + items.length) % items.length;      // 끝에서 처음으로 순환
  items.forEach((b, k) => b.tabIndex = k === n ? 0 : -1); // Tab 정지점은 항상 1개
  items[n].focus();
});
    🧠 배울 점: Tab은 "영역 사이" 이동, 화살표는 "영역 안" 이동 — 탭·라디오·메뉴·툴바가 전부 이 규칙이다. 한 번 useRovingTabIndex 훅으로 만들어두면 세그먼트 컨트롤·필터 칩에도 재사용된다.

    ⌨️ 비밀번호·결제 PIN 설정 — 규칙은 미리 보여주고, 틀림은 늦게 말하기 입력·폼

    "8자 이상, 영문·숫자·특수문자 조합"을 제출 후 에러로 알려주면 사용자는 규칙을 외워서 다시 친다. 요즘은 규칙을 체크리스트로 먼저 깔아두고 입력에 따라 하나씩 초록으로 바꾼다. 결제 PIN은 한 단계 더 — 쉬운 번호(111111·123456)를 막고, 두 번 입력으로 확인한다.

    const RULES = {
  len:   v => v.length >= 8,
  alpha: v => /[a-z]/i.test(v),
  num:   v => /\d/.test(v),
  sym:   v => /[^a-z0-9]/i.test(v),
  rep:   v => v.length > 0 && !/(.)\1\1/.test(v),
};
let touched = false;
pw.addEventListener('input', paint);
pw.addEventListener('blur', () => { touched = true; paint(); });

function paint() {
  for (const li of rulesEl.children) {
    const ok = RULES[li.dataset.r](pw.value);
    li.classList.toggle('met', ok);
    li.classList.toggle('fail', !ok && touched);   // 입력 중엔 절대 빨강 금지
    li.querySelector('.st').textContent = ok ? ' — 충족' : ' — 미충족';
  }
}

    🧠 배울 점: 체크리스트는 aria-live로 매 글자마다 읽히게 하지 말 것 — 입력 중 수다가 된다. 각 항목에 숨김 텍스트("충족/미충족")를 두고 aria-describedby로 필드에 연결하면, 사용자가 원할 때 필드에서 다시 들을 수 있다.

    🌀 CSS @scope — BEM 없이 "이 컴포넌트 안에서만", 그리고 "여기부터는 빼고" 트렌드·개념

    @scope (.root) to (.limit) { … }는 스타일이 적용될 시작점(스코프 루트)과 끝점(스코프 한계)을 CSS가 직접 안다. 클래스 이름 규칙(BEM)이나 CSS Modules 해시 없이도 컴포넌트 스타일이 밖으로·안쪽 슬롯으로 새지 않는다. Chrome 118·Safari 17.4에 이어 Firefox 146이 지원하면서 주요 브라우저 모두에서 쓸 수 있게 됐다.

    💻 코드

    /* ① 근접성: 둘 다 명시도가 같아도, 더 가까운 스코프 루트가 이긴다 */
@scope (.t-light) { a { color: #1d4ed8; } }
@scope (.t-dark)  { a { color: #93c5fd; } }

/* ② 도넛 스코프: .card 안이지만 .slot 아래는 제외 */
@scope (.card) to (.slot) {
  :scope { padding: 16px; }          /* :scope = 루트(.card) 자신 */
  p { font-size: 12px; color: gray; } /* 슬롯 안 p 에는 적용 안 됨 */
}

/* ③ <style> 안에 루트 없이 쓰면 "부모 요소"가 루트 (인라인 컴포넌트 스타일) */
<div class="promo">
  <style> @scope { h3 { color: tomato; } } </style>
  <h3>이 h3만 빨강</h3>
</div>
    • 근접성(scoping proximity): 명시도(specificity)가 같을 때 소스 순서보다 먼저 따지는 규칙. "DOM에서 몇 단계 위에 루트가 있나"가 가까운 쪽이 이긴다.
    • 명시도 주의: @scope (.card)의 .card는 안쪽 규칙 명시도에 더해지지 않는다. :scope나 &를 쓰면 더해진다.
    • CSS Modules·Tailwind와 경쟁? 대체라기보다 보완 — 특히 CMS/가맹점 HTML처럼 통제 못 하는 콘텐츠를 품는 컴포넌트에서 도넛 스코프가 빛난다.
    🧠 배울 점: 우리가 CSS-in-JS·Modules를 쓴 큰 이유가 "스타일 누수"였는데, 그 절반은 이제 플랫폼이 해준다. 단 Baseline "신규(newly available)" 단계라 구형 브라우저 사용자 비중을 먼저 확인하고, 미지원 시에도 깨지지 않게(스코프 없이도 무난한 기본 스타일) 짜는 게 안전하다.
