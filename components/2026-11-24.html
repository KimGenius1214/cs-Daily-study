단계형 모달 — 모달 위에 모달을 쌓지 말고 한 창 안에서 단계를 바꾸고, 포커스는 새 단계 제목으로 🪟 오버레이·모달·토스트

환불처럼 “금액 고르기 → 사유 → 최종 확인”이 이어지는 일을 모달 여러 개로 쌓으면, Esc 한 번에 어디가 닫히는지·뒤 창의 입력이 살아 있는지 사용자도 낭독기도 헷갈립니다. 하나의 <dialog> 안에서 내용만 바꾸고, 단계 표시·이전 버튼·닫기 확인을 그 안에 둡니다.

같은 환불 흐름, 두 가지 구조 (모의 데이터 · 결제 38,000원)

❌ 모달을 쌓는 방식

“다음”마다 새 dialog를 위에 띄웁니다. 열어서 Esc를 눌러 보세요.

✅ 한 창 안에서 단계 전환

단계가 바뀌면 포커스가 새 단계 제목으로, 이전으로 돌아가도 입력은 유지. 입력 후 닫으면 창 안에서 한 번 확인합니다.

기록은 일부러 화면에 남깁니다. 실제 서비스라면 최종 결과만 알림(토스트·상태 문구)으로 알립니다.

환불 금액
환불 사유
정말 환불할까요?
결제 환불

3단계로 진행합니다. 마지막 단계에서 환불하기를 눌러야 실제로 환불됩니다.

입력한 내용이 사라져요. 환불 창을 닫을까요?
  1. 1. 금액
  2. 2. 사유
  3. 3. 확인
 
<dialog id="refund" aria-labelledby="t">   <!-- 창은 하나 -->
  <h2 id="t">결제 환불</h2>
  <ol aria-label="진행 단계"><li aria-current="step">1. 금액</li>…</ol>
  <section data-step><h3 tabindex="-1">환불할 금액을 고르세요</h3>…</section>
</dialog>

function go(next){
  state.step = next;                 // 입력값은 state에 — 단계 DOM을 지워도 유지
  render(state);
  host.querySelector('h3').focus();  // 새 단계 제목으로 포커스 이동 → 낭독기가 단계를 읽음
}
dialog.addEventListener('cancel', e => {   // Esc
  if (isDirty(state) && !confirming) { e.preventDefault(); showInlineGuard(); }

서비스 공지 배너 — 점검 시각은 KST로 못박고, 닫으면 공지 ID로 기억하고, 심각도가 오르면 다시 띄우기 🔔 피드백·상태(로딩·빈상태·에러)

PG 점검·카드사 장애 공지는 “닫기 한 번에 영영 사라짐”과 “닫아도 매번 다시 뜸” 사이에서 균형이 필요합니다. 닫은 기록을 공지 ID + 단계로 남겨 같은 공지는 다시 안 띄우되, 예고→임박→진행 중처럼 상황이 바뀌면 다시 보여줍니다. 결제를 막는 공지면 결제 버튼에도 이유를 붙입니다.

진행 중(결제 차단)은 닫을 수 없고 role="alert"로 한 번 낭독, 예고는 조용히. 종료 공지는 8초 뒤 스스로 접힙니다.

// 닫은 기록: "공지 ID@단계" — 단계가 오르면 키가 달라져 다시 보인다
const key = n => `${n.id}@${n.phase}`;
const dismissed = new Set(JSON.parse(localStorage.getItem('notice:dismissed') ?? '[]'));
const visible = notices
  .filter(n => n.phase !== 'live' ? !dismissed.has(key(n)) : true)   // 결제 차단 중엔 못 닫음
  .sort((a, b) => SEVERITY[b.phase] - SEVERITY[a.phase]);          // 가장 심각한 것 먼저
// 시각은 서버가 준 ISO(UTC) → 표시만 KST로, 시간대 라벨을 붙여서
new Intl.DateTimeFormat('ko-KR', { timeZone: 'Asia/Seoul', month: 'long', day: 'numeric',
  weekday: 'short', hour: '2-digit', minute: '2-digit', hourCycle: 'h23' }).format(new Date(n.startsAt));

스크롤 기반 애니메이션 — animation-timeline의 scroll()·view()로 읽기 진행 막대와 등장 효과를 스크롤 리스너 없이 🌀 트렌드·개념

기존엔 scroll 이벤트나 IntersectionObserver로 진행률을 계산해 스타일을 바꿨습니다. 이제 CSS 애니메이션의 “시간축”을 스크롤 위치로 바꿀 수 있습니다. scroll()은 스크롤 컨테이너가 얼마나 내려갔는지, view()는 요소가 화면 안에 얼마나 들어왔는지를 진행도로 씁니다.

각 상자를 스크롤해 보세요

정산 안내 (CSS 타임라인)

JS 0줄. 진행 막대 = scroll-timeline, 카드 등장 = view(). 미지원 브라우저에선 막대가 안 보이고 카드는 그냥 보입니다(내용을 숨기지 않음).

정산 안내 (JS 대체 구현)

같은 결과를 scroll 리스너 + IntersectionObserver로. 미지원 브라우저용 폴백이 필요하면 이쪽을 @supports not 일 때만 켭니다.

⚠️ 함정: animation 단축 속성은 animation-timeline을 기본값(auto)으로 되돌립니다. 반드시 animation: 다음 줄에 animation-timeline:을 쓰세요.

@supports (animation-timeline: scroll()) {
  .article   { scroll-timeline: --article block; }          /* 이 컨테이너의 세로 스크롤을 타임라인으로 */
  .progress  { animation: grow linear both;                 /* ① 단축 속성 먼저 */
               animation-timeline: --article; }             /* ② 타임라인은 그 다음 줄 */
  .card      { animation: reveal linear both;
               animation-timeline: view();                  /* 요소가 화면에 들어오는 정도 */
               animation-range: entry 0% entry 80%; }       /* 들어오기 시작~80%까지만 재생 */
}
@keyframes grow   { from { transform: scaleX(0) } to { transform: scaleX(1) } }
@keyframes reveal { from { opacity: 0; translate: 0 16px } }
@media (prefers-reduced-motion: reduce) { .progress, .card { animation: none } }
