🧭 가맹점 계층 트리 뷰 — 포커스 이동과 선택을 가르는 키보드 규칙 내비게이션·탭

본사 › 지역 › 가맹점 › 단말기처럼 깊이가 있는 목록은 트리 뷰(role="tree", 접고 펼치는 계층 목록)로 보여준다. 핵심은 화살표 = 포커스만 이동, Enter = 이동/선택으로 두 동작을 분리하고, 트리 전체를 Tab 한 번으로 통과시키는 것.

A. 내비게이션 트리 — 화살표로 둘러보고 Enter로 이동

    현재 보기
    본사 전체

    트리에 포커스 후 ↑↓ 이동 · → 펼치기/자식으로 · ← 접기/부모로 · Home/End · * 형제 모두 펼치기 · 글자 입력 = 이름으로 점프(예: "해"). 화살표로는 오른쪽 화면이 안 바뀐다 — Enter/클릭에서만 바뀐다.

    B. 선택 트리 — 하위 전체 선택·부분 선택(mixed)·검색 자동 펼침

      Space 체크 토글. 부모를 체크하면 하위 전부, 일부만 체크되면 부모가 mixed(–). 검색하면 매칭 항목의 조상 노드가 자동으로 펼쳐지고 나머지는 숨는다. 칩은 "최상위로 묶어" 요약(강남점 2대 전체 → "강남점").

      핵심 코드 — 키보드 매핑과 accessible name

      <ul role="tree" aria-label="가맹점 계층">
  <li role="treeitem" aria-expanded="false" tabindex="0" aria-labelledby="n-seoul">
    <span class="trow"><span id="n-seoul">서울 지역</span></span>
    <ul role="group" hidden> … </ul>   <!-- 자식 -->
  </li>
</ul>
// ⚠️ aria-labelledby 없으면 treeitem 이름 = 자식 텍스트 전체("서울 지역 강남점 T-1001 …")

function onKey(e){
  const cur = e.target.closest('[role="treeitem"]');
  const items = visibleItems();            // 접힌 그룹 안의 항목은 제외
  const i = items.indexOf(cur);
  switch (e.key) {
    case 'ArrowDown': focus(items[i+1]); break;
    case 'ArrowUp':   focus(items[i-1]); break;
    case 'ArrowRight': isCollapsed(cur) ? expand(cur) : focus(firstChild(cur)); break;
    case 'ArrowLeft':  isExpanded(cur)  ? collapse(cur) : focus(parentItem(cur)); break;
    case 'Home': focus(items[0]); break;
    case 'End':  focus(items.at(-1)); break;
    case '*':    siblings(cur).forEach(expand); break;
    case 'Enter': activate(cur); break;     // 여기서만 라우팅/선택
    default: typeahead(e.key);               // 이름 첫 글자 점프
  }
}
function focus(el){ if(!el) return; prev.tabIndex = -1; el.tabIndex = 0; el.focus(); } // roving tabindex
      • roving tabindex(묶음 안에서 tabindex=0을 한 항목에만 두고 화살표로 옮기는 기법) — 트리 전체가 Tab 정지점 1개.
      • 펼침 상태는 aria-expanded, 리프 노드엔 아예 붙이지 않는다(붙이면 "접힘"으로 읽혀 자식이 있다고 오해).
      • 선택 트리는 aria-multiselectable="true" + 항목별 aria-checked(true/false/mixed).
      언제 트리가 아닌가: 깊이 2단 이하·항목 20개 미만이면 트리보다 그룹 헤더가 있는 평범한 리스트나 사이드바가 낫다. 트리 키보드 규칙은 사용자가 모르는 경우가 많아, 마우스·터치로도 전부 가능해야 한다.

      🃏 날짜별 그룹 거래 리스트 — 스티키 날짜 헤더·일별 합계·KST 경계 카드·리스트

      거래내역은 "날짜 헤더 + 그날 거래들" 묶음이 표준이 됐다. 스크롤하면 현재 날짜 헤더가 위에 붙어 있고(position: sticky — 스크롤되다 지정 위치에 닿으면 멈춰 붙는 배치), 헤더에 그날의 순합계가 있다. 결제 도메인에서 진짜 함정은 어느 시간대 기준으로 날짜를 자르냐다.

      A+B. 스티키 헤더 + 일별 합계 + 필터 · KST/UTC 묶기 비교

      KST(Asia/Seoul) 기준으로 날짜를 묶는 중.

      UTC 모드를 켜면 KST 00:00~08:59 거래(노란 배경)가 전날 그룹으로 넘어가고, 일별 합계도 정산서와 어긋난다. 서버가 UTC ISO 문자열을 주면 new Date(iso).toISOString().slice(0,10)로 자르는 코드가 바로 이 버그다.

      핵심 코드 — 시간대 고정 그룹핑과 상대 날짜 라벨

      const kstDay = new Intl.DateTimeFormat('en-CA', { timeZone: 'Asia/Seoul' }); // → "2026-10-01"
const groupKey = iso => kstDay.format(new Date(iso));   // ❌ iso.slice(0,10) / toISOString()

function dayLabel(key, todayKey){
  const diff = (Date.parse(todayKey) - Date.parse(key)) / 864e5;   // 둘 다 자정 UTC로 파싱 → 정수
  if (diff === 0) return '오늘';
  if (diff === 1) return '어제';
  return new Intl.DateTimeFormat('ko-KR', { month:'long', day:'numeric', weekday:'short', timeZone:'UTC' })
           .format(new Date(key));                        // "9월 28일 (월)"
}

      • 구조: 날짜마다 <section aria-labelledby> + <h3> — 스크린리더 사용자는 제목 단축키로 날짜 단위 점프가 가능.
      • 금액은 색만으로 구분하지 않는다: "+"/"−" 부호 + "입금/출금" 텍스트(시각적으로 숨김)를 같이 둔다.
      • 필터로 그날 거래가 0건이 되면 헤더째 숨긴다(빈 날짜 헤더는 소음). 합계도 필터 결과 기준으로 다시 계산.
      • 스티키 헤더 뒤로 내용이 비치면 가독성이 떨어지니 불투명에 가까운 배경을 준다(backdrop-filter는 보너스).
      "오늘/어제" 같은 상대 라벨은 자정이 지나면 틀려진다. 페이지를 오래 켜 두는 어드민이라면 자정에 라벨을 다시 계산하거나(setTimeout으로 다음 자정 예약), 날짜를 병기("오늘 · 10월 1일")하는 게 안전하다.

      🌀 interestfor — 호버·포커스로 여는 미리보기 카드를 HTML 속성 하나로 트렌드·개념

      <button interestfor="id">는 사용자가 요소에 관심(interest)을 보일 때 — 마우스를 올리거나, 키보드로 포커스하거나, 터치로 길게 누를 때 — 대상 팝오버를 연다. 지연 시간·마우스가 카드로 넘어가는 동안 유지·Esc 닫기처럼 JS로 매번 짜던 "호버카드" 규칙을 브라우저가 맡는다.

      거래 ID에 마우스 올리기 / Tab으로 포커스 → 요약 카드. ⓘ → 짧은 설명 툴팁
