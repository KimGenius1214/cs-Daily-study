📊 CSS-only 차트 — 막대·도넛·목표 게이지를 라이브러리 없이 데이터·테이블·차트

대시보드 숫자 몇 개를 보여주자고 차트 라이브러리(Chart.js·Recharts 등) 전체를 번들에 넣을 필요는 없다. 막대·도넛·진행률 같은 단순 비교·비율·목표 달성률은 순수 CSS로 충분하다. 핵심 도구는 세 가지 — 막대는 width %, 도넛은 conic-gradient()(원을 각도만큼 색칠하는 CSS 함수), 게이지는 진행 바. 값은 텍스트로도 함께 두어 스크린리더·색맹 사용자도 읽게 한다.

목표를 넘기면(117%) 막대 색이 초록→호박/빨강 그라데이션으로 바뀐다 — 색만으로 판단하지 않게 숫자(117%)를 항상 함께 보여준다.

막대는 로드 시 0%→목표폭으로 자라며(transition:width), 도넛은 conic-gradient의 각도만 바꿔 다시 칠한다. 셋 다 DOM 요소 하나 + CSS로 끝난다.

언제 라이브러리를 쓰나: 축·툴팁·줌·수십 개 시리즈가 필요한 분석용 차트는 Chart.js/Recharts가 맞다. 반대로 카드 위 요약 지표 하나를 보여줄 땐 CSS가 더 가볍고 빠르다(번들 0KB, 리플로우 적음). 접근성: 도넛은 role="img"+aria-label로 "승인 84%…"를 통째로 읽히고, 막대·게이지는 옆의 텍스트 값이 곧 대체 텍스트다. conic-gradient는 모든 최신 브라우저에서 동작한다(추정: 2023 이후 Baseline).

🔔 토스트 큐 시스템 — 쌓기·자동 dismiss·hover 일시정지·aria-live 피드백·상태

토스트(toast)는 화면 구석에 잠깐 떴다 사라지는 알림이다. 하나 띄우는 건 쉽지만, 여러 개가 연달아 발생할 때가 진짜다: 위로 쌓고(stack), 각자 타이머로 사라지고, 마우스를 올리면(hover) 타이머를 멈춰 읽을 시간을 주고, 스크린리더엔 aria-live로 읽히게 해야 한다. optimistic UI(낙관적 UI — 응답 전에 화면부터 바꾸는 방식)와 짝을 이뤄 "저장됨/실패" 결과 통지에 많이 쓴다.

여러 번 눌러 쌓임을 확인하고, 뜬 토스트에 마우스를 올리면 하단 진행 바(남은 시간)가 멈춘다 — 떼면 다시 흐른다. 에러 토스트는 더 오래 유지된다.

역할 구분이 핵심이다: 대부분의 토스트는 role="status"(aria-live="polite" — 읽던 걸 끊지 않고 이어 읽음), 에러·긴급은 role="alert"(assertive — 즉시 끼어들어 읽음)를 쓴다. WCAG 2.2.1(시간 조절 가능)에 따라 자동 사라짐엔 멈출 방법이 있어야 하므로 hover·focus 시 타이머를 멈춘다(느린 독자·화면 확대 사용자 배려). 색은 보조 신호일 뿐, 아이콘·제목 텍스트로 의미가 통해야 한다. 이 데모의 라이브 영역은 화면 밖에 두지 않고 실제 토스트 컨테이너 자체에 aria-live를 걸었다.

🌀 View Transitions API — 정렬·필터가 툭 바뀌지 않고 부드럽게 트렌드·개념

View Transitions API는 DOM이 바뀌는 순간을 브라우저가 스냅샷으로 이어붙여 부드럽게 전환해 주는 표준 기능이다. 리스트를 정렬·필터할 때 항목이 순간이동하듯 툭 재배치되던 걸, 각 항목이 제자리로 미끄러지게 만든다. 예전엔 Framer Motion 같은 애니메이션 라이브러리가 하던 일을 이제 document.startViewTransition() 한 줄로 시작한다.

    지원 여부 확인 중…

    정렬·필터 버튼을 눌러 보면 카드가 새 위치로 미끄러진다(지원 브라우저). 각 카드에 view-transition-name을 고유하게 주면 브라우저가 "같은 카드가 여기서 저기로 갔다"를 알고 이어붙인다. prefers-reduced-motion이 켜져 있으면 전환을 건너뛴다.

    왜 지금 뜨나: 같은 문서(SPA) 안 전환은 2025-10-14부로 Baseline("newly available") — Chrome 111+, Safari 18+, Firefox 144+에서 동작한다(WebSearch 확인). 문서 간(MPA) 전환은 아직 Chromium(Chrome 126+) 위주이고 Firefox·Safari는 미지원이라, 프로덕션에선 "지원되면 부드럽게, 아니면 즉시 반영"의 점진적 향상으로 쓴다 — 이 데모가 그 형태다(미지원 브라우저에선 애니메이션 없이 그냥 재배치). 주의: 전환 중엔 화면이 잠깐 캡처되므로 무거운 리스트에선 성능을 확인해야 한다.
