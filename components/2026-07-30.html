🧭 접히는 사이드바 내비게이션 — 아이콘 레일·활성 표시·툴팁 내비게이션·탭

사이드바 내비게이션(sidebar nav)은 대시보드형 제품의 왼쪽 기둥입니다. 요즘은 화면이 좁거나 집중이 필요할 때 아이콘만 남기고 접히는 레일(icon rail)로 줄였다가, 필요하면 라벨까지 펼치는 방식이 표준입니다. 접혔을 때는 각 항목에 툴팁을 띄워 아이콘의 뜻을 알려 줍니다. 아래 « 버튼으로 접고 펴 보고, 항목을 눌러 활성 표시를 확인하세요.

대시보드

선택된 메뉴의 본문이 여기 들어옵니다. 사이드바를 접으면 아이콘만 남고, 마우스를 올리거나 Tab으로 포커스하면 툴팁이 뜹니다.

상태: 사이드바 펼침 · 활성 메뉴 대시보드

🧩 변형들 (요즘 패턴)

  • 아이콘 레일 ↔ 확장 — 접으면 폭 64px로 아이콘만, 펴면 라벨·배지까지. 넓은 화면에선 펼침, 좁으면 접힘을 기본값으로 두는 경우가 많습니다.
  • 활성 표시(active indicator) — 현재 페이지는 배경색 + 왼쪽 세로 바 + 굵은 글씨로, 색 하나에만 기대지 않고 여러 신호를 겹칩니다.
  • 접힘 시 툴팁 — 라벨이 사라진 만큼, 아이콘의 의미를 hover·focus 툴팁으로 보완합니다(정산의 "3건 대기"처럼 배지 내용도 함께).
  • 배지(badge) — 처리할 일이 있는 메뉴에 숫자를 붙여 주의를 끕니다. 접힌 상태에선 툴팁 텍스트로 옮겨 줍니다.

💻 코드 (핵심 — 접기 토글 + 활성 표시)

toggle.addEventListener('click', () => {
  const collapsed = sb.classList.toggle('collapsed');
  // 접힘 상태를 보조기술에도 알림
  toggle.setAttribute('aria-expanded', String(!collapsed));
  toggle.setAttribute('aria-label', collapsed ? '사이드바 펼치기' : '사이드바 접기');
});

// 활성 메뉴: 색이 아니라 aria-current로 "지금 이 페이지"를 표시
links.forEach(a => a.addEventListener('click', e => {
  e.preventDefault();
  links.forEach(l => l.removeAttribute('aria-current'));
  a.setAttribute('aria-current', 'page');   // 스크린리더가 "현재 페이지"로 읽음
}));

♿ 접근성·상태 설계

  • 컨테이너는 <nav aria-label="주 메뉴">. 현재 페이지 링크에 aria-current="page" — 색뿐 아니라 의미로도 "여기"를 알립니다.
  • 접기 버튼은 aria-expanded + aria-controls로 상태를 노출하고, 라벨을 "접기/펼치기"로 갱신합니다.
  • 툴팁은 focus로도 떠야 키보드 사용자가 접힌 아이콘의 뜻을 압니다(hover 전용 금지). 여기선 :focus-visible에도 툴팁을 띄웠습니다.
  • 아이콘은 장식이라 aria-hidden 처리하고, 링크 텍스트(라벨)가 접근 이름을 담당합니다.

대시보드·결제·정산·고객 같은 상위 내비를 사이드바로 두면 화면 전환 없이 이동이 빠릅니다. 좁은 노트북·집중 모드에선 접어서 표를 넓게 쓰고, "정산 3건 대기"처럼 액션이 필요한 곳에 배지를 달아 놓치지 않게 합니다. 접힘 상태 저장은 실제 제품에선 서버·쿠키로 하되, 이 데모는 메모리에만 둡니다(스토리지 미사용).

🔗 참고: WAI-ARIA aria-current, 툴팁 패턴(focus로도 노출). 접힘 상태는 화면 폭에 따라 기본값을 다르게 두는 편이 흔합니다. 이 데모는 self-contained.

🃏 선택 가능한 리스트 — 전체선택(indeterminate)·대량 작업 바 카드·리스트

표·리스트에서 여러 항목을 골라 한 번에 처리하는 패턴입니다. 핵심은 두 가지 — 머리글의 전체 선택 체크박스가 "일부만 선택"일 때 보여 주는 중간 상태(indeterminate, 체크도 해제도 아닌 대시 표시), 그리고 하나라도 고르면 아래에서 올라오는 대량 작업 바(bulk action bar)입니다. 아래에서 몇 개 체크해 보세요.

🧩 변형들 (요즘 패턴)

  • 전체 선택 + indeterminate — 머리글 체크박스는 셋 중 하나: 모두 선택(체크)·일부 선택(대시)·선택 없음(빈칸). 일부 선택 상태를 대시로 보여 줘야 "부분 선택 중"임이 드러납니다.
  • 대량 작업 바 — 선택이 0이면 숨고, 1개 이상이면 떠오릅니다. "내보내기·삭제·해제"처럼 선택 대상에 할 수 있는 동작만 모읍니다.
  • 선택 행 강조 — 고른 행은 배경색으로 표시해, 스크롤해도 무엇을 골랐는지 보입니다.
  • 개수 라이브 표시 — "3개 선택됨"을 실시간으로 갱신해 규모를 감 잡게 합니다(삭제 전 확인용).

💻 코드 (핵심 — indeterminate + 선택 집계)

function sync(){
  const boxes = [...list.querySelectorAll('.row-cb')];
  const on = boxes.filter(b => b.checked).length;
  // 머리글 체크박스의 3가지 상태
  all.checked = on === boxes.length && on > 0;
  all.indeterminate = on > 0 && on < boxes.length;  // 일부만 → 대시 표시
  bar.classList.toggle('show', on > 0);              // 하나라도 있으면 작업 바
  count.textContent = on + '개';
}
all.addEventListener('change', () => {               // 전체 선택/해제
  list.querySelectorAll('.row-cb').forEach(b => b.checked = all.checked);
  sync();
});

♿ 접근성·상태 설계

  • 머리글 체크박스는 aria-label="전체 선택", 각 행 체크박스도 무엇을 선택하는지 라벨을 답니다(스크린리더가 "선택: 스타벅스 정산"으로 읽음).
  • indeterminate는 JS 속성입니다(el.indeterminate = true) — HTML 속성으로는 못 켭니다. 시각적 대시도 브라우저가 그려 줍니다.
  • 작업 바는 role="region" + 라벨로 묶어, 선택 후 나타나는 동작 묶음임을 알립니다.
  • 파괴적 동작(삭제)은 색·라벨로 구분하고, 실제 제품에선 취소(undo) 토스트나 확인 단계를 두는 편이 안전합니다.

🌀 Popover API + CSS Anchor Positioning — JS 없이 뜨고 위치잡는 메뉴·툴팁 트렌드·개념

떠 있는 메뉴·툴팁·팝오버를 만들 때, 예전엔 (1) 다른 요소에 가리지 않게 맨 위 레이어로 띄우기와 (2) 트리거 옆에 정확히 위치잡기 둘 다 JS·라이브러리(Floating UI 등)로 했습니다. 이제 Popover API(HTML popover 속성)가 (1)을, CSS Anchor Positioning(anchor-name/anchor())이 (2)를 플랫폼 기본 기능으로 해결합니다. 아래 버튼을 눌러/올려 보세요.

국내 카드 결제 수수료는 건당 2.9% + ₩30입니다. 정산은 D+2 영업일에 이뤄져요.

메뉴는 클릭으로 열고 Esc·바깥 클릭으로 닫힙니다(브라우저 기본 제공, JS 0줄). 툴팁 버튼은 hover·focus·click로 뜹니다.

지원 여부 확인 중…

📈 왜 지금 뜨나 / 어디에 쓰나

  • Popover API — popover 속성을 붙이면 요소가 top layer(맨 위 레이어)로 떠서 overflow:hidden·z-index 지옥을 피합니다. 가벼운 해제(light dismiss) — 바깥 클릭·Esc로 닫힘 — 를 브라우저가 공짜로 줍니다. Baseline 널리 사용 가능(Chrome 114·Safari 17.4·Firefox 125 이상, 출처 확인).
  • CSS Anchor Positioning — 트리거에 anchor-name, 팝오버에 position-anchor+anchor()를 주면 CSS만으로 트리거 기준 배치가 됩니다. 화면 밖으로 나갈 것 같으면 position-try-fallbacks: flip-block으로 자동으로 위/아래를 뒤집습니다. 2026년 Baseline 진입(Chrome 125·Safari 26·Firefox 147 계열, 출처 확인). 옛 사파리 등에선 미지원이라 폴백이 필요합니다.
  • 어디에 — 행 단위 "⋯ 더보기" 메뉴, 필드 옆 도움말 툴팁, 알림 드롭다운, 셀렉트 대체 목록 등 "떠서 트리거 옆에 붙는" 거의 모든 것.

💻 코드 (복붙용 — 선언만으로 동작)

<!-- 트리거와 팝오버를 popovertarget으로 연결. JS 불필요 -->
<button popovertarget="menu">⋯ 작업</button>
<div id="menu" popover> … 메뉴 … </div>

<style>
  /* (2) 위치잡기: 트리거를 앵커로 지정 */
  button{ anchor-name: --t; }
  #menu{
    position-anchor: --t;
    top: anchor(bottom);      /* 트리거 아래에 */
    left: anchor(left);
    margin-top: 8px;
    position-try-fallbacks: flip-block;  /* 넘치면 위로 뒤집기 */
  }
</style>

/* 폴백: anchor positioning 미지원이면 JS로 좌표 계산 */
if(!CSS.supports('anchor-name: --x')){ positionWithJS(trigger, menu); }

♿ 접근성·상태 설계

  • 메뉴 트리거엔 aria-haspopup="menu", 툴팁 트리거엔 aria-describedby로 관계를 알립니다. 팝오버가 열리면 포커스 이동·Esc 닫기를 브라우저가 처리합니다.
  • 순수 정보성 툴팁은 popover="hint"(다른 팝오버를 닫지 않고 겹쳐 뜨는 유형)로, 메뉴는 기본 popover(auto)로 구분해 씁니다.
  • 폴백 필수 — 앵커 위치잡기를 지원 안 하면 팝오버가 엉뚱한 데 뜰 수 있습니다. CSS.supports로 확인해 JS 좌표 계산으로 대체하거나, 최소한 트리거 근처에 고정 배치합니다(이 데모가 그렇게 합니다).
  • 키보드 도달성·색 대비는 일반 메뉴/툴팁 기준을 그대로 지킵니다.
