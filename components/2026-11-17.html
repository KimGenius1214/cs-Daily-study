🪟 상세 사이드 드로어 — 목록을 떠나지 않고 보고, 주소에 남기고, 닫으면 누른 줄로 돌아오기 오버레이·모달·토스트

거래 목록에서 한 건을 열 때 페이지 이동 대신 오른쪽 패널로 보여주면 필터·스크롤 위치가 그대로 남습니다. 핵심은 네 가지: 모달로 할지 비모달로 할지 고르기, ?txn=ID로 주소에 남겨 새로고침·공유·뒤로가기가 되게, 닫으면 포커스를 누른 줄로 복귀, 메모를 쓰다 닫으면 한 번 확인.

거래 목록 — "거래 ID"를 눌러 보세요 (Esc·바깥 클릭·✕로 닫기, 드로어 안 ↑↓ 버튼으로 이웃 거래 이동)

거래 ID가맹점금액상태

모달 드로어는 <dialog>.showModal()로 열어 배경 잠금·Esc·포커스 가두기를 브라우저에 맡깁니다. 분할 패널은 <aside> 영역이라 목록 클릭이 계속 되고, 내용이 바뀌면 제목으로 포커스를 옮기지 않고 조용히 갱신만 알립니다.

 
<dialog id="drawer" class="drawer" aria-labelledby="dTitle">…</dialog>

let opener = null;
function openTx(id, btn) {
  opener = btn;                                  // 닫힐 때 돌아갈 곳
  render(id);
  if (!drawer.open) drawer.showModal();          // 배경 inert·Esc·포커스 가두기 자동
  const url = new URL(location);
  url.searchParams.set('txn', id);
  history.pushState({ txn: id }, '', url);       // 뒤로가기 = 닫기
}
drawer.addEventListener('cancel', e => {         // Esc
  if (memoDirty) { e.preventDefault(); showGuard(); }
});
drawer.addEventListener('click', e => {          // ::backdrop 클릭
  if (e.target === drawer) requestClose();
});
drawer.addEventListener('close', () => {
  opener?.focus();                               // 누른 줄로 복귀
  if (new URL(location).searchParams.has('txn')) history.back();
});
addEventListener('popstate', () => {
  const id = new URL(location).searchParams.get('txn');
  id ? render(id) : drawer.close();
});

언제 무엇을: 상세를 보면서 목록을 비교해야 하면 분할 패널(넓은 화면), 하나만 집중 처리(환불·메모)면 모달 드로어. 640px 이하에선 분할 패널도 전체 폭으로 내려옵니다. 주소 동기화를 하면 새로고침 시 ?txn=을 읽어 드로어를 다시 여는 것까지 해야 완성입니다(이 데모도 로드 시 확인). 바깥 클릭 닫기는 실수 닫힘이 잦으니 입력이 있는 드로어에선 확인을 끼우세요.

🔔 파일 업로드 상태 — 고르는 순간 거르고, 진행률은 보이되 말은 아끼고, 취소·재시도는 파일마다 피드백·상태

사업자등록증·통장 사본·정산 증빙 업로드는 "올리는 중 / 완료 / 실패"만으론 부족합니다. 형식·크기는 서버로 보내기 전에 거르고, 파일마다 진행률·취소·재시도를 두고, 화면 낭독기에는 시작·완료·실패만 알리며, 업로드가 끝나기 전 제출 버튼은 왜 못 누르는지 말해 줍니다.

증빙 서류 업로드 (PDF·JPG·PNG, 파일당 5MB) — 직접 파일을 끌어 놓거나 아래 샘플 버튼으로

    파일을 1개 이상 올리면 제출할 수 있어요.

    진행률은 <progress>에 맡기고(낭독기가 필요할 때 읽음), 라이브 영역(aria-live)은 상태가 바뀔 때만 씁니다. 1%마다 알리면 낭독기가 숫자만 읽다 끝납니다.

    // fetch()는 업로드 진행률 이벤트가 없다 → XHR의 upload.onprogress
function upload(file, { onProgress, signal }) {
  return new Promise((resolve, reject) => {
    const xhr = new XMLHttpRequest();
    xhr.open('POST', '/api/documents');
    xhr.upload.onprogress = e => e.lengthComputable && onProgress(e.loaded / e.total);
    xhr.onload  = () => (xhr.status < 300 ? resolve(JSON.parse(xhr.response)) : reject(new Error(xhr.status)));
    xhr.onerror = () => reject(new Error('network'));
    signal.addEventListener('abort', () => { xhr.abort(); reject(new DOMException('취소', 'AbortError')); });
    const fd = new FormData(); fd.append('file', file);
    xhr.send(fd);
  });
}

// 보내기 전 검증 — accept 속성은 '선택 창 필터'일 뿐, 끌어 놓기는 그대로 통과한다
const OK = ['application/pdf', 'image/jpeg', 'image/png'];
const reason = f => !OK.includes(f.type) ? '지원하지 않는 형식'
                 : f.size > 5 * 1024 * 1024 ? `5MB 초과 (${(f.size/1048576).toFixed(1)}MB)` : null;

    상태 어휘를 고정하세요: 대기 → 올리는 중 n% → 완료, 갈래로 거절(보내지도 않음, 이유 표시·재시도 없음)과 실패(보냈다 끊김, 재시도 있음). 거절과 실패를 같은 빨간 "오류"로 뭉치면 사용자는 같은 파일을 계속 다시 올립니다. 업로드 중 페이지를 떠나면 beforeunload로 한 번 묻고, 클라이언트 검증은 편의일 뿐 서버도 다시 검사해야 합니다(파일 확장자·MIME은 바꿀 수 있음).

    🌀 inert — 보이지만 지금은 못 만지는 영역을 포커스·클릭·낭독기에서 한 번에 빼기 트렌드·개념

    inert는 HTML 전역 속성입니다. 붙이면 그 요소와 모든 자손이 Tab 포커스·클릭·텍스트 선택·접근성 트리에서 빠집니다. 예전엔 같은 효과를 위해 tabindex=-1을 하나하나 달고, aria-hidden을 붙이고, 포인터 이벤트를 막았습니다. 2023년부터 주요 브라우저가 모두 지원합니다(Baseline).

    주의 네 가지. ① dialog.showModal()은 바깥을 이미 inert로 만드니 모달에 또 달 필요가 없습니다 — inert는 dialog가 아닌 자작 오버레이·드로어·잠금 화면에 씁니다. ② 조상이 inert면 자손이 inert=false여도 못 빠져나옵니다. ③ 보기엔 그대로라 반투명·커서 등 시각 단서를 따로 줘야 합니다. ④ aria-hidden과 달리 클릭·포커스까지 막으니, "읽기만 숨기기"가 목적이면 inert가 아니라 aria-hidden입니다.
