📊 그룹 소계·합계 테이블 데이터·테이블·차트

정산·회계 테이블에서 사람이 진짜 보는 건 개별 행이 아니라 “이 묶음 얼마”와 “전부 합쳐 얼마”다. 행을 그룹으로 접고, 그룹마다 소계를 달고, 총합계는 화면 아래에 붙박이로 두면 스크롤을 아무리 내려도 합계가 시야에서 사라지지 않는다.

그룹 기준
2026-09-10 결제 거래 내역. 그룹별 소계와 총합계 포함.
거래 ID 시각 수단 상태 수수료
총합계

그룹 헤더를 클릭(또는 Enter)하면 접힌다. 접어도 그룹 헤더 오른쪽의 소계와 아래 총합계는 그대로 남는다 — “안 보이는 행도 합계에는 들어있다”가 눈으로 확인돼야 신뢰가 생긴다.

표를 조작하면 여기에 상태가 표시됩니다.

이 표에 들어간 설계 결정 4가지

  • 숫자는 오른쪽 정렬 + 고정폭 숫자. font-variant-numeric: tabular-nums는 “0~9의 폭을 전부 똑같이 맞춰라”는 CSS 한 줄이다. 이게 없으면 1과 8의 폭이 달라 자릿수 줄이 어긋나 보인다.
  • 음수는 색만으로 표시하지 않는다. 빨강 + − 부호를 같이 쓴다. 색각 이상 사용자나 흑백 출력에서도 읽혀야 하기 때문.
  • 총합계는 <tfoot> + position: sticky; bottom: 0. 스크롤 컨테이너 안에서 바닥에 붙는다. 마크업상으로도 tfoot이라 스크린리더가 “표의 합계 영역”으로 읽는다.
  • 정렬은 그룹 안에서만. 그룹 경계를 넘어 섞어 정렬하면 소계가 의미를 잃는다. 그룹 순서 자체는 소계 크기순으로 정렬한다.

💻 핵심 코드

/* 1) 자릿수가 맞는 금액 열 */
td.n, th.n {
  text-align: right;
  font-variant-numeric: tabular-nums;   /* 숫자 폭 통일 */
}

/* 2) 스크롤해도 바닥에 붙는 총합계 */
.tablescroll { max-height: 380px; overflow: auto; }
tfoot.total td {
  position: sticky;
  bottom: 0;                 /* 헤더는 top:0, 합계는 bottom:0 */
  z-index: 3;
  background: var(--surface); /* 배경 필수 — 없으면 행이 비쳐 보인다 */
  border-top: 2px solid var(--border);
}

/* 3) 그룹 접기: 버튼에 aria-expanded, 데이터 행에는 hidden */
<tr class="grouprow">
  <td colspan="7">
    <button aria-expanded="true" aria-controls="g-store-a">스토어A …</button>
  </td>
</tr>

♿ 접근성·상태 설계

  • aria-sort는 정렬된 열의 <th>에 ascending/descending/none으로 붙인다. 한 표에 오름·내림이 동시에 켜지지 않게 나머지는 반드시 none으로 되돌린다.
  • 그룹 토글은 <button aria-expanded>로. 행 전체를 클릭 가능하게 만들되 실제 포커스 대상은 버튼 하나여야 키보드 탭 순서가 깔끔하다.
  • 정렬·접기 결과는 role="status" 영역에 한 줄로 알린다(“정산액 내림차순, 10건 중 7건 표시”). 시각적 변화만으로는 스크린리더 사용자가 눈치채지 못한다.
  • 가로 스크롤이 생기는 표는 스크롤 컨테이너에 tabindex="0"을 줘서 키보드로도 좌우 스크롤이 되게 한다(이 데모에도 적용).
함정. position: sticky는 border-collapse: collapse인 표에서 브라우저마다 경계선이 사라지거나 겹쳐 보이는 사례가 알려져 있다. 그래서 이 데모는 border-collapse: separate; border-spacing: 0에 셀별 border-bottom을 직접 그렸다.

🔔 부분 성공 결과 리포트 피드백·상태(로딩·빈상태·에러)

12건을 일괄 처리했는데 9건 성공, 2건 실패, 1건 건너뜀. 이때 “처리 완료 ✅” 토스트 하나를 띄우면 거짓말이 되고, “처리 실패 ❌”를 띄우면 성공한 9건이 사라진다. 부분 성공은 제3의 상태이고, 별도의 결과 화면이 필요하다.

정산 보류 건 일괄 승인 대기 중
0 / 12 처리 중…

진행 중에도 이미 성공한 건수를 같이 세어 보여준다. 중간에 창을 닫아도 “몇 건은 이미 처리됐다”를 알 수 있어야 한다.

⚠️ 일부만 처리됐습니다
성공 0건 실패 0건 건너뜀 0건

    실패 항목엔 사유와 다음 행동이 같이 있어야 한다. “오류가 발생했습니다”만 있으면 사용자는 고객센터에 전화하는 것 말고 할 수 있는 게 없다.

    ‘12건 일괄 승인’을 눌러보세요.

    🧩 변형들 — 결과를 어디에 보여줄까

    방식언제 쓰나주의
    인라인 리포트
    (이 데모)    		 처리 건수 5~50건, 사용자가 그 자리에서 실패를 고칠 수 있을 때 목록이 길어지면 스크롤 영역으로 가두고 실패를 맨 위로 올린다
    토스트 + 상세 링크 전부 성공이 대부분이고 실패가 예외적일 때 토스트 문구에 반드시 실패 건수를 넣는다. “완료”만 쓰면 안 된다
    별도 결과 페이지 수백~수천 건 배치, 결과를 나중에 다시 봐야 할 때 작업 ID로 URL을 만들어 새로고침·공유가 되게 한다. CSV 내보내기 제공
    전부 아니면 전무
    (원자적 처리)    		 부분 반영이 회계상 말이 안 되는 경우(예: 하나의 정산 배치) UI 문제가 아니라 서버 트랜잭션 설계 문제다. 먼저 백엔드와 합의할 것

    💻 상태 판정 로직 (복붙용)

    type BulkOutcome = 'all' | 'partial' | 'none';

function outcomeOf(r: { ok: number; fail: number; skip: number }): BulkOutcome {
  if (r.fail === 0 && r.ok > 0) return 'all';
  if (r.ok === 0) return 'none';
  return 'partial';            // ← 이 분기를 빼먹는 게 가장 흔한 버그
}

const TONE = {
  all:     { icon: '✅', tone: 'success', title: '모두 처리했습니다' },
  partial: { icon: '⚠️', tone: 'warning', title: '일부만 처리됐습니다' },
  none:    { icon: '❌', tone: 'error',   title: '처리하지 못했습니다' },
} as const;

    ♿ 접근성·상태 설계

    • 진행률은 role="progressbar" + aria-valuenow/min/max. 값이 바뀔 때마다 갱신한다. 끝나면 progressbar를 없애고 결과 영역으로 포커스를 옮길지 결정한다(이 데모는 포커스를 옮기지 않고 role="status"로 알린다 — 사용자가 다른 걸 하고 있을 수 있어서).
    • 결과 배너는 role="status"(= aria-live="polite", 하던 말을 끊지 않고 이어서 읽음). 치명적 오류만 role="alert"(즉시 끊고 읽음)로 올린다.
    • 성공/실패를 아이콘 색으로만 구분하지 않는다. ✅/⚠️ 기호 + “성공”/“실패” 텍스트를 함께 둔다.
    • 재시도 버튼은 실패가 0건이면 disabled가 아니라 아예 감춘다. 눌러도 아무 일 없는 버튼은 혼란만 준다.

    🧠 paysable 적용 포인트

    • 정산 보류 해제, 대량 환불, 가맹점 일괄 등록 — 결제 도메인의 일괄 작업은 부분 성공이 기본값이다. PG 응답이 건별로 오기 때문.
    • 실패 사유는 반드시 사용자 언어로 매핑한다. PG_TIMEOUT → “PG사 응답이 늦어 처리되지 않았습니다. 재시도해 주세요.” 코드를 그대로 노출하되, 지원팀 문의용으로 작게 병기하는 게 좋다.
    • 재시도는 멱등키(idempotency key)가 있어야 안전하다 — 같은 키로 두 번 요청해도 결제가 두 번 일어나지 않게 하는 서버 장치. 이게 없으면 “실패 건만 재시도” 버튼은 이중 승인 사고로 이어질 수 있다.

    🌀 CSS @property 트렌드·개념

    CSS 변수(--brand 같은 것)는 원래 브라우저 입장에서 그냥 문자열이다. 그래서 --gauge: 0 → --gauge: 74로 바꿔도 “0에서 74로 서서히”가 안 되고 툭 바뀐다. @property는 변수에 타입을 등록해서 “이건 숫자야 / 각도야 / 색이야”를 알려준다. 그 순간부터 transition과 @keyframes가 그 변수에 먹기 시작한다.

    (A) 도넛 게이지 · <number>
    0
    (B) 회전 그라데이션 테두리 · <angle>
    프리미엄 플랜 마우스를 올리거나 Tab으로 포커스해 보세요.
    각도 자체를 보간하므로 회전용 wrapper 요소가 필요 없다
    (C) 숫자 카운트업 · <integer>
    건
    0건
    지원 여부 확인 중…

    (C)의 숫자는 JavaScript 타이머가 아니라 counter-reset: c var(--count) + content: counter(c)로 그린다. 즉 CSS transition이 정수를 보간하고, ::after가 그 값을 문자로 찍는다.

    📈 왜 지금 뜨나 / 어디에 쓰나

    • web.dev 블로그에 따르면 @property는 2024년 7월 9일 Baseline “newly available”이 됐다. Firefox 128에서 CSS.registerProperty()와 CSSPropertyRule이 기본 활성화되면서 마지막 조각이 맞춰졌다. (“Baseline newly available” = 주요 브라우저 최신 버전에 모두 들어왔다는 뜻. 구형 브라우저까지 안전한 “widely available”과는 다르다.)
    • 그동안 “그라데이션을 애니메이션하려면 가짜 요소를 겹쳐 opacity를 교차”, “숫자를 세려면 requestAnimationFrame” 같은 우회가 표준이었다. 이제 둘 다 CSS 선언 몇 줄로 대체된다.
    • 덤으로 타입 검증이 생긴다. syntax:"<color>"로 등록한 변수에 --x: 12px를 넣으면 그 선언이 무시되고 initial-value가 쓰인다. 변수 오타가 조용히 레이아웃을 깨뜨리던 문제를 줄여준다.
    • inherits 지정이 필수다. false면 자식으로 안 흘러내려서, 컴포넌트마다 독립적인 값을 갖게 된다(오늘 데모 3개 전부 inherits:false).

    💻 코드 (복붙용)

    /* 1) 등록 — 이 세 줄이 핵심 */
@property --gauge {
  syntax: "<number>";   /* 타입: number / integer / angle / color / length / percentage … */
  inherits: false;       /* 필수. 자식에게 상속시킬지 */
  initial-value: 0;      /* 필수(syntax가 '*'가 아닌 경우) */
}

/* 2) 이제 transition이 먹는다 */
.donut {
  --gauge: 0;
  background: conic-gradient(var(--brand) calc(var(--gauge) * 1%), #eee 0);
  transition: --gauge .9s cubic-bezier(.22,.8,.28,1);
}
.donut.is-full { --gauge: 96; }

/* 3) 숫자 카운트업 — JS 타이머 없이 */
@property --count { syntax: "<integer>"; inherits: false; initial-value: 0; }
.counter {
  --count: 0;
  transition: --count 1.4s ease-out;
  counter-reset: c var(--count);
}
.counter::after { content: counter(c); }

    ♿ 접근성·주의사항

    • ::after로 찍은 숫자는 보조기기에 불안정하게 읽힌다. 그래서 이 데모는 카운터를 aria-hidden="true"로 감추고, 실제 값은 별도의 role="status" 텍스트로 알린다.
    • 도넛 게이지는 그림이므로 role="img" + aria-label="한도 소진률 74퍼센트"를 값이 바뀔 때마다 갱신한다.
    • prefers-reduced-motion: reduce(사용자가 OS에서 “동작 줄이기”를 켠 상태)일 땐 transition을 꺼서 최종값으로 즉시 보여준다. 값 자체는 그대로 전달되므로 정보 손실이 없다.
    • 등록된 커스텀 속성은 애니메이션 대상이라 매 프레임 다시 그린다. 배경 그라데이션 전체를 큰 영역에서 60fps로 보간하면 비용이 든다 — 작은 요소·짧은 시간에 쓰는 게 안전하다.

    🧠 paysable 적용 포인트

    • 대시보드의 한도 소진 게이지·정산 진행률 도넛: 차트 라이브러리를 얹지 않고 conic-gradient + @property로 끝난다. 번들이 늘지 않는다.
    • 결제 완료 화면의 금액 카운트업: JS 애니메이션 루프를 지우고 CSS로 옮기면 리렌더와 무관하게 돌아간다.
    • Next.js에서는 @property 블록을 전역 CSS(예: app/globals.css)에 두는 편이 안전하다. CSS Modules 안에서도 동작하지만 등록은 문서 전역 스코프라 파일 간 이름 충돌을 조심해야 한다.
    • 미지원 브라우저에서는 transition만 무시되고 최종 값은 정상 적용된다. 즉 자연스러운 점진적 향상(progressive enhancement)이라 폴백 코드를 따로 안 짜도 된다.
