🪟 알림 센터 — 벨 배지·읽음/안읽음·그룹·빈 상태 인박스 오버레이·모달·토스트

알림 센터(notification center)는 벨 아이콘을 눌러 여는 쌓이는 알림 목록입니다. 잠깐 떴다 사라지는 토스트(toast)와 달리, 놓친 알림을 나중에 다시 확인하는 영구 보관함(inbox)이라는 점이 다릅니다. 아래 데모는 안읽음 배지, 날짜 그룹, 개별/전체 읽음 처리, 다 읽으면 배지 사라짐, 비면 빈 상태를 담았고, 패널은 Esc·바깥 클릭으로 닫힙니다.

    🧩 변형들 (요즘 패턴)

    • 안읽음 배지(unread badge) — 벨 위 숫자로 "몇 개 놓쳤나"를 한눈에. 0이 되면 배지를 숨겨 시선을 안 뺏습니다.
    • 읽음/안읽음 구분 — 안읽은 항목은 배경·점(dot)으로 강조하고, 열어 보면 자동으로 읽음 처리합니다.
    • 날짜·유형 그룹 — "오늘 / 지난 7일"처럼 묶어 스캔을 돕습니다(결제·시스템·경고 유형 아이콘 색 구분).
    • 빈 상태(empty state) — 다 읽거나 없을 때 빈 화면 대신 "새 알림이 없어요" 안내로 마무리감을 줍니다.

    💻 코드 (핵심 — 열기·읽음·배지 동기화)

    function openPanel(){
  panel.classList.add('open');
  bell.setAttribute('aria-expanded','true');
  panel.querySelector('.nc-item')?.focus();   // 첫 항목으로 포커스
}
function markRead(id){
  const n = items.find(i => i.id === id);
  if(n) n.read = true;
  syncBadge();                                 // 배지 다시 계산
}
function syncBadge(){
  const unread = items.filter(i => !i.read).length;
  badge.textContent = unread;
  badge.classList.toggle('zero', unread === 0); // 0이면 숨김
}
// 바깥 클릭·Esc로 닫기
document.addEventListener('click', e => {
  if(open && !panel.contains(e.target) && e.target !== bell) closePanel();
});
document.addEventListener('keydown', e => { if(e.key === 'Escape') closePanel(); });

    ♿ 접근성·상태 설계

    • 벨에 aria-haspopup·aria-expanded·aria-controls로 "여닫는 팝업"임을 알립니다.
    • 목록은 aria-live="polite"로, 새 알림·읽음 변화를 스크린리더가 조용히 읽습니다.
    • 토스트가 아니라 비모달(non-modal) 패널이라 aria-modal="false" — 뒤 배경을 잠그지 않고 Esc/바깥 클릭으로 닫습니다.
    • 안읽음을 색만이 아니라 점(dot)·굵기로도 구분해 색각 이상에서도 알 수 있게 합니다.

    🧠 paysable 적용 포인트

    결제 승인·정산 완료·이상거래 경고·정산 실패처럼 "지나가면 안 되는" 이벤트는 토스트로 잠깐 알리고 알림 센터에 남겨 두는 이중 구조가 안전합니다. 유형별(결제/시스템/경고) 아이콘 색을 나누면, 운영자가 급한 경고를 먼저 집어냅니다. 실제 서비스는 안읽음 수를 서버와 동기화하고, 오래된 알림은 페이지네이션/무한스크롤로 나눠 부릅니다.

    🔗 참고: 토스트(휘발) ↔ 알림 센터(보관)는 역할이 다릅니다. WAI-ARIA "Menu Button / Dialog(non-modal)" 패턴 참고. 이 데모는 외부 라이브러리 없이 self-contained.

    🔔 비동기 4상태 뷰 — 로딩·성공·빈·에러를 한 자리에서 전환하고 재시도 피드백·상태(로딩·빈상태·에러)

    데이터를 불러오는 화면은 사실 네 가지 상태를 가집니다: 로딩(loading) → 성공(데이터 있음) · 빈 상태(empty) · 에러(error). 흔한 실수는 로딩·에러를 대충 처리하고 "데이터 있음"만 예쁘게 만드는 것입니다. 아래 데모에서 상태를 직접 바꿔 보세요. 로딩은 스켈레톤(skeleton, 내용 자리를 회색 뼈대로 미리 잡아 두는 것)으로, 에러는 재시도 버튼과 함께 보여 줍니다.

    🧩 변형들 (요즘 패턴)

    • 스켈레톤 우선 — 빈 화면·큰 스피너 대신, 실제 목록과 같은 뼈대를 깔아 "곧 여기 뜬다"를 예고하면 체감 대기가 짧아집니다.
    • 빈 상태 ≠ 에러 — "데이터가 0개"와 "불러오기 실패"는 전혀 다릅니다. 빈 상태는 다음 행동(첫 결제 만들기)을 제안하고, 에러는 재시도를 줍니다.
    • 부분 실패 구분 — 전체 실패와 "일부만 실패"는 다르게. 목록 일부만 못 불러오면 그 행만 재시도하게 하는 편이 낫습니다.
    • 낙관적 갱신은 신중히 — 결제 확정처럼 되돌리기 어려운 건 성공을 미리 보여주지 말고 서버 확정 후 표시합니다.

    💻 코드 (핵심 — 상태 머신으로 렌더)

    // UI를 4개 상태 중 하나로만 그린다 (한 번에 하나)
async function load(){
  render('loading');                       // aria-busy=true
  try{
    const rows = await fetchTransactions();
    render(rows.length ? 'success' : 'empty');   // 0개면 빈 상태
  }catch(e){
    render('error');                        // 실패 → 재시도 UI
  }
}
function render(state){
  panel.setAttribute('aria-busy', state === 'loading');
  views.forEach(v => v.classList.toggle('on', v.dataset.view === state));
}
retryBtn.addEventListener('click', load);   // 에러에서 다시

    ♿ 접근성·상태 설계

    • 로딩 중엔 컨테이너에 aria-busy="true"를 걸어 보조기기가 "작업 중"임을 알게 합니다.
    • 상태 영역을 aria-live="polite"로 감싸 로딩→성공/에러 전환을 스크린리더가 읽습니다.
    • 에러 문구는 원인과 다음 행동을 담고("다시 시도"), 재시도는 실제 <button>이라 키보드로 눌립니다.
    • 스켈레톤 애니메이션은 prefers-reduced-motion(움직임 최소화 선호)에서 멈춥니다.

    🧠 paysable 적용 포인트

    거래 내역·정산 목록·대시보드처럼 데이터를 불러오는 모든 화면의 공통 뼈대로 쓰면 좋습니다. 특히 결제 도메인에선 에러 상태의 품질이 신뢰를 좌우합니다 — "불러오지 못했어요 + 다시 시도"가 흰 화면보다 훨씬 안심됩니다. 네 상태를 한 컴포넌트(예: <AsyncBoundary>)로 표준화하면 화면마다 로딩·에러를 다시 짜지 않아도 됩니다.

    🔗 참고: React라면 Suspense + Error Boundary가 로딩/에러 상태의 표준 뼈대입니다. 스켈레톤은 레이아웃 이동(CLS)을 줄이는 부수효과도 있습니다(뼈대가 실제 크기를 미리 차지).

    🌀 inert 속성 — 화면 한 덩어리를 통째로 "만질 수 없게" 만들기 트렌드·개념

    inert는 어떤 요소와 그 안쪽 전체를 클릭·포커스·탭 이동·스크린리더 탐색에서 통째로 제외하는 HTML 속성입니다(2023년 표준화, 2025년부터 모든 최신 브라우저 지원 — Baseline 안정). 모달을 띄웠는데 Tab이 뒤 배경으로 새는 포커스 누수를 disabled 없이 한 방에 막습니다. 아래에서 토글해, 뒤 폼에 Tab·클릭이 정말 안 먹는지 확인해 보세요.

    테스트용 뒤 배경 입력: 지금은 포커스 가능

    📈 왜 지금 뜨나 / 어디에 쓰나

    • 포커스 트랩의 반쪽 — 모달을 열면 뒤 배경 컨테이너에 inert를 걸어, 탭이 뒤로 새지 않게 합니다(WCAG 포커스 순서 요건 충족).
    • disabled 남발 대신 — 폼 전체를 비활성화할 때 입력마다 disabled를 붙이는 대신, 부모에 inert 한 줄이면 안쪽 전부가 잠깁니다(값은 그대로 제출됨).
    • 로딩·전환 구간 — 저장 중 화면을 잠깐 못 만지게 하거나, 슬라이드 전환 중 화면 밖 패널을 접근 대상에서 빼는 데 씁니다.
    • <dialog>의 showModal()은 이걸 자동으로 해 줍니다. 직접 만든 오버레이엔 inert를 손수 걸어야 합니다.

    💻 코드 (복붙용)

    const overlay = document.getElementById('confirm');
const bg      = document.getElementById('appBg');

function openConfirm(){
  overlay.classList.add('show');
  bg.inert = true;                 // 뒤 배경 전체를 비활성 (탭·클릭·리더 제외)
  overlay.querySelector('button').focus();
}
function closeConfirm(){
  overlay.classList.remove('show');
  bg.inert = false;                // 되살리기
}

/* CSS로 '비활성처럼 보이게' 시각 힌트도 함께 */
.in-bg[inert]{ filter:grayscale(.4) blur(1px); opacity:.55; }

    ♿ 접근성·상태 설계

    • inert는 시각 표시를 자동으로 주지 않습니다 — [inert] 선택자로 흐리게 처리해 "지금 못 만진다"를 눈으로도 알려야 합니다.
    • 안쪽 요소는 접근성 트리에서 사라지므로, 스크린리더 사용자도 실수로 뒤 배경을 읽지 않습니다.
    • 모달을 열 때 배경 inert · 닫을 때 해제를 짝으로 관리하고, 닫은 뒤 포커스를 열었던 버튼으로 되돌립니다.
    • 주의: inert가 걸린 영역 안에 포커스가 남아 있으면 안 됩니다 — 열기 직전 포커스를 오버레이로 옮기세요.

    🧠 paysable 적용 포인트

    결제 확인 오버레이·바텀시트·저장 중 로딩처럼 "지금은 뒤를 만지면 안 되는" 순간에 씁니다. 특히 결제 더블탭·중복 제출을 막을 때, 처리 중 화면을 inert로 잠그면 disabled를 버튼마다 다는 것보다 안전하고 간단합니다. 다만 inert는 시각·상호작용 차단일 뿐 보안 경계가 아니므로, 서버 측 중복 방지(멱등키 등)는 별도로 둡니다.

    🔗 참고: MDN inert(HTML global attribute), web.dev "The inert attribute". Baseline: 2023 신규 → 2025년 광범위 지원(96%+). 이 데모는 self-contained.
