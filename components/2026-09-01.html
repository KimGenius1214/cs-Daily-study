💻 코드 — 슬라이드오버의 뼈대

<dialog class="sheet" id="sheet" aria-labelledby="t">…</dialog>

/* 오른쪽에 붙이고, 열릴 때 밀려 들어오게 */
dialog.sheet{
  margin:0 0 0 auto; height:100dvh; width:min(420px,90%);
  transform:translateX(100%); opacity:0;
  /* display 는 원래 애니메이션이 안 된다. allow-discrete 로 전환 대상에 포함시킨다 */
  transition:transform .26s ease, opacity .26s ease,
             overlay .26s allow-discrete, display .26s allow-discrete;
}
dialog.sheet[open]{ transform:translateX(0); opacity:1 }
/* @starting-style = "열리기 직전의 시작값". 없으면 첫 프레임부터 제자리라 전환이 안 보인다 */
@starting-style{ dialog.sheet[open]{ transform:translateX(100%); opacity:0 } }
@media (prefers-reduced-motion:reduce){ dialog.sheet{ transition-duration:.01ms } }

// 열기: showModal() 이면 배경 inert·Esc 닫기·포커스 복귀가 전부 공짜
openBtn.addEventListener('click', () => sheet.showModal());
// 취소(Esc·백드롭)와 확정 종료를 구분하고 싶으면 close(value) 로 값을 넘긴다
sheet.addEventListener('close', () => console.log(sheet.returnValue));

♿ 접근성·상태 설계

  • 모달이면 showModal() — 배경 inert, Esc 닫기, 포커스 가두기, 포커스 복귀가 브라우저 기본 동작입니다. 손으로 만든 포커스 트랩보다 안전합니다.
  • 비모달이면 직접 — 사이드 내비, 오프캔버스처럼 showModal()을 안 쓰는 패널은 배경에 inert를 직접 걸고 Esc 핸들러도 직접 답니다.
  • 제목 연결 — aria-labelledby로 패널 제목을 가리켜, 열렸을 때 스크린리더가 "무슨 패널인지" 읽게 합니다.
  • inert 영역은 눈에도 보이게 — 배경을 흐리거나 어둡게 해 "지금 못 만진다"를 시각적으로도 알립니다.
  • 모션 감속 존중 — prefers-reduced-motion(사용자 OS의 "동작 줄이기" 설정)일 때 슬라이드 전환을 사실상 끕니다.
  • 모바일 높이 — 100vh 대신 100dvh를 써야 주소창이 접힐 때 시트 바닥이 잘리지 않습니다.
브라우저 지원: <dialog>·::backdrop·inert는 주요 엔진에 모두 구현돼 있습니다. @starting-style/allow-discrete는 이보다 늦게 들어온 기능이라, 미지원 브라우저에서는 전환 없이 즉시 나타나는 형태로 자연스럽게 낮아집니다(기능은 그대로 동작).
📌 데모 편의를 위해 이 페이지의 시트는 position:absolute로 스테이지 박스 안에 가뒀습니다. 실제 서비스에서는 위치 지정을 빼면 화면 전체 오른쪽에 붙습니다.

🔔 장기 작업 진행률 피드백·상태

3초 넘게 걸리는 작업(정산 파일 생성, 대량 업로드)에 스피너 하나만 돌리면 사용자는 멈춘 줄 압니다. 남은 시간을 알 수 있으면 결정형, 모르면 비결정형, 오래 걸리면 백그라운드로 보내기 — 세 가지를 비교합니다.

변형 1 — 비결정형 vs 결정형

비결정형 (indeterminate)대기

서버가 얼마나 걸릴지 못 알려줄 때. "일하고 있다"만 전합니다. 대신 지금 무슨 단계인지 글로 같이 알려야 불안하지 않습니다.

결정형 (determinate)0%

예상 남은 시간 —

전체 건수를 아는 작업(1,240건 중 380건 처리)이라면 반드시 결정형으로. 백분율보다 "380 / 1,240건" 같은 실제 단위가 더 잘 읽힙니다.

⚠️ 결정형인 척하는 가짜 진행바(시간만 보고 90%까지 채우고 멈춰 있는 것)는 신뢰를 깎습니다. 실제 진행을 모르면 비결정형이 정직합니다.

변형 2 — 다단계 진행과 단계별 실패·재시도

8월 정산 파일 생성0%
  • 거래 내역 수집
  • 금액 검증
  • 수수료 집계
  • 파일 만들기

전체 진행률 하나만 두면 어디서 오래 걸리는지 알 수 없습니다. 단계를 쪼개면 실패 지점이 특정되고, 처음부터가 아니라 그 단계부터 재시도할 수 있습니다. 상태 변화는 role="status" 영역으로 화면 낭독기에도 전달합니다.

변형 3 — 백그라운드 작업 트레이

정산 관리

파일 생성이 오래 걸립니다. 기다리는 동안 다른 일을 하게 두는 편이 낫습니다.

8월 정산 파일

준비 중…

작업을 화면 한 구석으로 밀어 두고 페이지 이동을 막지 않습니다. 끝나면 트레이에서 결과(내려받기)를 바로 집을 수 있어야 하고, 완료 알림은 aria-live로도 전달합니다. 30초 이상 걸리는 작업의 기본형입니다.

💻 코드 — 진행바의 접근성 최소 구성

<!-- 방법 A: 네이티브. value 를 빼면 자동으로 비결정형이 된다 -->
<progress id="p" max="100" value="38" aria-labelledby="jobTitle"></progress>
<progress max="100" aria-label="처리 중"></progress>  <!-- value 없음 = 비결정형 -->

<!-- 방법 B: 직접 그릴 때. 세 값이 세트다 -->
<div role="progressbar" aria-label="정산 파일 생성"
     aria-valuemin="0" aria-valuemax="100" aria-valuenow="38"
     aria-valuetext="1,240건 중 380건"><i style="width:38%"></i></div>

// 비결정형으로 바꿀 땐 aria-valuenow 를 지운다 (0 으로 두면 "0%"로 읽힌다)
bar.removeAttribute('aria-valuenow');

// 진행 텍스트는 status 영역에 — 매 프레임이 아니라 '의미 있는 변화'에만 갱신
// (1%마다 갱신하면 스크린리더가 쉴 새 없이 떠든다)
if (step !== lastStep) live.textContent = `${step} 단계 시작`;

♿ 접근성·상태 설계

  • 1초 미만은 아무것도 띄우지 않기(깜빡임이 더 거슬립니다). 1~3초는 스피너·스켈레톤, 3초 이상은 진행률, 30초 이상은 백그라운드 트레이 — 대략의 갈림길입니다.
  • aria-valuetext — 백분율 대신 "1,240건 중 380건"처럼 사람 말로 읽히게 합니다.
  • 낭독 폭주 막기 — aria-live 영역은 퍼센트마다가 아니라 단계가 바뀔 때만 갱신합니다.
  • 진행률은 절대 뒤로 가지 않게 — 재계산으로 62%→41%가 되면 신뢰가 무너집니다. 최댓값을 유지하거나 비결정형으로 전환합니다.
  • 중단권 — 오래 걸리는 작업엔 취소 버튼을 둡니다. 취소가 서버에서 불가능하면 "화면에서만 숨김"인지 명확히 씁니다.
  • prefers-reduced-motion일 때 비결정형 막대의 왕복 애니메이션을 크게 늦춥니다.
📌 이 데모의 진행률은 전부 가짜 타이머입니다. 실제로는 서버가 주는 처리 건수/총 건수로 계산해야 하며, 그 값이 없으면 결정형을 흉내 내지 마세요.

🌀 light-dark()와 color-scheme 트렌드·개념

다크 모드를 만들 때 색 변수를 두 벌 선언하고 prefers-color-scheme 미디어 쿼리로 갈아 끼우는 게 오랜 관행이었습니다. light-dark()는 그 두 벌을 한 줄 안에 넣습니다.

📈 왜 지금 뜨나 / 어디에 쓰나

  • light-dark(밝을때색, 어두울때색)는 계산된 color-scheme 값을 보고 둘 중 하나를 고릅니다. 미디어 쿼리를 보지 않습니다 — 이게 핵심 차이입니다.
  • color-scheme은 상속되는 CSS 속성이라, 어떤 요소에 color-scheme:dark를 주면 그 안쪽만 다크가 됩니다. "이 카드만 항상 어둡게" 같은 부분 테마가 쉬워집니다.
  • 같은 속성이 네이티브 위젯(체크박스, 셀렉트, 스크롤바, 폼 자동완성 배경)의 기본 색까지 바꿔 줍니다. 그동안 다크 모드에서 가장 안 예뻤던 부분입니다.
  • MDN 기준으로 2024년 5월 주요 엔진에 모두 들어왔고, Baseline 표기로는 "신규 사용 가능(Newly available)" 단계입니다. 구형 브라우저 비중이 있는 서비스라면 폴백(대체값)을 함께 두는 게 안전합니다.

변형 2 — 코드량 비교

지금까지 — 변수 두 벌 + 미디어 쿼리
:root{
  --bg:#ffffff;
  --text:#14181f;
  --card:#f6f7f9;
  --accent:#4f46e5;
}
@media (prefers-color-scheme: dark){
  :root{
    --bg:#10151d;
    --text:#e7ebf2;
    --card:#1b2230;
    --accent:#a5a6ff;
  }
}
/* "이 카드만 항상 어둡게"를 하려면
   변수를 또 한 벌 덮어써야 한다 */
.card{ background:var(--card); color:var(--text) }
light-dark() — 한 벌로
:root{
  /* 이 선언이 있어야 light-dark() 가 동작한다 */
  color-scheme: light dark;

  --bg:     light-dark(#ffffff, #10151d);
  --text:   light-dark(#14181f, #e7ebf2);
  --card:   light-dark(#f6f7f9, #1b2230);
  --accent: light-dark(#4f46e5, #a5a6ff);
}
/* 부분 테마: 이 한 줄이면 안쪽 전체가 다크 */
.invoice{ color-scheme: dark }

.card{ background:var(--card); color:var(--text) }

💻 코드 — 사용자 선택(라이트/다크/시스템) 붙이기

/* 1) 기본은 시스템 설정을 따른다 */
:root{ color-scheme: light dark }

/* 2) 사용자가 고르면 루트의 color-scheme 만 덮어쓴다.
      색 변수는 건드리지 않는다 — light-dark() 가 알아서 갈아 낀다 */
:root[data-theme="light"]{ color-scheme: light }
:root[data-theme="dark"] { color-scheme: dark  }

/* 3) 구형 브라우저 폴백: 앞줄이 무시되면 뒷줄만 남는다 */
.card{
  background:#ffffff;                        /* 미지원 시 이 값 */
  background:light-dark(#ffffff, #10151d);   /* 지원 시 이 값 */
}
// 사용자 선택 저장/복원 (localStorage 는 실제 서비스에서만 — 이 데모에선 생략)
const setTheme = (v) => document.documentElement.dataset.theme = v; // 'light'|'dark'|''
// '' 로 두면 :root 의 `color-scheme: light dark` 가 살아나 시스템 설정을 따른다

🧩 주의할 점

  • color-scheme 선언을 빠뜨리면 아무 일도 안 일어납니다. light-dark()만 쓰고 color-scheme이 없으면 항상 첫 번째(밝은) 색이 나옵니다. 가장 흔한 실수입니다.
  • prefers-color-scheme 미디어 쿼리와 섞어 쓰면 어긋납니다. 미디어 쿼리는 OS 설정을, light-dark()는 요소의 color-scheme을 봅니다. 한쪽으로 통일하세요.
  • 커스텀 속성(--x) 안에 넣으면 값이 쓰이는 요소의 color-scheme이 기준입니다. 그래서 부분 테마가 자연스럽게 따라옵니다.
  • 색상 대비(명도차)는 두 벌 모두 따로 검증해야 합니다. 문법이 짧아졌다고 대비 기준(본문 4.5:1)이 사라지진 않습니다.
  • 이미지·차트처럼 CSS 색이 아닌 자산은 light-dark() 밖입니다. SVG는 currentColor로 빼 두면 같이 따라옵니다.
지원 현황: MDN·web.dev 기준 2024년 5월 주요 엔진 전체에 구현(Baseline "신규 사용 가능"). "널리 사용 가능(Widely available)" 승격은 2026년 하반기로 예상됩니다 — 정확한 시점은 브라우저별 릴리스에 따라 달라질 수 있어 추정으로 둡니다.
