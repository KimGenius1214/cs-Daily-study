🪟 위험도별 확인 3단계 오버레이·모달·토스트

모든 삭제에 똑같이 "정말 삭제할까요?" 모달을 띄우면 사용자는 읽지 않고 확인을 누릅니다. 되돌릴 수 있으면 실행 후 되돌리기, 어려우면 확인, 치명적이면 이름 입력으로 마찰을 나눕니다.

A. 되돌리기 낮음

  • 결제 알림 (이메일)
  • 정산 알림 (이메일)

즉시 반영하고 5초 동안 되돌리기를 줍니다. 시간이 지나야 서버에 확정합니다.

B. 단순 확인 중간

  • Visa ···· 4242

제목에 대상을 쓰고, 기본 포커스는 안전한 "취소"에 둡니다. 버튼 라벨은 "예"가 아니라 "카드 삭제".

C. 이름 입력 확인 높음

  • 가맹점 API 키 (live)

복구 불가 + 영향 범위가 큰 동작만. 가맹점명 paysable-shop을 쳐야 버튼이 활성화됩니다.

Visa ···· 4242 카드를 삭제할까요?

예약된 정기결제 1건이 이 카드를 사용 중이에요. 삭제하면 해당 결제가 실패할 수 있어요.

API 키를 폐기할까요?

이 키를 쓰는 서버의 결제 요청이 즉시 모두 실패합니다. 계속하려면 가맹점명 paysable-shop을 입력하세요.

가맹점명이 일치하면 버튼이 활성화됩니다.
입력 확인은 복사·붙여넣기를 막지 않습니다(막으면 접근성만 해칩니다). 데모 데이터는 모두 가짜입니다.
dlg.showModal();            // 배경 inert + Esc 닫기 내장

🔔 에러 상태 설계 피드백·상태

"오류가 발생했습니다"는 정보가 없습니다. 무슨 일인지, 사용자가 할 수 있는 일, 다시 시도 가능 여부, 문의용 요청 ID를 같이 줍니다. 유형을 눌러 보세요.

유형 선택 → 재시도

429는 Retry-After 초만큼 기다린 뒤 버튼이 열립니다. 403은 재시도해도 같으니 재시도 버튼 대신 권한 요청을 줍니다. 모든 값은 가짜입니다.

// 재시도 가능 여부는 상태코드로 판단
const retryable = s => s === 429 || s >= 500 || s === 0; // 0 = 네트워크
// 429: Retry-After 헤더 초만큼 대기 후 활성화

🌀 light-dark() 트렌드·개념

light-dark(밝은값, 어두운값)은 요소의 color-scheme에 따라 색을 고릅니다. 다크 모드용 미디어쿼리를 따로 쓰지 않아도 됩니다. 단, color-scheme이 normal이면 항상 밝은 값입니다. 위의 테마 버튼을 눌러 보세요.

같은 CSS, 요소별 color-scheme만 다름

normal (선언 없음)항상 밝은 값
light항상 밝은 값
dark항상 어두운 값
inherit (페이지 따라감)테마 토글을 따름

지원: Baseline 2024에 신규 지원된 것으로 알고 있습니다(정확한 날짜·브라우저 버전은 MDN에서 확인 필요, 추정). 구형 브라우저용으로 앞줄에 단색 폴백을 둡니다.
:root { color-scheme: light dark; }
.card { background: #fff; background: light-dark(#fff, #161c26); }
