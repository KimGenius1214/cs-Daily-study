🧭 목록 더 불러오기 3형 페이지네이션 · 더보기 · 무한 스크롤

긴 목록을 나눠 보여주는 방법은 크게 셋입니다. 셋 다 "다음 데이터로 이동"이라는 내비게이션이고, 골라 쓰는 기준이 각각 다릅니다. 아래 탭을 눌러 같은 거래 데이터를 세 방식으로 비교해 보세요.

    각 페이지가 고유 주소를 가집니다. 현재 페이지는 aria-current="page"로 표시해 스크린리더가 "현재 페이지"라고 읽습니다. 정산·감사처럼 "3페이지 그거"라고 다시 찾아가야 하는 목록에 적합합니다.

      사용자가 직접 눌러야 다음 묶음이 옵니다. 로딩 중엔 버튼이 비활성 + 스피너, 끝나면 추가된 개수를 aria-live(변경 내용을 소리로 알려주는 영역)로 알리고 새로 추가된 첫 항목으로 포커스를 옮깁니다. 스크롤 위치를 잃지 않아 실무에서 가장 안전한 기본값입니다.

        아래로 스크롤하면 자동으로 더 불러옵니다

        스크롤이 바닥 근처에 닿으면 IntersectionObserver(요소가 화면에 들어왔는지 감시하는 브라우저 API)가 다음 묶음을 자동으로 붙입니다. 자동 로딩만 두면 키보드 사용자가 갇히므로 동일 기능의 버튼을 반드시 함께 둡니다.

        기준번호 페이지네이션더보기 버튼무한 스크롤

        푸터 접근✅✅❌ 계속 밀림
        손 안 쓰는 탐색△ 클릭 많음△ 클릭 필요✅ 편함

        💻 핵심 코드 — 더보기 버튼의 포커스 이동

        async function loadMore() {
  btn.disabled = true;
  btn.innerHTML = '<span class="spin"></span>불러오는 중…';

  const rows = await fetchPage(page++);
  const firstNewIndex = list.children.length;   // 붙이기 전 길이 = 새 항목 시작점
  list.append(...rows.map(renderRow));

  // 1) 스크린리더에 결과를 말해 준다
  status.textContent = `${rows.length}건 추가. 총 ${list.children.length}건.`;

  // 2) 키보드 사용자를 새 콘텐츠 앞으로 데려간다 (스크롤 위치는 유지)
  const firstNew = list.children[firstNewIndex];
  firstNew.tabIndex = -1;                        // 원래 포커스 못 받는 요소를 임시로 받게
  firstNew.focus({ preventScroll: true });

  btn.disabled = false;
  btn.textContent = '더 보기';
}

        ♿ 접근성 체크

        • <nav aria-label="…">로 페이저를 감싸고, 현재 페이지에 aria-current="page".
        • 비활성 이전/다음은 aria-disabled="true"로 두어 포커스 순서에서 사라지지 않게 합니다(버튼이 갑자기 없어지면 탭 이동이 튑니다).
        • 추가 로딩 결과는 aria-live="polite" 영역에 문장으로 알립니다. "10건 추가, 총 30건."
        • 무한 스크롤에는 항상 버튼 폴백 + 목록 끝을 알리는 문장("마지막입니다").
        💡 paysable 적용 — 결제/정산 내역은 "지난주에 본 그 페이지"를 다시 찾는 일이 잦으므로 번호 페이지네이션(URL의 ?page=)이 기본이 좋습니다. 반대로 관리자 알림·활동 로그처럼 최신순으로 훑기만 하는 목록은 더보기 버튼이 낫습니다. 무한 스크롤은 개수가 수천 건이고 되찾을 필요가 없는 화면에만 제한적으로 쓰는 걸 권합니다.

        🃏 드래그 정렬 리스트 마우스 드래그 + 키보드 대체 조작

        항목 순서를 사용자가 직접 바꾸는 컴포넌트입니다. 드래그만 구현하면 키보드·터치·스크린리더 사용자는 아예 못 씁니다. 요즘 기준은 "드래그는 편의, 키보드가 정식 경로". 아래에서 마우스로 끌어도 되고, 핸들에 Tab으로 간 뒤 Space로 집어서 ↑↓로 옮겨도 됩니다.

        핸들에서 스페이스 또는 엔터를 눌러 항목을 집고, 위아래 화살표로 옮긴 뒤 다시 스페이스로 놓습니다. 이스케이프로 취소합니다.

          Tab 핸들로 이동 · Space 집기/놓기 · ↑↓ 이동 · Esc 취소 · 마우스로 핸들을 끌어도 됩니다.

          집힌 항목은 색·왼쪽 굵은 선으로 표시하고, 이동할 때마다 "OO을 2번째에서 1번째로 옮겼습니다"를 role="status" 영역이 읽습니다. 위치를 색으로만 표시하면 화면을 못 보는 사용자에게 아무 정보가 없습니다.

          💻 핵심 코드 — 키보드 집기·이동

          handle.addEventListener('keydown', (e) => {
  const li = handle.closest('li');

  // 집기 / 놓기 토글
  if (e.key === ' ' || e.key === 'Enter') {
    e.preventDefault();                       // 스페이스로 페이지가 스크롤되지 않게
    grabbed = grabbed === li ? null : li;
    handle.setAttribute('aria-pressed', String(!!grabbed));
    say(grabbed ? `${name(li)} 집었습니다. 화살표로 이동.`
               : `${name(li)} 놓았습니다. 현재 ${pos(li)}번째.`);
    return;
  }

  if (!grabbed) return;                       // 안 집은 상태에선 화살표 무시

  if (e.key === 'ArrowUp' || e.key === 'ArrowDown') {
    e.preventDefault();
    const from = pos(li);
    const sibling = e.key === 'ArrowUp'
      ? li.previousElementSibling
      : li.nextElementSibling;
    if (!sibling) { say('더 이상 옮길 수 없습니다.'); return; }

    // DOM에서 실제로 자리를 바꾼다
    e.key === 'ArrowUp' ? sibling.before(li) : sibling.after(li);
    handle.focus();                           // 이동 후에도 포커스 유지 (핵심!)
    say(`${name(li)}을 ${from}번째에서 ${pos(li)}번째로 옮겼습니다.`);
  }

  if (e.key === 'Escape') { restoreOriginalOrder(); grabbed = null; }
});

          ♿ 접근성·상태 설계

          • 핸들은 <button>. div에 draggable만 달면 포커스도 안 가고 엔터도 안 먹습니다.
          • 집힌 상태는 aria-pressed="true" — 스크린리더가 "눌림"으로 읽어 모드에 들어갔음을 알립니다.
          • DOM 순서를 바꾸면 포커스가 날아갑니다. 이동 직후 handle.focus()로 되찾아 주는 게 이 컴포넌트의 가장 흔한 버그 지점입니다.
          • 순서는 눈으로도 번호(1·2·3)를 같이 보여줍니다. 위치를 색·그림자로만 알리지 않습니다.
          • 저장은 낙관적으로(먼저 반영) 하되 되돌리기를 함께 제공합니다. 잘못 끌었을 때 복구 경로가 없으면 사용자는 드래그 자체를 피하게 됩니다.
          • prefers-reduced-motion(움직임 줄이기 OS 설정)이 켜져 있으면 이동 트랜지션을 끕니다.
          💡 paysable 적용 — 결제수단 우선순위, 대시보드 위젯 배치, 정산 리포트 컬럼 순서처럼 "사용자가 자기 화면을 정리하는" 자리에 씁니다. 저장은 이동할 때마다 서버에 쏘지 말고 디바운스(연속 입력을 묶어 마지막 한 번만 보내기)하거나 명시적 저장 버튼으로 묶는 편이 요청 수·충돌 면에서 안전합니다.

          🌀 스크롤 기반 애니메이션 animation-timeline: scroll() · view()

          "스크롤에 맞춰 진행바가 차거나, 카드가 화면에 들어올 때 나타나는" 효과를 JS 없이 CSS만으로 만드는 표준입니다. 기존엔 scroll 이벤트나 IntersectionObserver + JS가 필요했는데, 이제 애니메이션의 시간축을 시계 대신 스크롤 위치로 바꿔 끼웁니다.

          상단 바 = scroll() 타임라인 카드 등장 = view() 타임라인 JS 0줄

          위 상자 안에서 스크롤해 보세요. 맨 위 얇은 바는 스크롤 진행률을, 각 카드는 자기가 화면에 들어오는 정도를 각각 애니메이션 진행도로 씁니다. 두 타임라인의 차이가 핵심입니다.

          📈 왜 지금 뜨나

          • 메인 스레드를 안 쓴다 — JS 스크롤 핸들러는 스크롤할 때마다 코드가 돌아 끊길 수 있지만, CSS 타임라인은 브라우저 합성기에서 처리됩니다(공식 문서들이 이 점을 주요 이점으로 듭니다).
          • 스크롤 애니메이션 하나 붙이자고 라이브러리를 끌어오던 관행이 사라집니다.
          • 브라우저 지원(2026-08 기준, 검색 확인): Chrome/Edge 115+ 정식, Safari 26+ 지원, Firefox 정식판은 아직 플래그 뒤라 Baseline은 아닙니다. 즉 없어도 되는 장식에만 쓰고 @supports로 감싸는 게 안전합니다.

          💻 코드 (복붙용)

          /* 1) 스크롤 진행바 — scroll() 타임라인
      "이 요소의 가장 가까운 스크롤 조상이 얼마나 스크롤됐나"를 0~100%로 씀 */
@supports (animation-timeline: scroll()) {
  .progress-bar {
    transform-origin: 0 50%;
    animation: grow linear both;
    animation-timeline: scroll(nearest);   /* root / nearest / self */
  }
}
@keyframes grow { from { transform: scaleX(0) } to { transform: scaleX(1) } }

/* 2) 등장 애니메이션 — view() 타임라인
      "이 요소가 스크롤포트 안에 얼마나 들어와 있나"를 0~100%로 씀 */
@supports (animation-timeline: view()) {
  .card-reveal {
    animation: reveal linear both;
    animation-timeline: view();
    animation-range: entry 5% cover 28%;   /* 들어오기 시작~28% 덮을 때까지 진행 */
  }
}
@keyframes reveal {
  from { opacity: 0; transform: translateY(18px) scale(.97) }
  to   { opacity: 1; transform: none }
}

/* 3) 필수 — 움직임을 줄여달라는 사용자 설정 존중 */
@media (prefers-reduced-motion: reduce) {
  .card-reveal { animation: none !important; opacity: 1 !important; transform: none !important }
  .progress-bar { animation: none !important; transform: scaleX(1) !important }
}

          ♿ 함정과 접근성

          • animation-fill-mode: both(축약형의 both)를 빼면 범위 밖에서 원래 스타일로 튑니다. 거의 항상 넣습니다.
          • 내용을 감추는 데 쓰지 마세요. 미지원 브라우저에서는 애니메이션이 안 돌아 opacity:0인 채로 남아 콘텐츠가 통째로 사라질 수 있습니다. 초기 opacity:0은 반드시 @supports 블록 안에서만 줍니다.
          • prefers-reduced-motion: reduce일 때 끄는 건 선택이 아니라 기본입니다. 스크롤 연동 움직임은 전정기관 불편을 유발할 수 있습니다.
          • scroll(nearest)는 가장 가까운 스크롤 조상을 찾습니다. 대상 요소가 그 스크롤 컨테이너 안에 있어야 합니다. 밖에 있으면 scroll-timeline-name + timeline-scope로 이름을 붙여 넘겨야 합니다.
          💡 paysable 적용 — 결제 콘솔 본문에는 과하지만, ① 긴 약관·정산 상세의 읽기 진행바, ② 랜딩·릴리즈 노트의 섹션 등장, ③ 긴 테이블 상단 스티키 헤더의 그림자 on/off 같은 데 쓰기 좋습니다. 모두 "없어도 기능은 멀쩡한" 장식이라 Firefox 미지원이 문제되지 않습니다.
