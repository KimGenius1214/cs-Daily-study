🔘 아이콘 전용 버튼⌨️ 조회 기간 선택🌀 :has()

🔘 아이콘 전용 버튼 — 이름은 aria-label, 툴팁은 보조, 눌리는 영역은 24px 이상 버튼·액션

테이블 행 끝의 복사·다운로드·더보기 아이콘은 화면을 아끼지만, 스크린리더에겐 "버튼"이라고만 들리고 손가락엔 너무 작습니다. 요즘 디자인 시스템은 세 가지를 같이 챙깁니다: 접근 이름(보조기기가 읽는 버튼 이름), 툴팁(시각 사용자용 같은 이름 — 호버와 포커스 둘 다에서), 타깃 크기(아이콘은 작아도 누르는 영역은 넓게).

DEMO — 각 아이콘에 마우스를 올리거나 Tab으로 이동해 보세요. 아래 상자에 "스크린리더가 듣는 것"이 표시됩니다. Esc는 툴팁 닫기.

❌ 흔한 구현 이름 없음 · 키보드 불가

① div + onclick: Tab으로 못 감. ② 이름 없는 button: "버튼"만 읽힘. ③ title만: 터치·키보드에선 툴팁이 안 뜨고, 읽어 주는 방식도 보조기기마다 제각각.

✅ 권장 구현 이름 + 툴팁 + 44px 영역

거래 ID 복사 영수증 다운로드 즐겨찾는 가맹점 거래 취소 — 정산 완료 건은 취소 불가정산 완료 건은 취소할 수 없습니다 새로고침Alt R

즐겨찾기는 토글 — 이름은 고정하고 상태는 aria-pressed로. 취소는 비활성이지만 aria-disabled라 포커스가 닿고 "왜 안 되는지"가 들립니다.

대상 아이콘에 포커스하거나 마우스를 올려 보세요

실전 배치 — 거래 행 끝의 아이콘 액션

한빛상회 · 48,000원TX-20261116-0042 · 11/16 08:31
거래 ID 복사 영수증 다운로드

목록 안에서는 "복사" 버튼이 20개 반복됩니다. 접근 이름에 대상(거래 ID·가맹점)을 넣어야 버튼 목록만 훑는 사용자도 구분할 수 있어요. 툴팁은 짧게 둬도 됩니다.

로그
<!-- 아이콘 버튼: 이름은 aria-label, 아이콘은 장식 -->
<span class="tipw">
  <button type="button" class="ib" aria-label="TX-0042 거래 ID 복사">
    <svg aria-hidden="true" focusable="false">…</svg>
  </button>
  <span class="tip" aria-hidden="true">거래 ID 복사</span>  <!-- 이름 중복 낭독 방지 -->
</span>

/* 아이콘은 24px, 누르는 영역은 44px — 레이아웃은 그대로 */
.ib { position: relative; width: 24px; height: 24px; }
.ib::before { content: ""; position: absolute; inset: -10px; }

// 툴팁: 호버는 지연, 포커스는 즉시, Esc로 닫기(WCAG 1.4.13)
wrap.addEventListener('pointerenter', () => t = setTimeout(open, 300));
wrap.addEventListener('pointerleave', () => { clearTimeout(t); close(); });
btn.addEventListener('focus', open);  btn.addEventListener('blur', close);
document.addEventListener('keydown', e => e.key === 'Escape' && closeAll());

WCAG 2.2의 2.5.8 "타깃 크기(최소)"(AA)는 24×24 CSS px 이상 또는 주변 간격 확보를 요구하고, 44×44는 더 엄격한 AAA(2.5.5) 기준입니다. 영역을 ::before로 넓힐 땐 이웃 버튼의 영역과 겹치지 않게 간격(gap)을 함께 잡으세요 — 겹치면 엉뚱한 버튼이 눌립니다.

⌨️ 조회 기간 선택 — 프리셋은 버튼 한 번, 직접 입력은 고치지 말고 알려주기, 끝 날짜는 '다음 날 0시 미만'으로 입력·폼

거래내역·정산 조회 화면의 첫 입력은 거의 항상 기간입니다. 사용자는 대부분 "오늘·이번 달·지난달"을 원하니 프리셋을 앞에 두고, 직접 입력은 보조로 둡니다. 시작일이 종료일보다 늦거나 최대 기간을 넘으면 몰래 바꾸지 말고 이유와 한 번에 고치는 버튼을 줍니다. 서버로 보낼 땐 KST 기준, 끝은 다음 날 0시 미만(반개구간)으로 보내야 23:59:59.500 같은 건이 빠지지 않습니다.

조회 기간 (KST) ~

날짜를 직접 바꾸면 프리셋이 "직접 입력"으로 넘어가고, 다시 프리셋과 같은 범위가 되면 그 프리셋이 켜집니다. 오늘이 포함되면 "집계 중" 표시 — 금액이 아직 바뀔 수 있다는 신호.

서버로 보낼 값
// KST 오늘 — toISOString()은 UTC라 새벽 0~9시에 하루 틀림
const todayKST = new Intl.DateTimeFormat('en-CA', {
  timeZone: 'Asia/Seoul', year: 'numeric', month: '2-digit', day: '2-digit',
}).format(new Date());                                   // "2026-11-16"

// 날짜 문자열 산술은 UTC 자정 기준으로 (DST·로컬 TZ 영향 제거)
const addDays = (ymd, n) => {
  const d = new Date(ymd + 'T00:00:00Z'); d.setUTCDate(d.getUTCDate() + n);
  return d.toISOString().slice(0, 10);
};

function validate(from, to) {
  if (!from || !to)      return { code: 'EMPTY' };
  if (from > to)         return { code: 'REVERSED', fix: () => [to, from] };   // 고쳐줄 '제안'만
  if (to > todayKST)     return { code: 'FUTURE',   fix: () => [from, todayKST] };
  const days = diffDays(from, to) + 1;                    // 양끝 포함
  if (days > MAX_DAYS)   return { code: 'TOO_LONG', fix: () => [addDays(to, -(MAX_DAYS - 1)), to] };
  return { code: 'OK', days };
}

// 서버엔 반개구간 [from 00:00, to+1 00:00) +09:00
const params = { from: `${from}T00:00:00+09:00`, toExclusive: `${addDays(to, 1)}T00:00:00+09:00` };

"최근 3개월"을 달력 3개월(8/16~11/16)로 할지 90일로 할지는 팀 정책입니다. 어떤 쪽이든 칩 아래에 실제 날짜 범위를 늘 보여 주면 오해가 없습니다. 또 <input type="date">의 표시 형식과 달력 UI는 브라우저·OS 설정을 따르므로 디자인을 픽셀 단위로 맞추려 하지 말고, 값(YYYY-MM-DD)만 믿으세요.

🌀 :has() — 자식·형제의 상태로 부모를 꾸며서, 스타일용 JS 클래스 토글을 걷어내기 트렌드·개념

:has()는 "이런 걸 안에 가진 요소"를 고르는 선택자입니다(관계형 의사 클래스). 예전엔 입력이 틀리면 JS로 부모 div에 .is-error를 붙였지만, 이제 .field:has(input:user-invalid) 한 줄이면 됩니다. 2023년 말 주요 브라우저에 모두 들어와 Baseline이 됐고, 지금은 "부모 선택자"를 넘어 빈 상태·개수별 레이아웃까지 CSS로 처리하는 흐름입니다.

DEMO — 아래 세 상자는 스타일 변경에 JS를 쓰지 않습니다(전체 동의·장바구니 추가/삭제 같은 동작만 JS)

확인 중…

① 필드 상태 → 감싼 상자 전체

이메일 형식이 아니에요 (예: name@example.com)

.hfield:has(input:user-invalid) — 건드리고 나간 뒤에만 빨간 상자. 포커스 중엔 테두리만 브랜드색.

② 필수 약관 미동의 → 결제 버튼 모양

필수 약관 2개에 동의해야 결제할 수 있어요

.paybox:has(.req:not(:checked)) — 모양만 바꿉니다. 실제로 막는 건 클릭 핸들러(그리고 서버).

③ 자식 개수·유무 → 레이아웃·빈 상태

    장바구니가 비었어요

    .cart:not(:has(li)) → 빈 상태, .cart:has(li:nth-child(4)) → 4개부터 2열. "개수 쿼리"를 미디어쿼리 없이.

    로그
    /* ① 부모(필드 래퍼)가 자식 입력의 상태를 안다 */
.field:has(input:user-invalid)        { border-color: var(--bad); }
.field:has(input:user-invalid) .err   { display: block; }
.field:has(input:focus-visible)       { border-color: var(--brand); }

/* ② 형제·사촌 상태 — 필수 체크가 하나라도 비면 버튼을 '안 됨' 모양으로 */
.paybox:has(.req:not(:checked)) .paybtn { background: var(--surface-2); }

/* ③ 빈 상태·개수 쿼리 */
.cart:not(:has(li)) .empty        { display: block; }
.cart:has(li:nth-child(4)) ul     { grid-template-columns: 1fr 1fr; }

/* 지원 확인(구형 브라우저 폴백) */
@supports not selector(:has(*)) { .field.is-error { border-color: var(--bad); } }

    주의 세 가지. ① body:has(…)처럼 넓은 범위에 걸면 DOM이 바뀔 때마다 재계산 범위가 커지니, 가능한 가까운 조상에 거세요. ② :has() 안에 :has()는 중첩할 수 없고, ::before 같은 의사 요소도 안에 못 넣습니다. ③ :has()는 보이는 모양만 바꿉니다. 버튼이 회색이어도 클릭은 되므로 막는 로직·aria 상태는 따로 둬야 합니다.
