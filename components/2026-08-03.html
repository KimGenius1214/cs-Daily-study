🔘 세그먼트 컨트롤 — 라디오 기반 분할 토글과 슬라이딩 인디케이터 버튼·액션

세그먼트 컨트롤(segmented control)은 2~4개의 배타적 선택지를 한 줄 캡슐 안에 나란히 놓고 하나만 고르게 하는 컨트롤이다. 탭과 달리 페이지 전체를 바꾸기보다 같은 화면의 표시 방식·범위(기간·정렬·통화 등)를 바꿀 때 쓴다. 내부는 radio 그룹이라 화살표 키 이동·스크린리더 지원이 공짜로 따라온다.

기본 · 슬라이딩 인디케이터가 선택 칸으로 미끄러진다 (클릭/화살표 키)

선택: 일간
선택: ₩ KRW

라벨을 클릭하거나, 컨트롤에 포커스를 준 뒤 ←→ 로 이동해 보세요. 흰 인디케이터가 선택 칸으로 애니메이션되며, 값이 바로 아래에 반영됩니다. (모션 최소화 설정이면 애니메이션은 자동으로 꺼집니다.)

왜 이렇게? 겉보기엔 버튼 무리지만 속을 진짜 radio 로 만들면 "하나만 선택"이라는 의미와 키보드 동작을 브라우저가 알아서 처리한다(버튼 div 로 흉내 내면 전부 직접 구현해야 함). 인디케이터는 포지션 계산(선택 칸의 offsetLeft/offsetWidth)으로 옮겨 텍스트 길이가 달라도 정확히 맞춘다. 옵션이 5개를 넘으면 세그먼트 대신 select나 드롭다운이 낫다.

⌨️ OTP 인증코드 입력 — 자동 포커스 이동·붙여넣기 분배·재전송 타이머 입력·폼

문자로 받은 OTP(One-Time Password, 일회용 인증번호)를 칸별로 나눠 입력받는 패턴. 결제 3DS 인증·로그인 2단계 인증에서 매일 쓰인다. 핵심은 사용자가 손을 거의 안 대도 되게 만드는 것: 한 자 입력하면 자동으로 다음 칸, 6자리를 붙여넣으면 칸마다 분배, 재전송은 타이머로 도배 방지.

정답은 428913 — 한 칸씩 타이핑하거나 6자리를 통째로 붙여넣어 보세요

남은 시간 30초

입력이 다 차면 자동 검증한다. 틀리면 흔들림 + 재입력, 맞으면 초록 확정. Backspace 는 빈 칸에서 이전 칸으로, ←→ 로도 칸 이동. 재전송 버튼은 카운트다운이 끝나야 활성화됩니다.

왜 이렇게? 실제 앱에선 각 input 에 inputmode="numeric"(모바일 숫자 키패드)과 첫 칸에 autocomplete="one-time-code" 를 준다. 그러면 iOS Safari가 문자로 온 코드를 키보드 위에 자동 채우기 로 띄워준다(안드로이드·크롬은 WebOTP API 로 보완 — 이건 추정 포함, 플랫폼별 동작 차이 있음). 붙여넣기 분배가 이 패턴의 진짜 편의: paste 이벤트에서 숫자만 뽑아 칸마다 흩뿌리면 비밀번호 관리자/문자 복사와 궁합이 좋다. 단일 input 한 칸도 복붙·자동채우기엔 오히려 단순·안전하니, 6칸 UI는 "예뻐서"가 아니라 팀 합의로 고른다.

🌀 CSS 앵커 포지셔닝 — JS 없이 요소를 기준점에 붙여 배치 트렌드·개념

앵커 포지셔닝(anchor positioning)은 한 요소(기준=anchor)에 이름을 붙이고, 다른 요소(팝오버·툴팁·메뉴)를 그 기준의 위/아래/옆에 CSS만으로 붙이는 새 기능이다. 예전엔 Floating UI 같은 JS 라이브러리로 좌표를 계산했는데, 이제 anchor-name + position-anchor + position-area 몇 줄로 끝난다. 화면 밖으로 나가면 position-try-fallbacks 가 자동으로 반대편으로 뒤집는다.

버튼을 눌러 메뉴/툴팁을 띄워 보세요 — 위치는 100% CSS가 잡습니다

정산 옵션

이 카드는 버튼 아래에 자동 정렬됩니다. 공간이 부족하면 위로 뒤집힙니다(fallback).

수수료 안내

결제액의 2.8%가 수수료로 차감된 뒤 정산됩니다. 이 툴팁은 버튼 위에 붙습니다.

지원 여부 확인 중…

팝오버는 브라우저 기본 popover 속성으로 열고(바깥 클릭·Esc 로 닫힘), 위치만 앵커 CSS가 잡습니다. 미지원 브라우저에선 아래 안내가 뜨고 팝오버는 화면 기본 위치에 나타납니다.

왜 지금 뜨나? 2026년 기준 앵커 포지셔닝은 Chrome/Edge 125+, Firefox 132+, Safari 18.2+ 에서 동작해 Baseline(주요 브라우저 도달) 에 들어왔다(자동 뒤집기 @position-try 는 Safari 18.4+ 필요). 드롭다운·툴팁·태그 자동완성 위치 계산을 JS 없이 처리할 수 있어 번들이 가벼워지고, 팝오버가 overflow:hidden 부모에 잘려도 top layer 로 떠서 안 잘린다. 다만 구형 브라우저 폴백(JS 위치 계산 또는 정적 배치)은 아직 함께 둬야 한다.
