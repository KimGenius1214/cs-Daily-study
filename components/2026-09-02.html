왜 이렇게 하나 — 현재 플랜에 현재 배지를 박고 선택을 막으면, "이미 쓰는 플랜을 또 결제했다"는 사고를 구조적으로 없앱니다. 카드 전체를 <label>로 감싸 클릭 영역을 넓히고, 선택 표시는 :has(input:checked)로 CSS가 처리합니다.

변경 미리보기 대기

플랜을 고르면 오늘 청구될 금액을 계산합니다.

왜 이렇게 하나 — 업그레이드는 "지금부터 쓰고 차액만 낸다", 다운그레이드는 "이미 낸 돈이 있으니 다음 주기부터"가 자연스러운 기본값입니다. 그래서 방향에 따라 기본 선택을 바꾸고, 금액 계산 근거(남은 13일/31일)를 줄 단위로 드러냅니다. 금액이 바뀌는 영역은 aria-live="polite"로 감싸 화면낭독기 사용자도 변화를 듣습니다.

💻 프로레이션 계산 (핵심만)

// 남은 기간 비율로 "쓰지 않은 금액"을 돌려주고, 새 플랜을 남은 기간만큼만 청구
function proration({ current, next, cycleStart, cycleEnd, today }) {
  const DAY = 86400000;
  const total = Math.round((cycleEnd - cycleStart) / DAY);   // 31일
  const left  = Math.max(0, Math.round((cycleEnd - today) / DAY)); // 13일
  const ratio = left / total;

  const credit = Math.floor(current.price * ratio); // 현재 플랜 미사용분 = 환불 크레딧
  const charge = Math.floor(next.price    * ratio); // 새 플랜 남은 기간분
  const dueNow = Math.max(0, charge - credit);      // 음수면 0원 + 잔액은 크레딧으로 이월

  return { total, left, credit, charge, dueNow, carry: Math.max(0, credit - charge) };
}
용어 — 프로레이션(proration, 일할 계산): 주기 도중에 플랜을 바꿀 때 남은 날짜 비율로 금액을 나눠 정산하는 방식. 크레딧: 이미 냈지만 쓰지 않은 금액을 현금 환불 대신 계정 잔액으로 돌려주는 것. 실제 결제사(PG)마다 반올림·초 단위 계산·세금 처리가 달라, 화면 금액은 미리보기임을 표시하고 최종 금액은 서버 계산값을 쓰는 게 안전합니다.

♿ 접근성·상태 설계

  • 플랜 카드는 role="radiogroup" + 실제 <input type="radio">. div로 흉내 내면 ←→ 키 이동과 그룹 낭독을 전부 직접 구현해야 합니다.
  • 현재 플랜은 disabled + 현재 배지. 색만으로 구분하지 않습니다(색각 이상 대비).
  • 금액 미리보기 영역은 aria-live="polite" — 조작 흐름을 끊지 않고 변경분만 알립니다(assertive는 에러급에만).
  • 해지 확정 버튼은 .danger로 시각 구분 + 문구에 결과 날짜를 넣어 되돌릴 수 있음을 밝힙니다.
  • prefers-reduced-motion(사용자가 OS에서 "동작 줄이기"를 켠 상태) 존중 — 카드 확대·전환을 사실상 끕니다.

⌨️ 약관 동의 그룹 입력·폼

가입·결제 첫 화면의 "전체 동의". 부분 선택(indeterminate) 상태, 필수/선택 구분, 하위 채널 동의, 필수 미동의 시 제출 차단과 포커스 이동까지 실제로 동작합니다.

변형 1 — 전체 동의 · 부분 선택 · 개별 항목 펼쳐보기

서비스 이용 약관 동의
제1조(목적) 본 약관은 회사가 제공하는 결제 및 정산 서비스의 이용 조건과 절차, 회원과 회사의 권리·의무 및 책임사항을 규정함을 목적으로 합니다. 제2조(정의) "회원"이란 본 약관에 동의하고 서비스 이용 계약을 체결한 자를 말합니다… (데모용 더미 텍스트)
수집 항목: 이름, 휴대전화번호, 이메일, 결제수단 정보. 이용 목적: 본인 확인, 결제·정산 처리, 고객 문의 응대. 보유 기간: 회원 탈퇴 시까지(단, 전자상거래법 등 관련 법령에 따라 일정 기간 보관)… (데모용 더미 텍스트)
할인·이벤트·신규 기능 안내를 선택한 채널로 보내드립니다. 언제든 설정에서 해제할 수 있으며, 해제해도 결제 승인·정산 같은 필수 안내는 계속 발송됩니다. (데모용 더미 텍스트)
동의 0 / 4 · 필수 0 / 3
제출됨

왜 이렇게 하나 — 전체 동의 체크박스는 세 가지 상태를 가집니다: 전부 해제 / 일부만 선택(indeterminate) / 전부 선택. 일부 선택 상태를 표현하지 않으면 사용자는 "전체 동의를 껐는데 왜 아래는 켜져 있지?" 하고 혼란스러워합니다. 마케팅(선택) 항목은 기본 해제가 원칙이며, 하위 채널은 부모를 켤 때만 드러납니다.

변형 2 — 제출 차단과 첫 미동의 항목으로 포커스 이동

위 폼에서 필수 항목을 하나라도 비운 채 동의하고 계속을 눌러 보세요. 에러 문구가 뜨고, 커서가 첫 미동의 체크박스로 이동합니다.

💻 코드 (복붙용)

// 부모(전체 동의) ↔ 자식 체크박스 3-상태 동기화
const all   = document.getElementById("agreeAll");
const items = [...document.querySelectorAll(".c-item")];

function syncParent() {
  const on = items.filter(i => i.checked).length;
  all.checked = on === items.length;
  // indeterminate 는 "일부만 선택됨"을 나타내는 DOM 프로퍼티.
  // HTML 속성으로는 못 쓰고 JS 로만 켠다. 화면낭독기는 보통 "부분 선택"으로 읽는다.
  all.indeterminate = on > 0 && on < items.length;
}
all.addEventListener("change", () => {
  items.forEach(i => { i.checked = all.checked; });
  all.indeterminate = false;
});
items.forEach(i => i.addEventListener("change", syncParent));

// 제출 시: 필수 미동의면 막고, 첫 미동의 항목으로 포커스
form.addEventListener("submit", (e) => {
  const miss = items.filter(i => i.dataset.required === "1" && !i.checked);
  if (miss.length) {
    e.preventDefault();
    errBox.textContent = `필수 항목 ${miss.length}개에 동의해 주세요.`;
    miss[0].focus();   // 에러만 띄우고 끝내면 사용자가 어디를 고칠지 못 찾는다
  }
});

♿ 접근성·상태 설계

  • indeterminate는 보이기만 하는 상태가 아니라 접근성 트리에도 "mixed"로 반영됩니다. div+아이콘으로 흉내 내면 이 정보가 사라집니다.
  • 전체 동의에 aria-controls로 하위 목록을 연결해 관계를 밝힙니다.
  • "보기" 버튼은 aria-expanded 토글 — 펼침 상태를 소리로도 알 수 있어야 합니다.
  • 에러 박스는 role="alert"로 즉시 낭독하고, 동시에 첫 미동의 항목으로 포커스를 옮깁니다. (에러 요약만 띄우는 건 절반짜리)
  • 필수/선택은 필수·선택 배지 텍스트로 구분 — 빨간 별표 하나로 끝내지 않습니다.
  • 체크 영역은 <label>로 감싸 클릭 타겟을 넓힙니다(모바일 최소 44px 권장).

💻 코드 (복붙용)

/* 1) sticky 요소의 "부모"를 스크롤 상태 컨테이너로 만든다 */
.sticky-wrap {
  container-type: scroll-state;
  container-name: stickyhead;
  position: sticky;
  top: 0;
}
/* 2) 위쪽 경계에 붙었을 때만 적용 */
@container stickyhead scroll-state(stuck: top) {
  .sticky-head { padding-block: 8px; box-shadow: 0 4px 14px rgb(0 0 0 / .14); }
}

/* 스냅에 걸린 항목만 강조 */
.snap-item { container-type: scroll-state; scroll-snap-align: center; }
@container scroll-state(snapped: inline) {
  .snap-card { opacity: 1; transform: scale(1.03); }
}

/* 아래로 더 스크롤할 수 있을 때만 힌트 */
.hint-wrap { container-type: scroll-state; }
@container scroll-state(scrollable: bottom) { .more { opacity: 1; } }

/* 미지원 브라우저용 기본값을 항상 먼저 쓰고, 지원 시에만 덮는다(프로그레시브 인핸스먼트) */
@supports (container-type: scroll-state) { /* … */ }
용어 — 컨테이너 쿼리: 화면 크기가 아니라 담긴 칸의 조건에 따라 스타일을 바꾸는 CSS. scroll-state()는 그 조건을 "스크롤 상태"로 확장한 것으로, stuck(sticky 요소가 경계에 붙음) · snapped(스냅 위치에 걸림) · scrollable(그 방향으로 더 스크롤 가능) 세 가지를 질의합니다. 프로그레시브 인핸스먼트: 미지원 환경에서도 기본 기능은 되고, 지원 환경에서만 좋아지게 만드는 방식.
브라우저 지원(2026-09 시점, 확인 필요) — MDN·Chrome 개발자 블로그 기준 stuck·snapped·scrollable은 Chrome/Edge 133+에서, scrolled는 Chrome/Edge 144+에서 지원됩니다. Safari·Firefox는 아직 안정 버전 미지원으로 추정됩니다. 따라서 없어도 되는 장식(그림자·강조·힌트)에만 쓰고, 기능 자체를 여기 걸지 마세요. 아래 배지가 지금 브라우저의 실제 지원 여부입니다.

♿ 접근성·상태 설계

  • 스냅 강조를 opacity로만 표현하면 대비가 낮아집니다 — 데모처럼 테두리 색까지 함께 바꿉니다.
  • "더 있음" 힌트는 pointer-events:none으로 클릭을 막지 않고, 장식이므로 낭독 대상이 아닙니다.
  • prefers-reduced-motion에서는 확대(transform)를 끄고 색 변화만 남깁니다.
  • 미지원 브라우저에서는 세 데모 모두 스크롤 자체는 정상이고 장식만 빠집니다 — 이것이 안전한 도입 기준입니다.
