💳 주문 요약 — 가격 분해·수량 반영·스티키 합계 결제·체크아웃 UX

체크아웃 마지막 관문. 사용자가 "내가 지금 정확히 얼마를 왜 내는지" 한눈에 납득해야 이탈이 준다. 수량을 바꾸면 소계·할인·배송·세금·합계가 즉시 다시 계산되고, 합계 카드는 스크롤해도 따라붙는다.

왜 이렇게? — 금액은 tabular-nums(숫자 폭 고정)로 정렬해 자릿수가 흔들리지 않게. 합계 변동은 색으로 잠깐 강조하되 prefers-reduced-motion이면 끈다. "무료배송까지 N원" 진행바로 장바구니 추가를 유도.

핵심 패턴

  • 단일 계산 함수 하나가 소계→할인→배송→세금→합계를 순서대로 도출. UI는 그 결과만 그린다(계산 로직 분산 금지).
  • 합계 카드는 position:sticky로 긴 목록에서도 항상 보이게.
  • 수량 −는 1에서 disabled로 막아 0/음수 진입 차단.
용어: tabular-nums = 모든 숫자를 같은 폭으로 그리는 글꼴 기능. 금액이 바뀌어도 자리가 안 흔들린다. · sticky = 스크롤하다 특정 지점에서 화면에 고정되는 CSS position.

⌨️ OTP 인증번호 입력 — 세그먼트 vs 단일 필드 입력·폼

문자로 온 6자리 코드를 넣는 화면. 두 방식을 나란히: 칸을 나눈 세그먼트형(붙여넣기 자동 분배·자동 이동)과, 자동완성에 가장 강한 단일 필드형. 정답은 123456 — 넣어보면 통과/실패가 실제로 뜬다.

세그먼트형 (6칸)

붙여넣기(Ctrl/⌘+V) 하면 6칸에 자동 분배 · 입력하면 다음 칸 자동 이동 · ←→Backspace 이동

단일 필드형 (자동완성 강함)

autocomplete="one-time-code" 덕에 iOS/안드로이드가 문자 코드를 키보드 위에 제안 → 한 번 탭으로 채움. 한 칸이라 붙여넣기·자동완성이 가장 매끄럽다.

핵심 패턴 / 어느 쪽을 쓰나

  • 단일 필드가 자동완성·붙여넣기·폼 제출에 제일 유리(web.dev 권장). 세그먼트형은 예쁘지만 붙여넣기·자동완성을 직접 처리해줘야 한다.
  • 공통: type="text" + inputmode="numeric"(숫자 키패드) + autocomplete="one-time-code". type="number"는 증감 화살표가 생겨 부적합.
  • 세그먼트형은 코드를 "칸마다 상태"가 아니라 "하나의 문자열"로 관리하면 붙여넣기·삭제가 단순해진다.
용어: one-time-code = 브라우저에게 "이건 일회용 인증코드"라 알려 문자 자동완성을 켜는 autocomplete 값. · inputmode="numeric" = 모바일에서 숫자 키패드를 띄우는 힌트(값 검증은 아님).

🌀 CSS field-sizing: content — 입력값에 맞춰 자라는 입력창 트렌드·개념

JS로 scrollHeight 재서 높이 늘리던 오토그로우 textarea, 이제 CSS 한 줄로 끝난다. 입력·삭제해 보면 아래 필드가 내용에 맞춰 늘고 줄어든다. 오른쪽 "고정폭"과 비교해 보라.

칩은 글자 수에 딱 맞게 폭이 줄고 늘어난다(min/max로 한계만 지정).

같은 글을 넣어도 이쪽은 안 자란다 — 스크롤이 생기거나 잘린다.

지원 확인 중…

왜 지금 뜨나 / 어디에 쓰나

  • Chrome·Edge·Opera 123+에서 지원, Safari도 최신에 추가(2026-06 시점 "최신 브라우저 대부분에서 동작"). 다만 일부 널리 쓰는 브라우저 미지원이라 아직 완전한 Baseline은 아니다 — Firefox 미지원(추정).
  • 미지원 브라우저는 그냥 고정 크기로 렌더되므로 점진적 향상으로 안전하게 도입 가능(깨지지 않음).
  • 쓸 곳: 코멘트·사유 입력, 인라인 편집, 태그·칩 입력, 검색창처럼 "내용만큼만 커지면 좋은" 필드.
/* 예전: JS로 높이 계산 → 이제 CSS 한 줄 */
textarea {
  field-sizing: content;   /* 내용에 맞춰 크기 조절 */
  min-height: 2.6em;       /* 최소 */
  max-height: 12em;        /* 최대(넘으면 스크롤) */
}
.chip { field-sizing: content; min-width: 3ch; max-width: 180px; }
용어: field-sizing = input·textarea 등 폼 요소의 크기를 내용(content)에 맞출지 지정하는 CSS 속성. · Baseline = 주요 브라우저 전반에서 안전하게 쓸 수 있는 상태를 뜻하는 웹 표준 지표. · 점진적 향상 = 지원 브라우저엔 좋은 경험, 미지원엔 최소 동작을 보장하는 설계.
self-contained 라이브 예시 · ?embed=<섹션id> 로 데모만 컴팩트 렌더 · ?theme=dark 지원
