🪟 증빙 라이트박스 — 크게 보고, 넘기고, 제자리로 오버레이·모달·토스트

정산 증빙·영수증·계약서 스캔처럼 목록에 썸네일이 깔려 있고 눌러서 크게 보는 화면은 어디에나 있다. 그런데 대부분 <div>에 position:fixed만 덮어 만든다. 보기엔 똑같지만 키보드 사용자에겐 완전히 다른 물건이 된다. 아래 두 버튼으로 같은 목록을 두 가지 방식으로 열어 Tab을 눌러 보면 차이가 바로 보인다.

🧩 변형들 (요즘 패턴)

변형언제 쓰나 / 무엇이 다른가
A. div 오버레이 비권장 직접 포커스 트랩·inert·Esc·스크롤 잠금을 다 구현해야 한다. 하나라도 빠지면 접근성 결함. 레거시 브라우저 지원이 필요할 때만.
B. <dialog> + showModal() 기본값 포커스 트랩·배경 inert·Esc·::backdrop·최상위 레이어를 브라우저가 준다. 오늘의 데모가 이것.
C. 갤러리형(좌우 이동) 증빙이 여러 장일 때. 모달을 닫았다 다시 열지 않고 안에서 이동한다. "3 / 8" 카운터와 aria-live 안내가 필수.
D. 확대·팬 영수증 글씨가 작을 때. 버튼·키보드로도 확대되게 한다(핀치 줌만 두면 데스크톱·키보드 사용자가 못 씀).
E. 메타 패널 동반 이미지만 띄우지 말고 금액·거래일·업로더·상태를 같이. 증빙은 "보는 것"이 아니라 "대조하는 것"이라서.

💻 코드 (복붙용)

<!-- 1) 마크업: dialog 하나를 재사용하고 내용만 갈아끼운다 -->
<dialog id="lb" aria-labelledby="lbTitle">…</dialog>

<script>
let lastTrigger = null;          // 어떤 썸네일에서 열렸는지 기억 → 닫을 때 돌려준다

function open(index, trigger){
  lastTrigger = trigger;
  render(index);
  lb.showModal();                // ← showModal()이어야 포커스 트랩·::backdrop·Esc가 붙는다
                                 //    show()는 비모달이라 배경이 그대로 살아 있다
}

// 닫힐 때 포커스 복귀: close 이벤트는 Esc로 닫혀도 반드시 발생한다
lb.addEventListener('close', () => lastTrigger?.focus());

// 배경(백드롭) 클릭으로 닫기 — dialog 자신이 클릭 대상이면 바깥이다
lb.addEventListener('click', (e) => { if (e.target === lb) lb.close(); });

// 좌우 이동. dialog 안에서만 듣게 하면 전역 키 핸들러와 안 싸운다
lb.addEventListener('keydown', (e) => {
  if (e.key === 'ArrowRight') { go(+1); e.preventDefault(); }
  if (e.key === 'ArrowLeft')  { go(-1); e.preventDefault(); }
});
</script>
용어 한 줄 정의 · 포커스 트랩 = 모달이 열린 동안 Tab이 모달 안에서만 순환하는 것. inert = 그 요소와 자손을 클릭·포커스·스크린리더 대상에서 통째로 빼는 HTML 속성. 최상위 레이어(top layer) = z-index와 무관하게 항상 맨 위에 그려지는 브라우저 전용 레이어. showModal()로 연 <dialog>가 여기에 올라가서, 부모의 overflow:hidden이나 transform에 잘리지 않는다.

♿ 접근성·상태 설계

  • 포커스 복귀: 닫을 때 열었던 썸네일로 돌려준다. 안 그러면 포커스가 <body>로 떨어져 목록 맨 위부터 다시 Tab 해야 한다. close 이벤트 한 줄이면 된다.
  • 이동 안내: 좌우로 넘길 때 화면만 바뀌면 스크린리더 사용자는 아무것도 모른다. role="status"(= 조용한 aria-live="polite") 영역에 "3 / 5, 카드매출전표 2026-09-03"처럼 짧게 쓴다.
  • 확대는 키보드로도: +/− 키와 버튼을 같이 둔다. 확대 배율은 aria-label이 아니라 화면 텍스트로 보여줘야 저시력 사용자에게 의미가 있다.
  • 첫 포커스 위치: 닫기 버튼에 두는 게 안전하다. 사용자가 실수로 열었을 때 Enter 한 번으로 빠져나간다.
  • 모션: 확대 트랜지션은 prefers-reduced-motion(= OS의 "동작 줄이기" 설정)에서 끈다. 이 파일도 그렇게 했다.
  • 이미지 대체 텍스트: 증빙은 alt="영수증"으로 끝내지 말고 어떤 거래의 무엇인지를 적는다. 여기서는 <svg role="img"> + <title>로 넣었다.

🧠 paysable 적용 포인트

  • 정산 증빙 뷰어: 거래 상세에서 증빙 여러 장을 넘겨 보는 화면. 지금 모달을 닫았다 열어야 한다면 갤러리형(C)으로 바꿀 가치가 크다.
  • 대사(對査) 작업: 메타 패널(E)에 전표 금액 vs 시스템 금액을 나란히 두면 라이트박스가 곧 검증 도구가 된다.
  • <dialog>로 갈아타기: 기존 커스텀 오버레이가 있다면 껍데기만 <dialog>로 바꿔도 포커스 트랩 코드를 통째로 지울 수 있다. 다만 ::backdrop은 기존 오버레이 배경과 겹치지 않게 정리해야 한다.
  • 중첩 주의: 라이트박스가 이미 모달 안(예: 상세 시트)에서 열린다면 <dialog>를 두 번 showModal()해도 괜찮지만, 닫는 순서가 뒤집히지 않게 반드시 close 이벤트로 복귀 대상을 관리한다.

🔔 서비스 상태 배너 — 장애를 알리되 화면을 막지 않기 피드백·상태

결제는 남의 시스템이 자주 아프다. 특정 카드사 승인이 느려지고, PG 점검이 잡히고, 가끔은 전면 장애가 난다. 이때 "무엇을, 어떤 세기로, 어디에" 알릴지가 설계다. 토스트로 띄우면 1초 뒤 사라져 못 보고, 모달로 막으면 멀쩡한 다른 결제수단까지 못 쓴다. 상태 배너는 그 사이의 답이다.

🧩 변형 A — 심각도 5단계 (닫기 동작함)

색만 다른 게 아니라 닫을 수 있는지가 다르다. 정보·복구는 닫기 허용, 진행 중 장애는 닫기 없음(끝나면 스스로 사라진다).

🧩 변형 B — 상태가 결제 화면 전체를 어떻게 바꾸는가 (시나리오 재생)

paysable — 결제하기
결제수단 선택

카드 승인까지 보통 2~3초 걸립니다.

상태가 바뀌면 배너만 바뀌는 게 아니다 — 해당 결제수단 행이 비활성되고, 선택돼 있었다면 자동 해제되고, 제출 버튼 문구와 안내가 같이 바뀐다. 배너를 "장식"으로 두면 사용자는 장애 난 수단을 계속 고른다.

🧩 변형들 (요즘 패턴)

알림 그릇언제주의
토스트내가 방금 한 행동의 결과(저장됨, 취소됨)몇 초 뒤 사라진다 → 지속되는 상태를 담으면 안 된다.
인라인 배너 오늘 주제지금 이 화면에 영향을 주는 지속 상태화면을 막지 않되, 영향받는 영역 바로 위에 둔다.
전역 상단 바앱 전체에 걸린 상태(점검 예고, 오프라인)여러 개 겹치면 콘텐츠가 밀린다. 동시에 1개 원칙.
인라인 필드 에러특정 입력이 틀렸을 때서비스 장애를 필드 에러로 쓰면 사용자가 자기 잘못인 줄 안다.
모달계속 진행하면 돈이 잘못되는 경우만남용하면 사용자는 읽지 않고 닫는다.

💻 코드 (복붙용)

<!-- 심각도에 따라 role이 달라진다. 이게 핵심이고 색은 부차적이다. -->

<!-- 정보·예고·복구: 조용히 알림. 사용자가 읽던 흐름을 끊지 않는다 -->
<div class="banner sched" role="status">…</div>

<!-- 진행 중 장애: 즉시 읽어줘야 함 -->
<div class="banner major" role="alert">…</div>

<script>
// 닫기 정책: "닫을 수 있는가"는 심각도가 결정한다
const DISMISSIBLE = { info:true, sched:true, slow:true, partial:false, major:false, fixed:true };

// 닫은 배너를 기억하되 "그 사건"에 대해서만 기억한다.
// incidentId를 안 쓰고 종류로만 기억하면, 다음 장애가 났을 때도 영원히 안 보인다.
function dismiss(incidentId){
  const seen = JSON.parse(sessionStorage.getItem('seenIncidents') || '[]');
  sessionStorage.setItem('seenIncidents', JSON.stringify([...seen, incidentId]));
}

// 상태 변경은 배너만 갈아끼우지 말고, 영향받는 컨트롤까지 함께 바꾼다
function applyStatus(s){
  renderBanner(s);
  for (const m of methods) m.disabled = s.downMethods.includes(m.id);
  if (s.downMethods.includes(selected)) selected = null;   // 고른 수단이 죽었으면 해제
  payBtn.disabled = (selected === null);
}
</script>
용어 한 줄 정의 · role="status" = 스크린리더가 지금 읽던 문장을 끊지 않고 끝난 뒤 읽어주는 영역(= aria-live="polite"). role="alert" = 즉시 끼어들어 읽는 영역(= aria-live="assertive"). 남용하면 화면 낭독이 계속 끊긴다. 부분 장애(partial outage) = 서비스 전체가 아니라 특정 기능·특정 결제수단만 안 되는 상태.

♿ 접근성·상태 설계

  • role을 심각도에 맞춘다: 점검 예고까지 alert로 주면 스크린리더 사용자는 페이지에 들어올 때마다 낭독이 끊긴다. 진행 중 장애만 alert.
  • 색만으로 구분하지 않기: 주황/빨강 배경 대신 아이콘 + 제목 문구("일부 지연", "결제 불가")로도 구분되게. 색각 이상 사용자와 흑백 출력 화면 모두를 위해서다.
  • 닫기의 기억 범위: sessionStorage에 사건 ID로 기억한다. "점검 배너"라는 종류로 기억하면 다음 달 점검 때도 안 보인다.
  • 배너가 바뀔 때 포커스는 옮기지 않는다: 사용자가 입력 중일 수 있다. 포커스 이동은 사용자가 스스로 한 행동(제출 실패 등)에만.
  • 시간은 사용자 시간대로: "오늘 새벽 2시~4시"처럼 절대 시각을 쓰되 타임존을 명시한다("KST"). 서버 UTC 문자열을 그대로 뿌리는 사고가 흔하다.
  • 막다른 길 금지: 장애 배너에는 항상 다음 행동을 준다 — 다른 결제수단, 상태 페이지 링크, "복구되면 알림받기".

🧠 paysable 적용 포인트

  • 결제수단별 헬스 상태: PG·카드사 단위 상태를 API로 받아 결제수단 행에 인라인으로 표시하면, 사용자가 죽은 수단을 고르고 실패하는 경로가 사라진다. 실패 후 안내보다 선택 전 안내가 늘 싸다.
  • 점검 예고 배너: 정산·출금처럼 시간에 민감한 화면에 특히 필요하다. "오늘 02:00~04:00 KST 출금 신청 불가" 한 줄이 CS 문의를 줄인다.
  • 복구 배너는 짧게 살렸다 지운다: 복구(fixed)는 닫기 허용 + 자동 만료(예: 30분)로 두면 "언제까지 떠 있어야 하나" 논쟁이 사라진다.
  • 배너 개수 상한: 동시에 2개까지, 심각도 높은 순. 배너가 3개 쌓이면 사용자는 전부 무시한다(경보 피로).

🌀 appearance: base-select — 네이티브 select를 드디어 CSS로 트렌드·개념

프론트엔드에서 가장 오래된 타협 중 하나가 <select>다. 드롭다운 목록은 OS가 그리기 때문에 글꼴·색·아이콘 어느 것도 CSS가 닿지 않았다. 그래서 다들 div로 커스텀 콤보박스를 만들고, 키보드·ARIA·모바일 대응을 처음부터 다시 짰다. appearance: base-select는 그 목록을 브라우저가 그리되 CSS가 꾸미는 요소 트리로 바꾼다. 네이티브의 접근성은 그대로 두고 모양만 가져오는 것.

🧩 변형 A·B — 같은 결제수단 목록, 네이티브 vs base-select

A. 기본 <select> 모든 브라우저

텍스트 한 줄이 전부다. 카드 로고도, 두 줄 배치도, 잔액 강조도 불가능하다.

B. appearance: base-select 지원 확인 중…

지원 브라우저에서는 로고·2줄 정보·체크 표시가 붙은 목록이 열리고, 미지원 브라우저에서는 평범한 네이티브 select로 그대로 동작한다(폴백).

브라우저 지원 확인 중…

📈 왜 지금 뜨나 / 어디에 쓰나

  • 커스텀 콤보박스의 비용이 너무 컸다: div로 만든 드롭다운은 키보드 탐색, 타이핑 점프, aria-activedescendant, 모바일 가상 키보드, 스크롤 락을 전부 직접 짜야 한다. 라이브러리를 써도 버전 업마다 회귀 버그가 났다.
  • 브라우저가 그리되 CSS가 꾸민다: appearance: base-select를 select와 ::picker(select) 양쪽에 걸면, 목록이 OS 위젯이 아니라 스타일 가능한 요소 트리로 바뀐다. <option> 안에 span·아이콘 같은 실제 HTML을 넣을 수 있다.
  • 같이 딸려오는 것들: ::picker-icon(화살표), ::checkmark(선택 표시), <selectedcontent>(선택된 옵션의 내용을 버튼에 그대로 복제), :open 의사클래스. 목록 열림 애니메이션은 @starting-style + transition-behavior: allow-discrete로 붙인다.
  • 지원 현황(2026-09 기준, 검색 확인): Chrome·Edge에서 안정 버전에 들어가 있고, Safari는 Technology Preview, Firefox는 플래그 뒤 프로토타입 단계다. Baseline(전 엔진 안정 지원) 아님. 다만 미지원 브라우저는 규칙을 무시하고 네이티브 select로 남으므로 점진적 향상(progressive enhancement)으로 오늘 바로 쓸 수 있다. — 세부 버전은 실제 프로젝트에서 재확인 권장(추정 포함).
  • 어디에 먼저: 옵션에 보조 정보가 필요한 선택 — 결제수단(로고+마스킹번호+한도), 통화(국기+코드+이름), 정산 계좌, 국가·시간대. 반대로 옵션이 텍스트 한 줄이면 그냥 네이티브로 두는 게 낫다.

💻 코드 (복붙용)

/* 1) select와 picker 양쪽에 걸어야 base 모드로 들어간다 */
select.rich,
select.rich::picker(select) { appearance: base-select; }

/* 2) 이제 평범한 CSS가 먹는다 */
select.rich::picker(select){
  border-radius: 12px; box-shadow: 0 6px 24px rgb(0 0 0 / .12); padding: 6px;

  /* 열림/닫힘 애니메이션: display가 바뀌는 요소라 두 가지가 더 필요하다 */
  opacity: 0;
  transition: opacity .14s, overlay .14s allow-discrete, display .14s allow-discrete;
}
select.rich:open::picker(select){ opacity: 1; }
@starting-style { select.rich:open::picker(select){ opacity: 0; } }

select.rich option:checked{ background: #eef0fe; color: #4f46e5; }
select.rich option::checkmark{ order: 99; margin-left: auto; }  /* 선택 표시를 오른쪽으로 */
select.rich::picker-icon{ transition: transform .15s; }
select.rich:open::picker-icon{ transform: rotate(180deg); }

/* 3) 지원 여부로 분기하고 싶을 때 */
@supports (appearance: base-select){ /* 향상된 스타일만 여기에 */ }
<!-- 마크업: 버튼과 selectedcontent는 base 모드에서만 의미가 있고,
     미지원 브라우저는 이 둘을 무시하고 option 텍스트만 쓴다 -->
<select class="rich">
  <button type="button"><selectedcontent></selectedcontent></button>
  <option value="visa">
    <span class="cardmark visa">VISA</span>
    <span class="optmain"><span class="t">신한카드</span><span class="s">···4291</span></span>
  </option>
</select>
용어 한 줄 정의 · appearance = 폼 요소를 OS 기본 위젯으로 그릴지 여부를 정하는 CSS 속성(기존엔 none으로 껍데기만 벗길 수 있었다). ::picker(select) = 열렸을 때 나타나는 목록 팝업을 가리키는 의사요소. <selectedcontent> = 선택된 option의 내용을 버튼 자리에 자동 복제해 주는 요소. 점진적 향상 = 최신 기능을 아는 브라우저에만 더 좋은 경험을 주고, 모르는 브라우저는 기본 동작으로 두는 전략.

♿ 접근성·상태 설계

  • 접근성은 공짜로 유지된다: 여전히 <select>라서 라벨 연결, 키보드 탐색, 폼 제출, :required·유효성 검사가 그대로 동작한다. 커스텀 콤보박스에서 가장 자주 깨지던 부분이다.
  • 옵션 안 HTML은 장식만: 스크린리더는 대체로 옵션의 텍스트를 읽는다. 아이콘에만 의미를 담지 말고 텍스트로도 같은 정보를 둔다(여기서는 "신한카드 ···4291").
  • 대비 직접 챙기기: OS 위젯일 땐 브라우저가 대비를 보장했지만, 이제 내가 칠한 색이 그대로 나간다. 선택 상태(option:checked) 대비를 특히 확인한다.
  • 모션 끄기: 열림 애니메이션은 prefers-reduced-motion에서 제거한다(이 파일도 적용).
  • 미지원 경로를 실제로 보기: 스타일을 짤 때 Firefox/Safari 안정 버전에서 한 번은 열어 본다. "지원 브라우저에서만 예쁘고 나머지에선 깨짐"이 가장 흔한 사고다.

🧠 paysable 적용 포인트

  • 결제수단 드롭다운: 라디오 카드 그룹을 쓸 공간이 없는 좁은 화면에서, 카드 로고·마스킹 번호·한도를 한 줄에 담을 수 있다. 커스텀 콤보박스를 새로 만들 이유가 하나 줄어든다.
  • 통화·국가 선택: 옵션이 200개인 목록에서 커스텀 구현은 가상 스크롤까지 필요했지만, 네이티브는 브라우저가 알아서 한다.
  • 도입 순서: ① 기존 커스텀 콤보박스 중 단일 선택 + 검색 불필요한 것부터 후보로 올린다(검색·다중선택이 필요하면 여전히 콤보박스 영역). ② @supports로 감싸 향상 스타일만 넣는다. ③ 네이티브 폴백 모양을 QA 체크리스트에 명시한다.
  • 남길 것: 자동완성이 필요한 칸(은행 검색 등)은 이 기능의 대상이 아니다. select는 여전히 "정해진 목록에서 하나 고르기"용이다.
