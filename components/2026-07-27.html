⌨️ 파일 업로드 드롭존 — 끌어다 놓기·진행률·용량 검증 입력·폼

드롭존(dropzone)은 파일을 끌어다 놓거나 클릭해서 올리는 입력 영역입니다. 결제 도메인에선 정산 증빙, 사업자등록증, 세금계산서 업로드에 매일 씁니다. 아래 데모는 드래그 하이라이트, 다중 선택, 파일별 진행률, 용량·형식 검증 에러, 삭제를 담았고, 마우스 없이도 올릴 수 있게 클릭·키보드로 파일 선택을 지원합니다. 진짜 서버는 없어 업로드는 흉내만 냅니다.

📎
파일을 여기로 끌어다 놓거나 눌러서 선택
JPG · PNG · PDF · 각 5MB 이하 · 여러 개 가능

    🧩 변형들 (요즘 패턴)

    • 드래그 하이라이트 — 파일이 위에 올라오면 테두리·배경을 바꿔 "여기 놓으면 된다"를 알립니다.
    • 파일별 진행률 — 여러 파일을 각각의 바로 보여 줘, 하나가 느려도 전체가 멈춘 것처럼 보이지 않습니다.
    • 즉시 검증 — 용량·형식을 올리는 즉시 확인해 잘못된 파일은 붉게 표시하고 이유를 붙입니다.
    • 클릭·키보드 대체 — 드래그만 강요하지 않고, 눌러서 OS 파일창을 여는 길을 항상 함께 둡니다.

    💻 코드 (핵심 — 드롭 처리 + 검증)

    const MAX = 5 * 1024 * 1024;               // 5MB
const OK  = ['image/jpeg','image/png','application/pdf'];

dz.addEventListener('dragover', (e) => { e.preventDefault(); dz.classList.add('over'); });
dz.addEventListener('dragleave', () => dz.classList.remove('over'));
dz.addEventListener('drop', (e) => {
  e.preventDefault(); dz.classList.remove('over');
  handle(e.dataTransfer.files);            // 끌어다 놓은 파일
});
function handle(fileList){
  for (const f of fileList){
    if (!OK.includes(f.type)) return addError(f, '지원하지 않는 형식');
    if (f.size > MAX)         return addError(f, '5MB를 넘음');
    upload(f);                             // 통과 → 업로드
  }
}

    ♿ 접근성·상태 설계

    • 드롭존 자체를 role="button" + tabindex="0"로 만들어 Enter/Space로 파일창을 열 수 있게 합니다.
    • 진행·완료·에러는 aria-live 영역에 텍스트로도 알려 스크린리더가 읽게 합니다.
    • 에러는 색만이 아니라 아이콘·문구로도 구분(색맹 대비). 삭제 버튼엔 aria-label.
    • 업로드 중 취소·재시도 경로를 제공하는 걸 권장(느린 네트워크 대비).

    🧠 paysable 적용 포인트

    가맹점 심사·정산 증빙·세금계산서 업로드가 전형적입니다. 특히 용량/형식 즉시 검증과 파일별 진행률은 반려·재업로드를 줄여 CS 문의를 낮춥니다. 서버 검증은 반드시 별도로(클라이언트 검증은 UX용일 뿐 보안 경계 아님).

    🔗 참고: HTML <input type="file"> + Drag and Drop API(MDN). 이 데모는 외부 라이브러리 없이 self-contained로 구현.

    🔘 수량 스텝퍼 — +/− 버튼·길게 눌러 가속·경계 클램프 버튼·액션

    수량 스텝퍼(number stepper)는 −/＋ 버튼과 숫자 입력으로 값을 조금씩 바꾸는 컨트롤입니다. (여러 단계로 진행 상황을 보여 주는 "스텝퍼/진행 표시"와는 다릅니다.) 결제에선 주문 수량, 할부 개월수, 인원 같은 데 씁니다. 아래는 최소·최대 클램프, 경계에서 버튼 비활성, 길게 누르면 가속 반복, 직접 타이핑 후 보정을 담았습니다.

    주문 수량

    1 ~ 99 · 1씩 · 길게 누르면 빨라짐

    합계: ₩12,900 (개당 ₩12,900)

    할부 개월

    1 ~ 24개월 · 경계에서 버튼 잠김

    3개월 할부 · 월 ₩4,300

    🧩 변형들 — 놓치기 쉬운 것

    • 경계 클램프 + 버튼 비활성 — 최소/최대에 닿으면 값이 넘어가지 않고, 해당 버튼을 disabled로 잠가 헛클릭을 막습니다.
    • 길게 눌러 가속(press-and-hold) — 오래 누르면 반복 속도가 빨라져 큰 값도 빠르게. 뗄 때 멈춥니다.
    • 직접 입력 보정 — 타이핑으로 범위를 벗어나면 blur·Enter 시 최소/최대로 되돌립니다(빈 값도 처리).
    • 스피너 숨김 — 브라우저 기본 숫자 화살표를 없애 커스텀 버튼과 겹치지 않게.

    💻 코드 (핵심 — 클램프 + 길게 눌러 반복)

    const clamp = (v) => Math.min(max, Math.max(min, v));
function set(v){
  v = clamp(v || min);
  input.value = v;
  dec.disabled = v <= min;      // 경계에서 버튼 잠금
  inc.disabled = v >= max;
  render(v);
}
// 길게 누르면 점점 빨라지는 반복
function hold(dir){
  let delay = 300;
  const run = () => {
    set(+input.value + dir * step);
    delay = Math.max(40, delay * 0.8);   // 가속
    timer = setTimeout(run, delay);
  };
  run();
}
btn.addEventListener('pointerdown', () => hold(+1));
addEventListener('pointerup', () => clearTimeout(timer));

    ♿ 접근성·상태 설계

    • −/＋ 버튼엔 명확한 aria-label("수량 1 늘리기"). 값은 실제 <input>이라 스크린리더가 읽습니다.
    • inputmode="numeric"로 모바일에서 숫자 키패드를 띄웁니다.
    • 경계에서 disabled로 잠가 "왜 안 눌리지?"를 시각·의미 양쪽으로 전달.
    • 키보드 ↑↓로도 증감(네이티브 number가 아니면 직접 핸들링).

    🧠 paysable 적용 포인트

    주문 수량·인원·할부 개월처럼 "정해진 범위에서 조금씩 바꾸는" 값에 씁니다. 값이 바뀔 때 합계·월 납입액을 즉시 다시 계산해 보여 주면(위 데모처럼) 사용자가 선택의 결과를 바로 이해합니다.

    🔗 참고: 자유 입력 필드보다 스텝퍼가 오입력을 줄입니다. 단, 값 범위가 아주 넓으면(예: 금액) 스텝퍼보다 직접 입력이 낫습니다.

    🌀 커스터마이즈 셀렉트 — 네이티브 select를 CSS로 직접 꾸미기 트렌드·개념

    지금까지 <select>의 펼침 목록은 CSS로 거의 못 꾸며서, 다들 JS로 가짜 드롭다운을 만들었습니다(접근성·키보드를 다시 구현해야 함). 새 표준 appearance: base-select는 진짜 네이티브 select를 그대로 두고 펼침 목록·옵션·체크표시·화살표까지 CSS로 꾸미게 해 줍니다. 접근성·키보드는 브라우저가 공짜로 유지합니다. 아래 셀렉트를 열어 보세요(지원 브라우저면 옵션에 색점·체크표시가 보입니다).

    지원 여부 확인 중…

    📈 왜 지금 뜨나 / 어디에 쓰나

    • Chrome/Edge 135+에서 안정 지원, Safari는 Technology Preview, Firefox는 Nightly 플래그 단계 — 아직 실험적이라 폴백 전제로 씁니다(2026년 기준, 배포 전 재확인 권장).
    • 미지원 브라우저는 base-select를 그냥 무시하고 기본 select로 렌더 → 점진적 향상(progressive enhancement)에 안전합니다.
    • 그동안 JS 커스텀 드롭다운에서 새로 짜야 했던 키보드 이동·타입어헤드·스크린리더를 브라우저가 유지해 줘 코드·버그가 줍니다.

    💻 코드 (복붙용)

    /* select와 그 펼침 목록을 '꾸밀 수 있는 모드'로 전환 */
select, ::picker(select){ appearance: base-select; }

::picker(select){                 /* 펼쳐지는 목록 상자 */
  border:1px solid #e2e6ec; border-radius:12px; padding:6px;
}
option{ border-radius:8px; padding:9px 11px; }
option:hover{ background:#eef0fe; }
option::checkmark{ color:#4f46e5; }   /* 선택된 항목의 체크표시 */
select::picker-icon{ transition:transform .2s; }
select:open::picker-icon{ transform:rotate(180deg); }  /* 열리면 화살표 회전 */

    ♿ 접근성·상태 설계

    • 핵심 장점이 접근성 유지입니다 — 네이티브 select라 키보드·타입어헤드·모바일 롤러가 그대로 동작.
    • 옵션 안에 아이콘·색점을 넣더라도 텍스트 라벨을 함께 둬 의미를 색에만 의존하지 않게.
    • 미지원 환경에서도 값 선택은 문제없어야 하므로, 커스텀 스타일은 "있으면 좋은" 향상으로만 설계.

    🧠 paysable 적용 포인트

    정산 주기·통화·결제수단처럼 옵션이 정해진 선택에서, 그동안 유지비 크던 JS 커스텀 드롭다운을 네이티브 + CSS로 대체할 여지가 생깁니다. 다만 아직 실험적이라 지금은 폴백 필수 — 미지원 브라우저에서 기본 select로 멀쩡히 동작하는지 반드시 확인하세요.

    🔗 참고: Chrome for Developers — Customizable select, CSS-Tricks / modern-css. 브라우저 지원은 빠르게 바뀌므로 배포 전 caniuse 재확인 권장.
