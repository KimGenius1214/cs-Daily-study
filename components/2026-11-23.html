하단 고정 결제 버튼 — 금액은 버튼 문장에, 마지막 내용과 포커스는 가리지 않게, 키보드가 뜨면 접기 🔘 버튼·액션

모바일 체크아웃의 "38,500원 결제하기" 바. position:fixed로 띄우면 맨 아래 약관 체크박스와 포커스된 입력칸이 바 뒤에 숨는다. 바를 스크롤 영역 안의 position:sticky로 두고, scroll-padding-bottom(스크롤해 보여줄 때 아래쪽에 비워 둘 여백)을 바 높이만큼 주면 둘 다 해결된다.

⌨️ 가상 키보드

버튼 문장에 금액을 넣으면 "얼마가 빠져나가는지"를 누르기 직전에 다시 읽는다. 쿠폰을 바꾸면 금액이 바뀌고 낭독기엔 한 번만 알린다. 동의 전에도 버튼은 disabled 대신 aria-disabled라 눌러 볼 수 있고, 누르면 이유를 말하고 체크박스로 포커스를 옮긴다.

키보드 흉내를 켜면 오른쪽은 요약을 접고 버튼만 남긴다. 화면이 절반으로 줄었을 때 바가 입력칸을 덮지 않게 하기 위해서다.

/* 바는 스크롤 영역 '안'의 마지막 자식 */
.checkout-scroll { overflow:auto; scroll-padding-bottom: calc(var(--bar-h) + 12px); }
.pay-bar {
  position: sticky; bottom: 0;
  padding-bottom: max(12px, env(safe-area-inset-bottom)); /* 홈 인디케이터 */
}
/* <meta name="viewport" content="..., viewport-fit=cover"> 가 있어야 env()가 0이 아님 */

// 동의 전: disabled 대신 aria-disabled + 이유 안내
payBtn.addEventListener('click', () => {
  if (payBtn.getAttribute('aria-disabled') === 'true') {
    why.textContent = '결제 동의에 체크해야 결제할 수 있어요';
    agree.focus(); return;
  }
  submitPayment();
});

사업자등록번호 입력 — 하이픈은 보여주기만, 체크섬은 오타 거르기일 뿐, 진위·휴폐업은 조회로 ⌨️ 입력·폼

검사 타이밍: 입력 중엔 개수만 보여 주고, 10자리가 다 찼을 때(입력이 끝났다는 신호) 체크섬을 본다. 10자리 미만에서 칸을 떠나면 그때 "n자리 입력됐어요"라고 말한다.

조회 중에 번호를 고치면 늦게 온 옛 응답은 버린다(요청 번호 비교). 조회 결과는 번호에 묶여 있어, 번호를 바꾸면 결과도 지운다.

const W = [1,3,7,1,3,7,1,3,5];
export function isBizNoChecksumOk(raw: string) {
  const d = raw.replace(/\D/g, '');
  if (d.length !== 10) return false;
  const n = [...d].map(Number);
  let sum = W.reduce((s, w, i) => s + n[i] * w, 0);
  sum += Math.floor((n[8] * 5) / 10);           // 9번째 자리 × 5 의 십의 자리
  return (10 - (sum % 10)) % 10 === n[9];
}
// 표시용: 3-2-5. 저장·전송은 항상 숫자 10자리
const fmt = (d: string) => d.length <= 3 ? d
  : d.length <= 5 ? `${d.slice(0,3)}-${d.slice(3)}`
  : `${d.slice(0,3)}-${d.slice(3,5)}-${d.slice(5)}`;

interpolate-size와 ::details-content — height:auto로 여닫는 애니메이션을 JS 측정 없이 🌀 트렌드·개념

지금까진 height: 0 → auto가 애니메이션되지 않아 scrollHeight를 재서 px로 넣거나 grid-template-rows: 0fr → 1fr 꼼수를 썼다. interpolate-size: allow-keywords를 루트에 한 줄 두면 auto·fit-content 같은 크기 키워드로도 전환이 된다. ::details-content는 <details>의 펼쳐지는 부분을 가리키는 가상 요소라, 아코디언을 JS 없이 부드럽게 만들 수 있다.

FAQ 아코디언 — 같은 내용, 두 방식

A. details + ::details-content (JS 0줄)

정산은 언제 들어오나요?
카드 결제는 승인일 기준 영업일 D+2에 등록하신 정산 계좌로 입금돼요. 공휴일이 끼면 하루씩 밀려요.
부분 환불도 되나요?
네. 거래 상세에서 환불 가능 잔액 안에서 여러 번 나눠 환불할 수 있어요. 수수료는 환불 비율만큼 돌려드려요. 긴 답변일수록 열리는 높이가 커지는데, 높이를 미리 몰라도 auto까지 자연스럽게 늘어나요.
영수증은 어디서 받나요?
결제 완료 화면과 거래 상세의 "영수증" 버튼에서 받을 수 있어요.

같은 name을 준 details는 하나만 열린다(배타적 아코디언). 미지원 브라우저는 그냥 즉시 열리고 닫힐 뿐 — 기능은 그대로다.

닫힌 패널은 높이만 0이라 안쪽 링크에 Tab이 들어간다 → inert로 막아야 한다. 버튼·aria-expanded·inert를 직접 관리해야 하는 게 이 방식의 비용.

이 브라우저의 지원 여부

Chromium 129+에서 interpolate-size, 131+에서 ::details-content가 들어온 것으로 알려짐. Safari·Firefox의 interpolate-size 지원은 2026-11 기준 미확인(추정: 미지원) — 그래서 "있으면 부드럽게, 없으면 즉시"로 쓰는 점진적 향상용이다.

:root { interpolate-size: allow-keywords; }   /* 상속됨 → 루트 한 번이면 끝 */

details::details-content {
  block-size: 0;
  overflow: clip;
  transition: block-size .35s ease,
              content-visibility .35s allow-discrete; /* 닫힐 때도 끝까지 보이게 */
}
details[open]::details-content { block-size: auto; }

@media (prefers-reduced-motion: reduce) {
  details::details-content { transition: none; }
}
/* 특정 요소만: height: calc-size(auto, size) 로 키워드 + 계산도 가능 */
