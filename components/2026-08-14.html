📊 인라인 편집 테이블 + 행 확장 데이터·테이블

정산표처럼 값이 자주 바뀌는 표는, 별도 편집 화면으로 가는 대신 셀을 그 자리에서 고치고(inline edit) 필요할 때만 행을 펼쳐 상세를 본다. 화면 전환·왕복을 없애 수정 속도를 높이는 요즘의 데이터 그리드 패턴이다.

펼치기 가맹점 금액 상태

셀을 클릭하거나 Tab으로 이동해 값을 고치세요. Enter 또는 포커스 아웃 시 저장(합계 자동 반영). ▸ 버튼(또는 Enter)으로 행을 펼쳐 상세를 봅니다.

합계 —저장됨 ✓

🧩 변형들 (요즘 패턴)

  • 인라인 셀 편집 — contenteditable 또는 셀 안 input. "저장" 버튼 없이 blur/Enter로 커밋하고 작은 "저장됨 ✓" 플래시로 확인.
  • 행 확장(expandable row) — 표는 요약만, 세부(수수료·승인번호·타임스탬프)는 펼쳤을 때만. 열을 무한정 늘리지 않는 밀도 관리법.
  • 숫자 우측 정렬 + tabular-nums — 자릿수를 세로로 맞춰 금액 비교가 쉬워진다.

💻 코드 (복붙용)

<!-- 편집 가능한 셀: contenteditable + inputmode -->
<td class="num">
  <span class="cell-edit" contenteditable="true"
        inputmode="decimal" role="textbox" aria-label="금액">12,000</span>
</td>

// Enter는 줄바꿈 대신 커밋(blur)
cell.addEventListener("keydown", e => {
  if (e.key === "Enter") { e.preventDefault(); cell.blur(); }
});
cell.addEventListener("blur", () => { commit(cell); flashSaved(); });

♿ 접근성·상태 설계

  • 편집 셀에 role="textbox"·aria-label. 숫자는 inputmode="decimal"로 모바일 키패드 유도. inputmode: 화면 키보드 종류 힌트.
  • 확장 토글은 <button aria-expanded>로, 상세 영역은 role="region". 접힘/펼침을 보조기기가 읽는다.
  • 펼침 애니메이션은 prefers-reduced-motion에서 끔. prefers-reduced-motion: 사용자가 OS에서 "동작 줄이기"를 켠 상태.

🧠 paysable 적용 포인트

정산·환불 관리 표에서 상담원이 금액/메모를 그 자리에서 고치게 하면 화면 왕복이 준다. 단, 결제 금액 같은 민감 필드는 인라인 편집 후 서버 검증 + 낙관적 UI 롤백을 붙이고, 확장 행에 승인번호·PG 응답코드를 담아 감사(audit) 흐름을 한 화면에서 처리한다.

🔔 실행 취소 토스트 (Undo Snackbar) 피드백·상태

"정말 삭제할까요?" 모달로 매번 막는 대신, 먼저 실행하고 잠깐 되돌릴 기회를 준다. 삭제하면 항목은 바로 사라지지만 하단 스낵바에 실행 취소 버튼과 카운트다운이 뜬다. 확인 클릭 수를 줄이면서도 안전한, 요즘 표준 패턴이다.

모든 항목이 삭제됐습니다. 스낵바의 실행 취소로 되돌리거나 아래 버튼으로 초기화하세요.

항목을 삭제했습니다

🧩 변형들 (요즘 패턴)

  • Undo 스낵바 — 삭제 직후 되돌리기. 카운트다운 바가 끝나면 실제 커밋(서버 반영).
  • 단일 슬롯 — 연속 삭제 시 이전 스낵바는 즉시 커밋하고 새 것만 표시. 스낵바가 쌓여 화면을 덮지 않게.
  • aria-live로 안내 — 스낵바 등장 문구를 스크린리더가 자동 낭독(role="status").

💻 코드 (복붙용)

let pending = null;                 // {item, timer}
function remove(item){
  commitPrevious();                 // 이전 삭제는 확정
  item.el.remove();                 // 화면에서 즉시 제거(낙관적)
  pending = { item, timer:setTimeout(commitPrevious, 5000) };
  showSnack("삭제했습니다");
}
function undo(){                     // 실행 취소
  clearTimeout(pending.timer);
  restore(pending.item);            // DOM 복원
  pending = null; hideSnack();
}
function commitPrevious(){           // 카운트다운 종료 → 서버 반영
  if(!pending) return;
  api.delete(pending.item.id);
  pending = null; hideSnack();
}

♿ 접근성·상태 설계

  • 스낵바는 role="status" + aria-live="polite". 포커스를 강제로 뺏지 않으면서 알린다. aria-live: 영역 내용이 바뀌면 보조기기가 읽어줌.
  • 키보드로도 실행 취소 가능해야 함 — 버튼에 도달 가능하고 Enter로 눌림.
  • 카운트다운 바 애니메이션은 prefers-reduced-motion에서 즉시 완료 상태로.

🧠 paysable 적용 포인트

거래 숨김·메모 삭제·필터 초기화처럼 되돌릴 수 있는 액션에 적합. 반대로 환불 실행·정산 확정처럼 비가역·금전 이동은 확인 모달을 유지한다. 낙관적 제거 + 5초 유예로 UX를 매끄럽게 하되, 유예 종료 시점에만 실제 API를 호출해 서버 부하와 롤백 복잡도를 줄인다.

🌀 View Transitions API 트렌드·개념

View Transitions API는 DOM이 바뀌기 전/후 상태를 브라우저가 알아서 스냅샷으로 잡아 부드럽게 교차(morph)시켜 주는 표준 API다. 예전엔 Framer Motion 같은 라이브러리로 하던 리스트→상세 전환을, 이제 CSS와 짧은 JS로 처리한다.

상품명

설명

카드를 클릭하면 썸네일이 상세 뷰로 이어져 커지는 전환이 실행됩니다(지원 브라우저). "전환 애니메이션: 끔"으로 비교해 보세요.

📈 왜 지금 뜨나 / 어디에 쓰나

  • 같은 문서(SPA) 전환은 Chrome/Edge 111+, Safari 18+, 그리고 최근 Firefox 버전에서 지원(정확 버전은 브라우저별 상이 — 배포 전 caniuse 확인 권장, 추정).
  • 문서 간(MPA) 전환은 Chromium 계열이 앞서 있고 Safari·Firefox는 아직 제한적(2026 진행 중, 추정). 그래서 점진적 향상으로 쓴다 — 미지원 시 애니메이션 없이 즉시 교체.
  • 리스트→상세, 탭 전환, 좋아요 토글 등 "같은 요소가 위치·크기만 바뀌는" 장면에 특히 잘 맞는다.

💻 코드 (복붙용)

// 점진적 향상: 미지원이면 그냥 콜백만 실행
function withTransition(update){
  if (!document.startViewTransition) { update(); return; }
  document.startViewTransition(update);   // 스냅샷 → DOM 변경 → 교차 애니메이션
}

// 이어지는 요소는 같은 이름을 부여 → 브라우저가 morph
// (리스트 썸네일과 상세 썸네일에 동일 이름)
.thumb-active { view-transition-name: vt-hero; }

// 동작 줄이기 존중
@media (prefers-reduced-motion: reduce){
  ::view-transition-group(*){ animation: none; }
}

♿ 접근성·상태 설계

  • 전환은 장식이다 — 미지원/저사양에서도 콘텐츠 접근에 지장이 없어야 하고, 실제로 startViewTransition이 없으면 즉시 교체된다.
  • prefers-reduced-motion에서 ::view-transition-group 애니메이션을 꺼 어지럼을 방지.
  • 포커스 관리는 별개 — 상세로 갈 때 제목/뒤로가기에 포커스를 옮겨 키보드 흐름을 유지.

🧠 paysable 적용 포인트

거래 리스트 → 거래 상세, 카드 목록 → 카드 관리처럼 같은 카드가 확대되는 흐름에 적용하면 맥락 유지가 좋아진다. Next.js(App Router) 환경에선 라우트 전환에 얹을 수 있으나 브라우저 지원 편차가 있으니 필수 기능이 아닌 향상으로만 쓰고, 미지원 시 동일하게 동작하는지 반드시 회귀 확인.
