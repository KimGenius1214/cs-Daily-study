📊 필터 툴바와 활성 필터 칩 패싯 · 칩 · 결과 없음

정산표처럼 행이 많은 표에서 진짜 어려운 건 표 자체가 아니라 "지금 뭘로 걸러진 상태인지"를 보여주는 일입니다. 요즘 패턴은 셋으로 정리됩니다 — ① 툴바에 필터 컨트롤을 모으고, ② 걸린 조건을 칩(chip)으로 표 위에 늘어놓고, ③ 각 옵션 옆에 패싯 카운트(그 옵션을 고르면 몇 건이 남는지)를 미리 보여줍니다.

🔍 조건에 맞는 거래가 없습니다 필터를 하나씩 풀어 보세요.

칩의 ✕는 그 조건 하나만 풉니다. 상태 드롭다운 옆 숫자는 몇 개가 걸려 있는지, 옵션 옆 회색 숫자는 그 옵션을 고르면 몇 건이 남는지(패싯 카운트)입니다. 0건인 옵션은 흐리게 처리해 "눌러봤자 빈 화면"을 미리 알려줍니다.

왜 이렇게 하나

  • 칩이 없으면 "왜 3건밖에 없지?"가 됩니다. 드롭다운 안에 숨은 체크는 닫으면 안 보입니다. 조건은 반드시 표 위에 펼쳐서 보여야 합니다.
  • 패싯 카운트(facet count) = 각 필터 옵션을 선택했을 때 남을 결과 수를 미리 계산해 옆에 붙이는 것. 사용자가 빈 결과에 부딪히는 횟수를 줄입니다.
  • 디바운스(debounce) = 입력이 멈춘 뒤 일정 시간(여기선 250ms) 지나서야 실제 필터/요청을 실행하는 기법. 글자마다 서버를 때리는 걸 막습니다.
  • 결과 수는 role="status" + aria-live="polite"로 읽어줍니다. 화면을 못 보는 사용자에게 "12건 중 3건"이 전달돼야 필터가 먹혔는지 압니다.
  • 빈 상태는 사과문이 아니라 탈출구여야 합니다. "왜 비었는지 + 초기화 버튼"을 함께 둡니다.

복붙용 — 필터 칩

function FilterChips({ filters, onRemove, onReset }) {
  if (filters.length === 0) return null;
  return (
    <div role="group" aria-label="적용된 필터" className="chips">
      {filters.map((f) => (
        <span key={f.id} className="chip">
          {f.label}
          <button
            type="button"
            className="x"
            aria-label={`${f.label} 필터 제거`}
            onClick={() => onRemove(f.id)}
          >✕</button>
        </span>
      ))}
      <button type="button" className="linkbtn" onClick={onReset}>전체 초기화</button>
    </div>
  );
}
필터 상태는 URL 쿼리스트링에 넣는 걸 권합니다(?status=failed&period=30). 그래야 "이 화면 그대로" 동료에게 링크로 넘길 수 있고, 새로고침·뒤로가기도 자연스럽습니다. Next.js라면 useSearchParams + router.replace 조합. 이 데모는 self-contained라 메모리 상태만 씁니다.

🔔 연결 상태와 저장 인디케이터 오프라인 배너 · 저장 중 · 큐 · 재동기화

자동 저장되는 화면에서 사용자가 가장 불안해하는 순간은 "방금 쓴 게 저장됐나?"입니다. 네트워크가 끊기면 그 불안이 손실로 바뀝니다. 요즘 패턴은 ① 연결이 끊기면 배너로 알리고, ② 저장 상태를 글자로 항상 보여주고, ③ 오프라인 편집은 큐에 쌓았다가 복귀 시 자동으로 밀어 넣는 것입니다.

•변경 없음 ⏳ 이 화면 데이터는 0초 전 기준입니다

대기 중인 저장 큐

    비어 있음 — 저장할 변경 사항이 없습니다.

    토글을 켜서 오프라인으로 만든 뒤 메모를 고쳐 보세요. 저장이 큐에 쌓이고, 토글을 다시 끄면 순서대로 밀려 나갑니다. 실제 online/offline 이벤트에도 반응하므로, 진짜로 와이파이를 꺼도 배너가 뜹니다.

    상태를 몇 개로 쪼갤 것인가

    상태사용자에게 보이는 말왜 필요한가
    idle"변경 없음"아무 일도 안 일어나는 게 정상임을 알려 불안을 줄임
    dirty"저장되지 않은 변경 사항"지금 창을 닫으면 잃는다는 신호
    saving"저장 중…"요청이 실제로 나갔다는 증거
    saved"오후 8:41에 저장됨"시각을 같이 줘야 "언제 것"인지 확인 가능
    queued"오프라인 — 3건 대기 중"실패가 아니라 보류임을 구분
    error"저장 실패 — 재시도"사용자에게 행동권을 넘김

    복붙용 — 연결 상태 훅

    import { useEffect, useState } from "react";

// navigator.onLine 은 "false면 확실히 오프라인, true여도 인터넷이 된다는 보장은 없다".
// 그래서 기능을 막는 데 쓰지 말고 '힌트'로만 쓴다. (MDN 권고)
export function useOnlineHint() {
  const [online, setOnline] = useState(
    () => (typeof navigator === "undefined" ? true : navigator.onLine)
  );

  useEffect(() => {
    const up = () => setOnline(true);
    const down = () => setOnline(false);
    window.addEventListener("online", up);
    window.addEventListener("offline", down);
    return () => {
      window.removeEventListener("online", up);
      window.removeEventListener("offline", down);
    };
  }, []);

  return online;
}

    ♿ 접근성 메모

    • 배너는 role="status" + aria-live="polite" — 스크린리더가 지금 하던 낭독을 끊지 않고 이어서 알립니다. alert(assertive)은 진짜 급한 것에만 씁니다.
    • 저장 인디케이터는 색만으로 구분하지 않고 텍스트를 함께 둡니다. 색각 이상 사용자에겐 초록/빨강 점만으론 구분이 안 됩니다.
    • 깜빡이는 점은 prefers-reduced-motion: reduce(OS의 "움직임 줄이기" 설정)에서 애니메이션을 끕니다.
    • 오프라인이라고 입력창을 disabled 시키지 마세요. 판정이 틀릴 수 있고(위 MDN 주의), 틀렸을 때 사용자는 멀쩡한 상황에서 앱을 못 씁니다. 저장을 미루되 입력은 계속 받습니다.

    🌀 CSS 앵커 포지셔닝 anchor-name · position-area · @position-try

    툴팁·드롭다운을 버튼 옆에 붙이려고 우리는 오랫동안 JS로 좌표를 쟀습니다(getBoundingClientRect, Floating UI 등). 앵커 포지셔닝은 이 계산을 CSS에게 넘깁니다. 기준이 될 요소에 이름표(anchor-name)를 붙이고, 따라다닐 요소가 그 이름을 가리키면(position-anchor) 브라우저가 알아서 붙여 놓습니다.

    지원 여부 확인 중…
    PG 수수료 2.9% + 건당 30원. 정산 시 자동 차감됩니다.

    툴팁은 버튼 위에(position-area: top), 메뉴는 아래에(bottom span-right) 붙습니다. 창을 세로로 좁히거나 스크롤해서 메뉴가 화면 밖으로 밀릴 것 같으면 @position-try 규칙에 따라 스스로 위로 뒤집힙니다. 미지원 브라우저에선 아래 JS 폴백이 좌표를 계산해 같은 자리에 놓습니다.

    핵심 3줄

    /* 1) 기준 요소에 이름표를 붙인다 (dashed-ident: -- 로 시작) */
#trigger { anchor-name: --tx-menu; }

/* 2) 따라다닐 요소가 그 이름을 가리킨다 */
#menu {
  position: absolute;
  position-anchor: --tx-menu;
  position-area: bottom span-right;  /* 기준 아래, 오른쪽으로 뻗기 */
  margin-top: 8px;
}

/* 3) 화면 밖으로 나갈 것 같으면 대안 위치로 갈아탄다 */
#menu { position-try-fallbacks: --flip-up, flip-block; }
@position-try --flip-up {
  position-area: top span-right;
  margin-top: 0; margin-bottom: 8px;
}

    📈 왜 지금 뜨나 / 어디에 쓰나

    • 2026년 기준 주요 브라우저에 대체로 들어왔습니다. 검색 결과상 Chrome/Edge 125+, Firefox 132+, Safari 18.2+에서 핵심 기능이 동작하고, @position-try의 자동 뒤집기는 Safari 18.4+부터라는 설명이 있습니다 — 실제 프로젝트에 넣기 전엔 caniuse/MDN에서 직접 재확인하시길 권합니다(여기 수치는 검색 기반, 미검증).
    • Popover API와 짝입니다. popover 속성이 "띄우고 닫고 포커스 관리"를 맡고, 앵커 포지셔닝이 "어디에 띄울지"를 맡습니다. 둘 다 쓰면 드롭다운에서 JS가 거의 사라집니다.
    • top layer 문제가 풀립니다. 부모에 overflow: hidden이나 transform이 걸려 있어도, popover/top layer 위의 요소를 원래 자리 기준으로 배치할 수 있습니다. 테이블 셀 안의 "⋯" 메뉴가 잘려 나가던 그 문제입니다.
    • 번들이 줄어듭니다. Floating UI 같은 포지셔닝 라이브러리를 안 쓰거나, @supports로 감싸 점진적으로 걷어낼 수 있습니다.
    • 주의: anchor-name 값은 페이지에서 유일해야 예측 가능합니다. 리스트에서 행마다 메뉴를 쓴다면 행 단위로 이름을 만들거나(style="anchor-name: --row-12"), 열려 있는 하나에만 이름을 붙이는 방식이 안전합니다.

    점진적 향상으로 감싸기

    /* 지원하면 CSS가, 아니면 JS 폴백이 위치를 잡게 한다 */
@supports (anchor-name: --x) {
  .js-positioned { position-anchor: --tx-menu; position-area: bottom span-right; }
}

    // JS 쪽
const supported = CSS.supports("anchor-name", "--x");
if (!supported) attachFloatingFallback(trigger, menu); // 기존 방식 유지
    paysable 적용 포인트 — 거래 목록의 행 단위 "⋯" 액션 메뉴, 수수료·정산 주기 툴팁, 금액 입력 옆 한도 안내 말풍선. 특히 overflow:auto인 테이블 래퍼 안에서 메뉴가 잘리는 문제를 popover + 앵커 포지셔닝 조합으로 지울 수 있습니다. 단, 결제 흐름의 핵심 UI라면 @supports 폴백을 반드시 유지하세요.
